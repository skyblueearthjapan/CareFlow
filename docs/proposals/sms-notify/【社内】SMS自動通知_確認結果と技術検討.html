【社内】SMS 自動通知　確認結果と技術検討

2026年10月10日　今泉さん向け（お客様には出さない資料）／ らく助の本番は読むだけで調べ、何も変えていません。外部への送信テストもしていません。
結論：らく助に組み込んで実現できます。ただし今のらく助には患者様の電話番号・メール・同意の欄が無く、送信の仕組みも無いため、そこから作ります。「週の確定」の状態も無いので新しく作り、変更は「確定時の写しと今の予定を見比べる」方式で検知するのが確実です。配信サービスの契約前に、模擬の送信まで含めてほぼ全部を作れます。お客様向けの相談書は、この前提で書き直しました（訪問予定の自動お知らせ_導入のご相談_A4.pdf・2 ページ）。

2. 無料・低価格の方法も含めた比較（お客様の負担を下げる案）

方法費用良い点弱い点・条件
国内 SMS 配信（KDDI・Cuenote・ネクスウェイ）6〜10 円／通番号だけで届く。到達率が高い（国内キャリア直結）。配信結果 API あり70 字超は 2 通分。共通番号は返信不可・誰からか分かりにくい
LINE 公式アカウント（Messaging API）月 200 通まで無料／月 5,000 円で 5,000 通無料枠が大きい。既読が分かる。返信も受けられる患者様（ご家族）の友だち追加が必要。らく助の患者と LINE の利用者を結び付ける登録の手間（初回に QR から登録）
メール（Amazon SES 等）ほぼ無料（SES は 1,000 通 約 0.1 ドル）文字数の制限なし。ご家族向け迷惑メール判定。送信ドメインの設定（SPF/DKIM）が要る。※ SendGrid の無料プランは 2025 年に終了
紙の予定表（訪問時に手渡し）無料携帯の無い高齢者にも届く。らく助の印刷機能を流用できる変更の連絡には使えない（変更は電話）
患者様ごとの予定ページ（URL を 1 回お渡し）無料いつでも最新の予定を見られる。変更も自動で反映見に行く必要がある（通知ではない）。URL の管理（推測されない鍵付き URL・期限）
海外系 SMS（Twilio・Amazon SNS）約 11〜18 円／通API が使いやすい国内サービスより割高。Amazon は既定で月 1 ドルの上限があり申請が要る
自前のスマホから送る携帯の SMS 料金契約が簡単おすすめしない：大量送信でキャリアの制限・規約に触れる恐れ、記録・再送が作れない
自動音声電話（IVR）月数千円〜＋通話料固定電話の方にも届く費用・作り込みが重い。今回は将来の選択肢

おすすめ：送り先ごとに方法を選べる作りにし、LINE・メールを希望される方は無料で、それ以外は SMS。携帯の無い方は紙。LINE とメールは配信サービスの契約を待たずに始められる。

3. らく助に組み込む場合の推奨構成

3-1. 足りないもの（新しく作る）と、使えるもの

必要なもの今のらく助方針
患者様の連絡先・同意無い（patients は住所・備考のみ）別テーブル patient_contacts（種別 SMS/LINE/メール、ご本人／ご家族、番号は国際形式に正規化、携帯 070/080/090 判定、受け取る種類＝週の予定／変更）と patient_contact_consents（いつ・誰が・方法・取り消し）。患者フォームと Excel 取込に欄を追加
週の確定無い（course_status・青ピン・カイポケの●未送信は別の意味）week_confirmations（拠点×週・確定者・日時）。手本は職員の休み申請の月確定（staff_shift_confirmations）
お知らせした内容の写し無い（取込前の写し inbound_snapshots は 5 世代で消える）patient_week_notices（患者×週で 1 行、送った予定の一覧を JSON で保存、版数）。比べるキーは 患者＋日＋開始時刻（訪問の ID は週の生成・取込で作り直されるので使わない）。2 名体制は 1 件にまとめる
変更の検知訪問を書き換える経路が 30 以上あり、1 か所で拾えない（操作履歴 schedule_op_log は一部の操作だけ）5〜10 分おきの見比べ（cron）。確定済みで今日以降の週について、今の予定と写しを患者ごとに比べ、追加・中止・日時の変更だけを拾う。担当の交代・コース・打刻は対象外。落ち着くまで 10 分待ってから送る（ドラッグで削除→配置の途中を送らない）
送信の順番待ち・再送キューは無い（FastAPI の BackgroundTasks と VPS の cron のみ）notification_outbox（宛先・本文・状態・試行回数・次の試行時刻・二重送信防止のキー・配信サービスの ID）。cron から 1 分〜5 分おきに送信 API を呼ぶ。手本はカイポケ連携のジョブ＋明細＋5 分おきの確定と advisory lock
配信サービスとのつなぎ無い送信の窓口を 1 つの型にする（送る／結果を取る）。実装は「模擬（送らずに記録）」「KDDI」「Cuenote」「ネクスウェイ」「LINE」「メール」を差し替え。手本は音声機能の voice_ai_provider（既定は none）
接続の鍵の保管カイポケのログイン情報を Fernet で暗号化して DB に保存する仕組みあり同じ形で messaging_credentials（拠点ごと可）。画面には鍵を出さない。監査ログの伏せ字に新しい項目名を足す
送信の記録・失敗の一覧アプリ内のお知らせ（職員向け）はあるが、患者宛て・送信状態の列は無い送信ログ（宛先は伏せ字）＋届かなかった一覧の画面。失敗は管理者へアプリ内で知らせる
届いたかの結果受け口（Webhook）は無い。carelink の API は外から届く（Cloudflare Access なし）まずは結果を取りに行く（ポーリング）方式で十分。Webhook を使うなら署名の確かめを必須に
送り主の名前・電話business_profile（事業所名・電話）は 1 件だけ当面はこれを使う。拠点ごとに分けるなら offices に列を足す

3-2. 処理の流れ

  1. 確定：管理者が「週の予定を確定」→ 患者ごとの予定を写し、文面を作り、送信前の確認画面（送らない方を外せる）→ 送信予約（outbox）。ここまで 1 回の処理でまとめて記録。
  2. 送信：cron が outbox を少しずつ送る（配信サービスの上限に合わせて速さを調整）。送った ID を保存。失敗は時間をおいて再送、上限回数で「失敗」にして一覧へ。
  3. 変更：cron の見比べで差分が出た患者だけ「変更前→変更後」を outbox へ。写しを新しい内容に更新（版数＋1）。同じ変更を二度送らないキー＝患者＋週＋版数。
  4. 取り消し：確定を取り消す・ご同意の取り消し・稼働中でなくなった方は、以後送らない。

4. 配信サービスの契約前に作れるもの

  • 連絡先・同意の欄（患者フォーム・Excel 取込）／週の確定と写し／変更の見比べ／文面づくり（70 字の目安を画面に表示）／送信前の確認画面／送信の記録と失敗の一覧
  • 模擬の送信（実際には送らず、送ったことにして記録する）で、確定→通知→変更→再通知まで一通り動かせる。テストは架空の患者と職員の携帯だけで行う
  • LINE とメールは無料枠で、契約を待たずに本物の送信まで作れる（事業所様の LINE 公式アカウントの開設は必要）
  • 契約後にやること：接続の鍵の登録 → 職員の携帯で試験 → 一部の患者様から開始

5. 想定される課題

課題対策
連絡先・同意の入力の手間（約 90 名）Excel でまとめて取り込める欄を用意。カイポケの利用者情報に電話があれば取込も検討（要確認）
確定後に予定がよく動く（ならし直し・カイポケ側の手直し）と変更通知が増える確定は「最終版」になってから押す運用。変更は落ち着いてからまとめて 1 通。カイポケ側だけで直した変更はらく助に入らないと通知されない（取込の運用とセット）
70 字を超えると料金が倍文面を短く。週 3 回以上の方は日付を詰めて表記、または「詳しくは予定ページ」の URL
送信元が誰か分からない・返信できない本文冒頭に【事業所名】、本文に問い合わせ電話。必要なら専用番号（月額）
誤送信（番号の入れ間違い・家族の番号変更）番号の書式チェック、最初の 1 回は「登録のお知らせ」を送って確かめる、本文に氏名・病名を入れない
サーバーの時計が UTC送信時刻・「今日」は必ず日本時間で計算（共通の関数を作る）
テスト環境が SQLite見比べ・送信の順番待ちは SQLite でも動く書き方にし、ロック部分は本番相当の環境で確認
既存の機能を壊さない新しいテーブルと新しい画面を足すだけ。既存の予定の書き換え経路には手を入れない（見比べ方式なので不要）。機能は拠点ごとのフラグで入／切

6. 作業量の目安

連絡先・同意（2〜3 日）／確定と写し・見比べ（3〜4 日）／送信の順番待ち・模擬送信・記録画面（3〜4 日）／LINE・メール（各 1〜2 日）／SMS 配信サービス 1 社の接続（1〜2 日、契約後）／レビュー・試験（2〜3 日）。合計 およそ 2.5〜3.5 週間（目安）。
