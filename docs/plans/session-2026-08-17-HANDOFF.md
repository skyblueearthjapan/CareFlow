## 1. QR打刻の開放（正典 = `docs/plans/qr-open-checkin-design.md`・実装済みステータス）

- **第1弾 `/q/{token}`**（`bdfc389` でデプロイ）: 標準カメラ/Chrome で QR を読むと 404 だった問題の根治。
  resolve-qr API + ランディングページ + `?qr=` スキャン省略。未ログインは callbackUrl でログイン後復帰。
- **第2弾 開放**（`325194c`・mig 0071 `visits.is_unplanned`）:
  - 担当外 = QR 必須（手動不可）。resolve v2 が患者氏名+当日全 visit（予定担当名・is_mine付き）を返し、
    本人が「代行 / 予定外」を選択。代行は `X-QR-Token` ヘッダの capability 分岐（GET/POST）で通す。
    担当外への GET は絞り込み projection（note/kaipoke_id/assignments/同行名を遮断）。
  - 予定外 = `POST /visits/adhoc-checkin`（advisory lock で二重生成防止・device_time 基準の時刻・当日外422）。
  - 通知3種 `checkin_substitute / checkin_unplanned / checkin_ng_staff`（冪等）。
  - モニター: 代行バッジ+代行者名（`substitute_staff_*` = 担当集合外の最新打刻者・actual とは別持ち）、
    📌予定外訪問の拠点別専用行、トレイ理由チップ。substitute 判定は arrival+departure 両方見る。
  - オフライン: `adhoc_arrival` キュー（ルート不在404/405 は保持・トークン起因404のみ破棄）。
- **入口ボタン**（`08879fa`）: 「今日の訪問」に「QRを読み取る」常設ボタン → `/q/{token}` へ委譲。
- **実機確認の残 3 点**: ①予定外打刻がある週のカイポケ取込挙動（打刻あり日=差分モード化・全週置換/戻すが422）
  ②代行到着で未訪問通知が自動解決 ③ベル通知新種別3つの表示 + 認証済み端末での X-QR-Token 疎通。
- PO 未決（仮値稼働中）: 予定外の既定60分 / カイポケ実績との突合運用 / 通知文言（設計書§9）。

## 6. ハマり所・教訓（今セッション発生分）

1. **並行 worktree エージェントで `git stash` 禁止** — stash スタックはリポジトリ共有で、他エージェントに
   pop され作業が交差する実事故が発生（双方 dangling commit から復旧・損失ゼロ）。退避は WIP コミットで。
   以後の全ブリーフに禁止事項として明記すること。
2. **worktree の分岐元が古いことがある** — エージェント起動時に「設計書が存在するか」を確認させ、
   無ければ `git reset --hard develop` させる手順をブリーフ冒頭に必ず入れる（本セッションで 3 回発生）。
3. **時刻依存テストは深夜に落ちる** — adhoc の 23:59 クランプ・JST 日跨ぎで 2 件が深夜実行時のみ失敗。
   期待値側にも同じクランプ規則を適用する（`_expected_adhoc_end` の型）。
4. **並行実装は凍結コントラクト+マーカー防御** — FE は `patient_name` の有無で新旧 BE を判別する等、
   どちらが先にデプロイされても安全側に倒れる設計にする（QR で実証済み。同行は FE 先行不可だった —
   最終レビューでデプロイ順の両方向を必ず検証させること）。
5. **レビュー指摘の「設計書と実装の食い違い」は設計書側の誤りのことがある** — course-guard ゲートと
   CSV 順序は私の設計書の一文が原因。ディレクター判断で設計書を改訂し撤回理由を残した。
6. **お客様の「訂正済」申告も検証する** — 青栁様の入院中は訂正済列にあったが DB 未反映だった（10件中1件）。
7. **本番データ修正は dry-run(ROLLBACK)→件数検証→COMMIT の二段** — 全40文の行数を先に確認してから書く。
