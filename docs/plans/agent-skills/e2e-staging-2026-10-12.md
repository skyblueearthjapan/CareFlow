## 2. 見つけた不具合

### 2-1. マスター系の op が職員コードを受け付けるように見えて 422（修正済み）
- 場所: `agent/rk/ops/masters.py` の `_need`（`ng-staff-update`・`staff-hours-update`・`staff-master-update`・患者系の `patient_id`）。
- 症状: 訪問系・休み系の op は `staff_id` に職員コード（`S004`）を書けるが、マスター系は UUID しか API が受けない。`rk plan check` は通るのに `rk apply` で 422（`uuid_parsing`）。
- 修正: `_need` で `*_id` が UUID の形でなければ plan check で断る（「職員コードなら rk sql staff_lookup で UUID を調べる」と表示）。テスト 189 件は通る。
- 残り（提案）: コードも受けたいなら `resolve_staff` を masters に入れる（snapshot/inverse も解決後の UUID を使うように）。

### 2-2. ならし案の `undo_note` が「プールへの戻しは API で戻せる見込み」と書いていた（修正済み）
- 場所: `agent/tools/leveling/plan.py:430` 付近（案の `undo_note`）。
- 実際は `return-to-pool` は `undoable=False`（`rk undo` は `--partial` が要る）。了承のときに誤った説明になるおそれ。
- 修正: プールへ戻す件数があるときは「API で戻せない（--partial で残りだけ戻す）」と書く。

### 2-3. 入らない訪問が 1 件でもあると、急な休みの案は必ず反映できない（設計の食い違い・未修正）
- 場所: `agent/tools/leveling/plan.py:399`（`errors` があれば `blockers`）・`docs/tools/week-leveling/report.py:192`（入らない訪問を「問題」に数える）。
- `rakusuke-week-optimize` の合格条件 2 は「入らない訪問が 0、**または全部に理由と相談先がある**」だが、道具は理由があっても `ready:false`。10/22（S004 休み）は上限超え 3 名まで許しても 2 件残り、正規の手順では反映できない。
- 提案（PO 判断）: 入らない訪問を「プールへ戻す（戻せない操作）」として了承で通す選択（例 `rk level --accept-unplaced`）を作り、`warnings` に理由と相談先を残す。または スキルの文言を「0 件のときだけ」に合わせる。

### 2-4. Git Bash から `python -m rk get /patients/…` が壊れる（包みは修正済み・cli.py は未修正）
- 症状: Git Bash が `/patients/…` を `C:/Program Files/Git/patients/…` に書き換え、`http.client.InvalidURL` の長いトレースバックで落ちる。スキルの読み方の例（`rk get /patients/<id>` など）がそのまま失敗する。
- 修正: `agent/bin/rk` に `export MSYS2_ARG_CONV_EXCL="*"`（引数の書き換えだけ止める。PYTHONPATH の書き換えは残す。`MSYS_NO_PATHCONV=1` にすると PYTHONPATH が壊れて `No module named rk`）。
- 提案（`agent/rk/cli.py`・今回は触れない約束）: path が `^[A-Za-z]:/` で始まり `/Git/` を含むときは「Git Bash の書き換えです。MSYS2_ARG_CONV_EXCL='*' を付けるか agent/bin/rk を使ってください」と日本語で止める。README の「動かし方」にも 1 行。

### 2-5. テストが `RK_ENV=staging` の下で 2 件落ちる（修正済み）
- 場所: `agent/tests/test_rk_config_auth.py:26` のフィクスチャが `RK_ENV` を消していなかった。`RK_ENV` を消す対象に足した（`RK_ENV=staging` でも 189 件通る）。

### 2-6. 小さな表示の問題（未修正・提案）
- `rk apply` の最後が、戻せる操作が 0 件（copy-week だけ）でも「元に戻すには: rk undo …」と出す（`agent/rk/applyrun.py`・今回は触れない約束）。0 件なら「API では戻せません（バックアップから）」だけにする。
- 案の `checks` の 1 行（`check_line`）が問題の詳しい内容の先頭 1 件だけを出す（「入らない訪問 1 件」と出るが実際は 2 件）。件数の合計を出すとよい（`agent/tools/leveling/plan.py` の `check_line`）。
- 試験環境の職員に同じ職員コード `S008` が 2 人いる（片方は性別なし）。コードで指定する op（`resolve_staff`）が迷う可能性。データの点検を PO に。
- PC→VPS の ssh が数回タイムアウト（`connect … timed out`・ポート転送 20 秒）。書き込みの前に止まるので害はないが、再実行の案内があるとよい。
