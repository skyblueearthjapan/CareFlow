# 案の出し方（PO 標準 2026-10-12）

管理者に見せる案は「見て分かる」「必ず確かめる」。正典は `agent/AGENTS.md` §5-2（内側を見せない約束は §2-4）。

## 案（plan.json）の追加項目（すべて任意・後方互換）
| 項目 | 形 | 無いとき |
|---|---|---|
| `headline` | 文字列のリスト（3 件まで） | `summary` の先頭 3 行で代用・`rk plan check` が注意 |
| `ops[i].reason` | 文字列（平易な理由） | 帳票に「理由は書かれていません」・注意 |
| `issues[]` | `{severity: info\|warn, text, options[]}` | 未決定の `unplaced` から「時刻をずらす／応援／保留」で補う |
| `conditions[]` | 文字列、または `{text, approved}` | 「いつもの決まりのまま」 |
| `compare_to` / `diff[]` | 前の案の id / 違いの文 | 無ければ節を出さない |
| `timelines[].rows[].before_blocks` | blocks と同形 | 変更後だけ（`blocks[].from` を「←元の担当」で表示） |

形が違うと `rk plan check` の誤り、内容が足りないのは注意（誤りではない）。

## 帳票 v2（`rk plan report`・`--v1` で旧形式）
`agent/rk/report_v2.py`。①結論 ②気になる点（選択肢つき）③変わるところと理由 ④今回だけの条件 ⑤案 N との違い ⑥確かめの問い（①反映する ②直してほしい ③やめる）。A3 は日ごとの時間割（変更=青の太枠＋◆、変わらない=薄く）。スクリプトなし・外部ファイルなし。戻せない操作は「画面からは元に戻せません」とだけ出す（バックアップ・run-id は出さない）。反映後は `render_applied` の短い報告。

## 評価（eval）に足す採点
1. headline が 1〜3 行ある 2. 変更した操作すべてに reason がある 3. 入らない訪問・予定外・緩めた決まりが issues に出ていて options が 2 つ以上
4. conditions が（緩めたときは）書かれ承認者つき 5. 作り直しで compare_to と diff がある
6. 反映前に 3 択（反映する／直してほしい／やめる）を聞いている（了承なしで apply しない）
7. チャットに表・全件一覧が無く、案のペインを指している 8. 管理者向けの文に禁止語（バックアップ・pg_dump・run-id・rk・スナップショット・保存期間）が無い
9. 反映後に短い「反映しました」報告（件数・照合・元に戻せるか）がある
