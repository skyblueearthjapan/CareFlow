作成: 2026-10-12 ／ 調査は読むだけ（本番・git は触っていない）

## 0. 全体像（今の実際の週の回し方）[事実・10/9 時点]

```
月次: カイポケ月初展開 ─ 休みの月確定 ─ 予実比較（月末）
週次: 週を作る（前の週をコピー or 固定訪問から生成）
        → 一斉スタッフ未割当 → ならし案（道具・本番は読むだけ）→ PO 了承・pg_dump
        → API で反映（今週だけ移動／プールへ／特別訪問の配置／コースに担当）
        → 新人の同行登録 → 照合 → カイポケ差分 → 送信（日中）→ export で突き合わせ
日次: 急休・キャンセル・時刻の調整 → 打刻・モニターの確認 → 実績時刻を合わせる
         → お客様がカイポケで直した分の取り込み（打刻のある日は差分・ない日は置換）
随時: 新患・終了・入院/休止・固定訪問の枠・希望・NG・特別訪問週間・職員・設定
```

画面の「週を生成 → 自動スタッフ割当 → レビュー」（古いマニュアル）は、**今は使わない**。理由: 自動割当は勤務時刻・予定（前後 15 分）・半休を見ず、ならし案を崩す（runbook §2-4）。PO 方針は「コースの数は出勤人数に合わせる・M は必要な曜日だけ・臨時コースはなくす」（アプリ本体は未改修）。

## 1. 作業の一覧（頻度ごと）

各作業の書式: **誰が／きっかけ／画面の手順／触るデータ／決まり・制約／つまずき（罠）／エージェントのやり方（読む→提案→反映→確かめる）**

### 1-A. 月次

#### A-1. カイポケ月初展開（月間スケジュールの展開）
- 誰が: 管理者（川名様）。月 1 回。
- きっかけ: 月が替わる前。カイポケに翌月の予定の器を作る。
- 画面: サイドバー「連携」→ 週を選び「01 展開する」（月 1 回）。
- データ: カイポケ側の月間予定（週間パターンから展開）。らく助は `kaipoke_jobs` に記録。
- 決まり: 展開は**対象月を間違えると過去月を上書き**する。
- 罠 [事実]: 2026-08-31 事故 — 「展開の対象月＝選んだ週の月曜の月」なので 8/31〜9/6 の週を選ぶと 8 月が対象になり、8 月の 70 名分が上書きされた（`incident-2026-08-31-kaipoke-expand-wrong-month.md`）。再発防止 A〜H は未実装。展開直後に別ジョブを流すと展開ジョブが running のまま残る。
- エージェント: 対象月を**明示**して PO に選択肢で確認 → 展開前にカイポケ export を保存（読み取り）→ 実行は人のボタンと同じ連携 API → 展開後 export の件数で確かめる。**自動実行はしない（取り返しがつかない）**。

#### A-2. 休みの月確定
- 誰が: 管理者。職員はスマホ `/m/leave` で 1 日 1 件の休み申請。
- きっかけ: 月ごとの勤務表を締める時。
- 画面: `/admin/pending-requests`（申請履歴）で承認 → 右側「休み・月確定」パネルでスタッフ選択 → 月カレンダーで日をクリックして休みを増減 → 「この月を確定して通知」。
- データ: `pending_requests(staff_off)` → 承認で `staff_weekly_overrides`（override_type='off'）、`staff_shift_confirmations`。
- 決まり: 休み＝エンジンのハード制約（その日は出勤しない）。半休（am_off/pm_off）は**エンジン 3 か所が 'off' しか見ない**ギャップあり。ならしの道具は午前休＝12:00 から、午後休＝12:00 までとして扱う。
- 罠: 承認経路は当該週の固定イベント（朝会）に取消印を付けない（「休みにする」は付ける）。applier は upsert しない（重複 409）。
- エージェント: 未承認の申請を一覧 → 「承認すると何件の訪問が担当なしになるか」を週ごとに試算して提示 → 承認 API → 影響する週のならし（B-3）を提案。

#### A-3. 予実比較・実績の点検（月末〜翌月初）
- 誰が: 松岡様（請求の確認）・PO。
- 画面: 連携コンソール「予実比較レポート（月）」→ ジョブ一覧の 📄。打刻履歴 `/records`。
- データ: カイポケ実績 CSV（`division=actual`）・`kaipoke_csv_snapshots`・打刻。
- 決まり: 実績の時刻は**看護記録（カイポケ実績）に合わせる**。一律 35 分にしない。読み取りが 1 件も無い訪問は「打刻なし（予定のみ）」で実績とみなさない。
- 罠: 「職種未設定」「同日複数」「資格不整合」タグ＝カイポケ側の二重登録や請求区分ずれの手がかり。
- エージェント: 月を指定して予実比較を起動（202・非同期）→ 結果を要約（一致／時刻ズレ／担当違い／予定のみ／実績のみ）→ 要対応だけを人へ。書き込みはしない。

#### A-4. 月またぎ週の扱い
- 送信も取込も月ごとに分かれる（2 か月混在は 422）。diff-local は月またぎなら両月分。月またぎ週の smart preview は 100 秒制限に当たることがある（admin_call 経由なら回避）。

### 1-B. 週次（毎週の中心作業）

#### B-1. 週を作る（前の週をコピー／固定訪問から生成）
- 誰が: PO または管理者（admin のみ）。
- きっかけ: 次の週の準備（今は 1〜3 週先まで作っている。週45 以降は未作成 [事実・10/10]）。
- 画面: スケジュール画面ツールバー「週を作る」→ ダイアログで選ぶ:
  - **前の週をコピー**（今の主な方法）: 写す元（過去 8 週）→ 確認（固定訪問に無い訪問を外せる・「固定訪問から補う」初期オフ・「続けて自動スタッフ割当」初期オン）→ 確定。表示中の週が写し先。
  - **固定訪問から生成**（`POST /schedule/generate-week-only`）。
- データ: `visits`（コピーは `source='manual_week'`、生成は `auto`）、`courses`、`snapshot_week`（コピーのみ）。担当は写さない。同行の既定・固定イベント（朝会）は週の生成で展開。
- 決まり:
  - コピーは時刻をそのまま写す → **マスターで変えた時刻は入らない**。生成はマスター（固定訪問の枠、無ければ希望）から作る。
  - 生成は `source='auto'/'reset_v2'`・planned・青ピンなしを消して作り直す。`manual_week`・取込・取消・打刻・青ピンは残す。同じ（患者・日・開始）なら飛ばす。
  - コースの無い固定枠は拠点の既定コース（稲A）へ寄る → 重なりが大量に出る（週42 で 35〜44 件）。
- 罠 [事実]:
  - **生成はスナップショットを取らない＝画面から戻せない**。押す前に pg_dump 必須（10/4 は取り忘れた）。コピーは「コピー前に戻す」あり（打刻のある週は不可）。
  - コピーで M コースが重複して 500（10/9 `8ee6558` で修正済み）。上書きモード（予定のある週へ写す）で proposed と確定済みコースが並ぶ経路は残る。
  - 「今週全件解除」（青ピン一括解除）→「週を生成」で、コピー・ならしの週（`manual_week`）が `auto` に書き換わって消える（10-12 HANDOFF B-2）。**直るまで押さない**。
  - 週の生成直後は訪問の主担当が空。コースの担当は残る。
  - 古い `reset_v2` が残っていると時刻違いの二重ができる（10/4 に方針変更で reset_v2 も作り直すようになった）。
- エージェント: 読む＝前の週の訪問・マスター（固定訪問／希望）・非稼働の患者・青ピン → 提案＝「コピー／生成どちらか」と件数の予告（入る・入らない・二重候補）→ PO の了承と pg_dump → 反映＝画面と同じ copy-week API（`/schedule/v2/copy-week/preview` → `/copy-week`）→ 確かめる＝同じ患者が同じ日に 2 件ないか（2 名体制・1 日 2 回は正常）、プール件数。

#### B-2. 一斉スタッフ未割当（ならしの前処理）
- 誰が: PO（画面の「一斉スタッフ未割当」）。
- 目的: ならし案は職員ごとに組み直すので、担当を全部空にしてから反映する（generic apply の前提）。
- 罠: `manual_staff_override` の訪問にはコースの担当（PATCH /courses）が伝わらない → `visit-assign-staff-week staff_id=null` で解く。

#### B-3. ならし（今週の最適解を作る）★中心
- 誰が: 今は Claude（道具）＋ PO の判断。人の画面作業なら半日規模。
- きっかけ: 週を作った後の重なり／職員の休み・不足／特別訪問週間の上乗せ／入らない訪問。
- 手順 [事実]: `level.py --week <月曜> --off S008 --add-special --seconds 90`（本番は読むだけ・1 本ずつ）→ `summary.json` の合格条件（`rule_errors=0`・`unplaced=0` か理由あり・`new_overlaps/new_late=0`・アプリの物差しと一致・あと 1 手の見落とし 0）→ Excel と A4（利用者名入り・`docs/reports/`）→ PO に「適用する／しない／条件を変えて計算し直す」を選択肢で聞く。
- データ（読む）: その週の `visits`（固定の時刻・長さ）、`patients.weekly_pattern`（時間の種類と希望の範囲）、`sex_restriction`、`patient_ng_staff`、座標・主担当拠点、`staff_shifts`・`staff_weekly_overrides`・`staff_events`（UTC のまま読む）、直前 4 週の担当歴、特別訪問週間の未配置の○。
- **決まり（ならしで守るもの）**: `week-leveling-rules-2026-10-02.md` と PO 決定
  | 項目 | 決まり |
  |---|---|
  | 上限 | 1 人 1 日 6 名（`scheduling_settings` 既定。コースの capacity は患者数の上限ではない） |
  | 曜日 | 動かさない |
  | 時刻 | 固定の時刻が第 1。だめなら希望の時間帯の中（幅の上限なし）。固定と希望が 30 分超離れていれば固定のまま（join_fixed）。完全固定（locked）でも希望の範囲内なら動かしてよい（D-1） |
  | 時間の種類 | 固定＝ちょうど／時間帯＝希望の開始〜終了の中で開始／午前＝12:00 前に開始／午後＝13:00 以降に開始／終日＝どこでも（下限は勤務開始） |
  | 勤務時刻 | 守る。マネージャー（川名＝稲毛・熊澤＝稲毛/都賀）はあふれの受け皿で、必要なら超えてよい（理由を添える） |
  | 予定（朝会など） | 取消以外は前後 15 分込みで塞ぐ。予定の時間は昼休みに数えない |
  | 昼休み | 11:30〜13:30 の中で約 45 分をなるべく。入らない日だけ 30 分（30 分は必須） |
  | NG | 絶対に当てない |
  | 女性限定 | 男性職員を絶対に当てない |
  | 同じ建物 | 約 100m 以内の 2 名は 1 人で 90 分の枠。移動 0 |
  | 移動 | 直線 ÷ 20km/h（最低 1 分）＋別住所へ 8 分。1 件目への移動は数えない |
  | 拠点 | 職員の拠点＝コースの拠点。またぎは重いコスト。宇田川さんの都賀 A 固定は月〜金だけ |
  | ローテーション | 直前と同じ職員 200・2 回前 100・3 回前 50（移動 1 分＝1） |
  | 新人 | コースを持たない（同行のみ）。道具は `is_trainee` を見ないので `--off` で外す |
  | 職員の構成 | 稲毛＝本名・高岡・髙梨（小西さんは新人＝同行のみ）／都賀＝宇田川／マネージャー＝川名・熊澤。都賀は月〜金営業（土曜は宇田川さん） |
- 罠: 道具は固定訪問の枠を直接読まない（週の visits を読む）→ マスターを変えたら先に週との食い違いを確かめる。道具は赤ピンを見ない。並列で回すと結果が揺れる。試算の「もしも」（M の延長など）は `week.json` を手元で書き換えて `--from-dir`。
- エージェント: これがスキル `week-leveling` そのもの。エージェントは「条件を言葉で受けて → オプション・week.json の書き換えに直す → 合格条件を自分で検査 → 入らない訪問の理由と相談先（時刻の相談か応援）を平易に説明」まで行う。

#### B-4. ならし案の反映（本番への書き込み）
- 誰が: Claude（PO 了承）または人が画面で。
- 手順 [事実・generic README]: `build_ops.py` で操作一覧（入らない訪問＝`DELETE /visits` で保留プールへ → `POST /schedule/v2/visit-move-week-only` → `/special-visit-marks/{id}/place` → `PATCH /courses/{id}`（月〜土・担当）→ ○の付け間違いの取消）→ 手元で流す順に追って検査 → 別担当レビュー → 戻し用 SQL を作り ROLLBACK で空打ち（psql `-q`）→ 反映前の確認（案の時点から週が変わっていないか・手の上書き 0）→ pg_dump → 管理者の鍵をサーバー内で発行 → `apply.py`（最初の想定外で止まる・`--from N`）→ `verify.sql | check.py`（一致件数・新人の担当 0・担当なし 0・手の上書き 0）。
- 決まり: 「今週だけ取消」ではプールに出ない（取消も件数に数える）→ プールへは `DELETE /visits`。`place` は拠点一致必須（違えば同じ拠点の M に置いて移す）。臨時・M2 テンプレートへは移さない（M と誤認）。PATCH /courses は新人だと 422、NG/女性限定は 422。
- 罠: 10/4 は PATCH /courses が取消の訪問にも担当を書いた（10/5 修正で planned だけ）。ASGI 直叩きは裏の処理が止まるので本番の窓口 127.0.0.1:18001 へ。
- エージェント: 上の流れを 1 つの「反映」手順にまとめ、各段で PO の了承点（pg_dump の前、apply の前）を設ける。

#### B-5. 新人の同行を付ける
- 誰が: 管理者（画面「👥新人同行」）／Claude（`PUT /accompaniments`）。
- データ: `accompaniments`（kind=trainee/support・スタッフ×週の全置換・course_ids）・`accompaniment_defaults`（毎週の既定。週の生成で展開）。visits の担当欄には書かない。
- 決まり: 新人は先輩のコースに付く（新人がコースを持つと 422）。本人の担当と時間が重なると 422。NG・性別は確認フロー。カイポケには職員名 2 として正規に出る。
- 例 [事実]: 週43・44 は小西さんをくじで 5 コースずつ（夕方が混む人に付けると学びと負担軽減の両立）。
- エージェント: 新人の出勤日と先輩のコースの一覧から割り振りを提案（偏らないように）→ 了承 → PUT → 表を A4 で。

#### B-6. カイポケへ送る（らく助 → カイポケ）
- 誰が: 管理者（画面）／Claude（API）。**日中**に。
- 画面: 職員スケジュールタブの同期帯「⇧カイポケへ送る」、または「連携」→ 週を選び「02 この週の差分を計算 → 03 内容確認 → 04 この週で本番反映」。
- API [事実]: `POST /api/v1/integrations/diff-local {month, weekStart, weekEnd}`（カイポケから export・1〜2 分）→ `correction_sheet_items` で中身確認 → `POST /integrations/apply {sheetId, dryRun:false}` → ロボット側 `GET :5000/api/apply/result` で進み具合 → reconcile cron がジョブを完了に → `POST :5000/api/export {month, division:"plan", async:true}` で出し直して突き合わせ。
- 決まり: 明日以降の予定だけ送る。1 件 30〜60 秒（172 件で約 1 時間 50 分）。担当なしは送らない（ガードあり）。正看/准看の請求区分は資格で決まる（正看優先、grade_change で 1 件の edit）。
- 罠: **お客様がカイポケで直接直す運用がある → 送る前に必ず差分を見る**（送ると手直しを上書きして戻す）。17〜18 時台は失敗しやすい。カイポケの export は担当なし（-）行を出さない（隠れ行→add の二重）。氏名の漢字違い（真理奈/真里奈、齋藤/齊藤）は「利用者が見つかりません」。成否は export で確定する。
- エージェント: 差分を取る → **カイポケ側の手直しと思われる行（edit で らく助が古い）を分けて表示** → 送る範囲を PO が選ぶ → 送信 → 進捗を日本語で随時報告 → export で一致件数を報告。

#### B-7. 突き合わせ（らく助 ⇔ カイポケ）
- 画面: 同期帯「🔄同期確認」（約 2〜3 分・差分の件数とズレ）・「●未送信」（RPA なしで保存済み CSV と比べる）。
- エージェント: 定期的に読み取りで突き合わせ、ずれの件数と種類（担当・時刻・追加・削除・資格のズレ）を要約。どちらを正にするかは PO に聞く。

#### B-8. 実現性チェック・スケジュール診断（週の点検）
- 画面: 週セレクタ横「実現性チェック」（A4・移動/重なり/バッファ/同住所）、「スケジュール診断」（1.5 倍の基準）。

### 1-C. 日次・当日

#### C-1. 職員の急な休み（急休）
- 誰が: 管理者。
- 画面: 職員スケジュールタブ（今週の運転席）→ 急休パネル（代替候補 ◎△× と理由・`POST /schedule/v2/substitute-candidates`）→ 付け替え（コース丸ごと＝`PATCH /courses/{id}`、1 件＝`POST /schedule/v2/visit-assign-staff-week`）→「休みにする」（`POST /staff/{id}/overrides`。その日の固定イベントに取消印）。

- 罠: 取込の add は取込由来の取消だけ復活させる。取消行に担当が付いていると職員スケジュールに横線が散らばる。

#### C-3. 時刻・日・担当の今週だけ変更

- エージェント: 「今回だけ／今後ずっと」を必ず聞く（スケジュール運用マニュアルの原則）→ 今回だけは visit-move-week-only、今後ずっとは固定訪問の枠（D-4）へ。

#### C-4. 打刻の確認・訪問モニター
- 画面: 訪問モニター（行＝職員）・打刻履歴 `/records`・通知（未訪問・予定外・担当外）。

#### C-5. カイポケ側の手直しの取り込み（カイポケ → らく助）
- 誰が: 管理者（画面）。今の最優先課題（週42 の約 45 件）[事実]。

- 決まり: smart-inbound＝**打刻のある日は差分、無い日は置換**（その日を全部消して作り直す・青ピンも守らない）。打刻済み訪問は取消も日の移動もしない（要確認で知らせる）。新人の職員名 2 は同行リンクとして扱う。
- 罠: 打刻のある週は「取り込み前に戻す」が 422。予定外打刻の週は全週置換が 422。置換は名寄せできない行をらく助から消す。イベント取込は別（訪問＋イベント／イベントのみ）。
- エージェント: 取込のプレビューを読み、人の言葉で「カイポケで何が変わったか」を要約 → どちらを正にするか PO に聞く → pg_dump → 取込 → 一致件数を報告。

## 2. PO の作業の約束（エージェントが守ること）

1. **返答・説明・質問・選択肢はすべて日本語**（進捗の 1 行報告も。英語で 2 回指摘あり）。
2. **確認は選択肢つき**（AskUserQuestion・1 問ずつ・2〜4 択）。自由記述は値が必要なときだけ。
3. **言葉**: 画面・帳票・説明で「合わせる・調整」を使い、「直す・修正・補正」は使わない。アプリ名は「らく助」（「楽スケ」と書かない）。理由の文言も責めない言い方（「読み取りなし」「読み取りが後になった」）。
4. **本番に書く前に PO の了承と pg_dump**（`gunzip -t` で検査）。週単位の戻し用 SQL を作り ROLLBACK で空打ちしてから。了承前は提案のみ。「週を生成」も書き込み。
5. **人がボタンを押したときと同じ API を使う**（PO 10/9）。必要なら画面操作（jev-hands）で確かめる。PO が「裏側でやって」と言ったときだけ API 直で可。DB への直接書き込みは原則しない（やむを得ない時は PO の了承・dry-run→COMMIT の二段・監査に残る）。
6. **お客様はカイポケで直接直す運用がある → 送る前に必ず差分を見る**。どちらを正にするかは PO が決める。
7. カイポケへの送信は**日中**（17〜18 時台を避ける）。成否は export で確かめる。
8. **大きい実装・反映は別担当がレビュー**（自己承認しない）。
9. 利用者名入りの帳票は `docs/reports/`（git 管理外）。公開しない。お客様向けは「お客様提出用」フォルダを分ける。Jev（判断モデル）へは記号と数字だけ。**実在の患者情報を外部サービスへ送るテストは禁止**。
10. PC のメモリが少ない → 試算は 1 本ずつ、長い処理はサーバー側で nohup。
11. VPS は UTC（cron は UTC で書く・バックアップ名の時刻も UTC）。
12. 事実と推測を分けて書く。引き継ぎ書とメモリより、正典の文書を正とする。
13. 新機能では事業所名・拠点・電話・ロゴ・略称をコードに書かない（別の事業所への提供の準備）。

### 4-1. 今は道具・スクリプト・手作業でしかできないこと

### 4-2. DB への直接書き込みでしかできなかったこと（記録に残る例）[事実]
| 例 | 理由 |
|---|---|
| 取消の訪問 24 件の担当を NULL に（10/4） | PATCH /courses が取消にも担当を書いた（10/5 修正） |
| 週ごとの戻し（`w42-restore-*.sql` など） | 「週を生成」・API 反映には画面の戻しが無い |
| 生成で消えた予定を戻す（`deleted_at` を戻す） | 週の生成はスナップショットを取らない |
| 主担当 NULL の修復・主担当＝コースの担当への再設定 | 過去の経路のミラー漏れ |
| 9/24 週39 をカイポケ正で 36 件合わせ | 跨ぎ date_change の失敗の後始末 |
| Excel の訂正依頼（PFV 時刻・曜日・削除・性別制限・NG・状態） | 8/16〜17 に dry-run→COMMIT の二段で一括 |
| 基本の時間の食い違い 3 名を 35 分に | 希望と型の不一致 |
| パスワードの統一 | 運用の決定（全アカウント） |
| 9/7 の 1 件（監査ログ method=SCRIPT） | アプリの決まりを例外的に通さず |
| 赤ピンの `is_pinned` と `movability` の食い違い | 見送りの昇格で片方だけ変わる経路（未修正・要確認） |

### 4-3. 画面はあるが、エージェントが使うと危ない操作
- 「週を生成」（戻せない）・「今週全件解除」（週が消える）・「自動スタッフ割当」「全面最適化」「範囲最適化」（ならし案を崩す）・`sync-fixed-to-week`（他人の担当まで書き換える）・月初展開（過去月の上書き）・Excel「完全置換」（患者を消す）・置換取込（その日を消す）・職員編集の保存（退職が稼働中に戻る）。
- エージェントはこれらを**既定で禁止**し、PO が名前を挙げて頼んだときだけ、了承・pg_dump の後に行う。

## 5. エージェントの作業の型（まとめ）

1. **読む**: 対象の週・日の予定、マスター（固定・希望・NG・性別・座標・拠点）、職員（勤務・休み・予定・新人）、カイポケの現況（差分・未送信）、プール。
2. **提案する**: ならし案（道具）または個別の変更案。入らない訪問の理由と相談先。件数の予告（増える・減る・カイポケへ送る件数）。帳票（A4・Excel）は `docs/reports/`。
3. **確認する**: 選択肢で PO に（日本語）。「今回だけ／今後ずっと」「らく助正／カイポケ正」「送る範囲」。
4. **反映する**: pg_dump → 戻し用 SQL を空打ち → 画面と同じ API を順に（最初の想定外で止まる）。
5. **確かめる**: 照合（案と盤面）・実現性チェック・診断・カイポケ export との一致。結果を runbook §7 のような記録に追記。
