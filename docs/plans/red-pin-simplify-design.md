## 2. 赤の新しい定義

- 実体: 固定訪問の枠（`patient_fixed_visits`）の 1 つの列で「赤か、赤でないか」の 2 値だけを持つ。
  - 今は `movability`（4 値）と `is_pinned`（ミラー）の二重持ち → **1 つにまとめる**（どちらを残すかは実装で決める。案: `movability` の `time_flexible`/`day_flexible` を廃止し `locked`/`unknown` の 2 値＋`is_pinned` を削除）。
- 効き方:

| 仕組み | 赤の訪問の扱い |
|---|---|
| 改善提案・範囲最適化・詰まり解消・プール一括 | 今どおり候補にしない（曜日・時刻を動かす提案を出さない） |
| 自動割当（週の生成時など） | 曜日・時刻は元に戻す（今どおり）。**コースを元に戻す処理・コース振替の禁止（G-32）はやめる**（K-2） |
| ならしの道具 | 曜日・時刻を固定（希望が「固定」の訪問と同じ扱い）。職員の割り振りは自由 |
| 人の操作（盤面のドラッグ・削除・プール戻し） | 注意を出したうえで可能（K-7） |
| カイポケ取込 | 赤とは無関係（今どおり） |

- 2 名体制: 2 人分の枠（slot 0/1）を両方とも同じに扱う（今は slot 0 だけ守られている）。改善提案は 2 名体制の患者を候補から外す（今は片方だけ動かす提案が出得る）。

## 5. リリースの進め方（案）

- 段 1: コード（API・画面・エンジン・ならしの道具）を出す。API は旧項目（`is_pinned` など）を 1 リリースの間「受けて捨てる」（`extra="forbid"` で 422 にならないように。古い画面のキャッシュ対策）。
- 段 2: 次のリリースで migration（0091 予定）で不要な列・値を消す（downgrade 付き。CI が往復で流すため）。
- 赤専用の API 2 本（`PATCH /patients/fixed-visits/{id}/pin`・`POST /patients/fixed-visits/pin/bulk`）は盤面専用なので削除。
- テスト: 棚卸し `2-api-db-tests.md` §5・`3-frontend.md` §4 の一覧どおりに削除・書き換え。全書き込み経路で「赤が 1 か所でそろう」ことを横断テストで固定。
- 文書: 仕様書・マニュアル 2 本・道具の README・スキル（week-leveling）を改訂。
- 実装と審査は別担当（自己承認しない）。本番反映前に pg_dump。

## 6. 将来の課題（今回はしない）
