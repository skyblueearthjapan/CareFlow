## 1. 事象
今週 (2026-08-31 週 / W36) の盤面に、入院・休止・解約の患者の訪問が表示された。PO は当面「今週だけ取消（manual_cancel）」で×を付けて対処。

## 2. 原因（確定）
- 訪問は **週生成した時点で `patients.status='active'` だった患者**から作られる（`layer1_expander` / `auto_allocator*` は生成時にだけ status を見る）。
- その後にステータスを admitted / suspended / cancelled に変えても、**生成済みの未来の訪問には何も波及しない**（`PUT /patients/{id}` に連動処理なし・盤面/週ビューも患者 status で絞っていない）。
- 今週分 136 件は 2026-08-07 10:29 に一括生成（source=auto）。ステータス変更はすべてその後（朝倉 8/24 入院・小川 8/31 08:10 解約・清水 8/31 08:21 解約・藤田守 8/31 09:46 休止・藤原 8/31 09:54 入院）。
- **特別訪問週間（⭐）のプール**は `special_visit_periods.status='active'` しか見ず、患者 status を見ない → 藤原様は入院後も○チケットがプールに出続け、本日 19:54/19:56 に配置された（source=manual_week）。

1. 残 planned の取消: 8/31 の 3 件、藤原 9/3・9/4、W42 の 17 件（UI「今週だけ取消」or 管理者操作）。

# 残タスク（追加・2026-08-31 20:40）: ログイン回数制限が事業所全員に効いてしまう

- 事象: 松岡様がパスワード誤り 5 回（20:26〜20:27 JST・うち 3 回が松岡様アカウント）→ 以後 `POST /auth/login` が **429 Too Many Requests**（20:27〜20:37 に 11 回）。アカウントロック（5 回失敗で 15 分・`locked_until`）は未発動。
- 原因: `backend/app/core/rate_limit.py` の limiter が `get_remote_address`（接続元 IP）でキー付けされているが、本番では NextAuth の `authorize()` が **frontend コンテナ（172.24.0.4）からサーバー側で backend を呼ぶ**ため、**全ユーザーのログインが同一 IP に見える** → 「5 回/15 分」が事業所全体の上限になる（1 人の入力ミスで全員が 15 分ログイン不可）。
- 対処案: ① frontend が `X-Forwarded-For`（Cloudflare の `CF-Connecting-IP`）を backend へ転送し、limiter の key_func をそのヘッダ優先にする ② または key を「メールアドレス（正規化）」にして per-account 化（既存の `locked_until` と二重になるので統合を検討）③ 429 の応答に「あと N 分」を含め、FE のログイン画面で案内を出す。
- 当面の運用: 429 が出たら **約 15 分待ってから 1 回だけ**試す（連打しない）。パスワード不明なら admin が /admin/users からリセット。
