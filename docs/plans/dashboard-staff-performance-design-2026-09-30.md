# ダッシュボード刷新 — スタッフ別の実績（設計・たたき台）

作成: 2026-09-30 ／ ステータス: **実装済み・未レビュー**（2026-10-01・本番未反映）
見た目の正典: `docs/mockups/dashboard-staff-performance-mock.html`（B = 人ごとのカード → 押すと C = 1 人を深く見る）

## 0. 目的（PO 2026-09-30）

トップのダッシュボードを、スタッフ基準で訪問の実績が分かる実用的な画面にする。スタッフの評価の基準にもなるので、管理者が無駄の有無と実際の業務量をひと目で、正確に判断できること。

見たい項目: 訪問実績（1 週間・1 か月で何件・何名）／1 回あたりの所要時間／移動距離／1 日あたりの平均稼働回数。

今のダッシュボード（`backend/app/api/v1/dashboard.py`・`frontend/app/(app)/dashboard/page.tsx`）は全体の数だけ（今日の訪問・完了・未割当・重複・今週合計・完了率＋7 日トレンド）で、スタッフ別が無い。

## 1. 決定（PO 2026-09-30）

- **トップは B（人ごとのカード）、カードを押すと C（1 人を深く見る）**。A（全員を 1 表で比べる）は採らない。
- 実装前にモックで見せ方を詰める進め方。

## 2. データの実情（本番 2026-08-31〜09-30・読み取りで確認）

| 項目 | 出せるか | 根拠 |
|---|---|---|
| 訪問件数・利用者数 | 出せる | `visits`（主担当・取消を除く）。1 人 84〜112 件／38〜56 名（新人を除く） |
| 1 日あたり件数 | 出せる | 件数 ÷ 訪問のあった日数。4.3〜6.1 件 |
| 1 回あたりの時間（予定） | 出せる | `end_time - start_time`。平均 35〜37 分 |
| 1 回あたりの時間（実績） | **一部だけ** | QR の到着・退出が揃った訪問のみ。630 件中 88 件（14%）。読み取り 0 件の職員 1 人、到着しか読まない職員 1 人 |
| 移動距離 | **直線なら出せる** | 患者 84 名・拠点とも座標あり。拠点 → 訪問 → … → 拠点の直線。17〜34 km/日。道のりの距離は無い |
| 車ごとの回数 | **出せない** | 車両・誰がどの車を使ったかの記録が無い |
| 会議・研修・休み | 出せる | `staff_events`（朝会 166・休み 57・カンファ/研修 16 ほか） |

## 3. 数字の決め方（PO 確認済み）

| 指標 | 定義 |
|---|---|
| 訪問件数 | 主担当（`primary_staff_id`。空ならコース担当）の訪問。取消・削除を除く。予定外の訪問を含む |
| 利用者数 | 期間内の実人数 |
| 出勤日数 | 訪問が 1 件以上あった日数（勤務表ではなく訪問の有無で数える） |
| 1 日あたり件数 | 訪問件数 ÷ 出勤日数 |
| 1 回あたり（予定） | 予定の長さの平均 |
| 1 回あたり（実績） | 実績時刻（`services/checkin/actuals.py`・調整後）の到着〜退出の平均。**到着・退出が揃った訪問が 5 件以上あるときだけ出す**。件数を必ず併記 |
| 移動距離 | 所属拠点 → 1 件目 → … → 最後 → 所属拠点を直線でつないだ合計。1 日あたり・1 件あたり |
| 1 日の内訳（追加案） | 訪問 = 予定の合計／移動 = 距離 ÷ 時速 20km（スケジュール計算と同じ前提）／合間 = 訪問と訪問の間から移動を引いた残り |
| チーム平均 | 表示中の拠点・期間の、訪問のあった人の平均 |

実績時間は「実績の時刻を合わせる」（Phase 2）の単一ソースを使う。調整した時刻がそのまま評価の数字になるので、Phase 2 の本番反映が前提。

## 4. 画面

- 期間: 今週／先週／今月／先月／任意。拠点の絞り込み。
- 上段: チーム全体の数字（訪問件数・1 人 1 日あたり・1 回あたり・移動・QR で時間が取れた割合）。QR の割合が低い間は注意書きを出す。
- **B カード**（1 人 1 枚）: 氏名、役割の札（拠点・管理者・准看護師・新人）、出勤日数／訪問件数と利用者数／1 日あたり（平均との差）／1 回あたり（予定と実績）／移動（km/日・平均との差・km/件）／週ごとの 1 日あたり件数の小さな棒。
- **C 1 人**: 5 週（または選んだ期間を週で割った）推移を、チーム平均と重ねた折れ線 4 枚（1 日あたり件数／1 回あたりの時間／1 日あたりの移動距離／1 日あたりの訪問の合間）＋週ごとの表。
- 今のダッシュボードの「今日の訪問・未割当・重複」などの運用の数字は、上段の下に小さく残すか、訪問モニターへ任せるかを決める（未決）。

## 5. PO 確認済み（2026-09-30「案のとおり」）

| # | 論点 | 決定 |
|---|---|---|
| 1 | 「この車で何回」 | **人ごとの 1 日あたり件数**で見る。車両単位の記録は作らない |
| 2 | 誰が見られるか | **管理者だけ**で始める（staff ロールには出さない） |
| 3 | 無駄を見る物差し | 「1 日の内訳（訪問・移動・合間）」と「1 件あたりの移動距離」を **C（1 人を深く見る）に載せる** |
| 4 | 出勤日数 | **訪問が 1 件でもあった日**で数える |
| 5 | 会議・研修の時間 | 「訪問の合間」から**分けて出す** |
| 6 | 今のダッシュボードの数字（今日の訪問・未割当・重複など） | **小さく残す** |
| 7 | 移動距離 | **直線のまま**（道のりにはしない） |

5 を受けた「1 日の内訳」の定義: 訪問／移動（直線距離 ÷ 時速 20km）／会議・研修など（`staff_events` のうち休み以外で、その日の最初の訪問開始〜最後の訪問終了に重なる分）／合間（訪問と訪問の間から、移動と会議・研修を引いた残り。0 未満は 0）。

2 を受けた権限: `require_role("admin")`。staff がダッシュボードを開いたときは、今のダッシュボードの数字（6 で残すもの・自分の分に絞られる既存の挙動）だけを出す。

## 6. 評価に使う際の注意（画面にも出す）

- 実績の時間は QR が定着するまで参考値。読み取りの無い人は「—」。
- 件数は役割（管理業務・新人）と勤務日数で変わる。役割の札と「1 日あたり」を並べる。
- 距離は直線。人どうしの比較には使えるが、走行距離や燃料費の計算には使えない。

## 7. 実装の見込み（決定後）

- BE: `GET /api/v1/dashboard/staff-performance?from&to&office_id`（admin）。期間内の訪問・実績時刻・座標・イベントを読み、職員 × 週で集計して返す（1 か月で約 600 訪問なので Python 側で集計）。
- FE: `/dashboard` を差し替え。カード、折れ線（既存の recharts）、期間と拠点の切り替え。
- 前提: Phase 2（実績時刻の単一ソース）が本番に入っていること。

## 8. 実装で確定した点（2026-10-01）

- **API**: `GET /api/v1/dashboard/staff-performance?from&to&office_id`（`require_role("admin")`）。集計は `backend/app/services/dashboard_staff_performance.py`。`from`/`to` を省くと今週。期間は 93 日まで（超えると 422）。返すのは 期間の数字 ＋ 週（月〜日・両端は期間で切る）ごとの数字を、職員ごととチーム平均で。拠点の一覧（`short_label` 付き）も同じ応答に入れる。
- **持ち主**: 主担当、空ならコース担当（訪問モニターの行と同じ条件 = 手動差し替えでない・コースが未削除）。モニターと違い「コース担当が今も在籍中か」は見ない（過去の期間を集計するため）。
- **拠点の絞り込み**: 職員の所属拠点（`staff.primary_office_id`）で絞る。距離の起点・終点も所属拠点。
- **実績**: `actuals.py` の到着・退出（調整後）から `stay_minutes` で出す。5 件以上で平均。件数（`actual_samples`）と「到着だけ」の件数（`arrival_only`）を常に返す。
- **距離**: `app/utils/geo.haversine_km` を使う。座標の無い端点を含む区間は飛ばし（つながない）、数を `skipped_legs` で返す。画面では C に「距離に入れていない区間が n か所」と出す。
- **移動速度**: `scheduling_settings.travel_speed_kmh`（無ければ既定 20）。応答の `travel_speed_kmh` で画面にも出す。
- **1 日の内訳**: 合間は日ごとに「訪問と訪問の間（重なる訪問は 1 本の帯）− 訪問間の移動（拠点との行き帰りは含めない）− 会議・研修など」、0 未満は 0。表の「移動」は拠点との行き帰りを含む全区間。
- **休みのイベント**: `staff_events` に休みの種別は無い（カイポケ取り込みの件名に出る）ため、**件名に「休」を含むもの（「休憩」を除く）を休み**として除く。取消（`cancelled_at`）も除く。イベントは壁時計の時刻のまま読む（`staff_events._combine` と同じ）。
- **チーム平均**: 1 日あたり・1 回あたり（予定）・km/日・km/件・内訳は、訪問のあった人の値の平均。件数・日数などは合計。**実績の平均だけは全員の揃った訪問を合わせて 5 件以上のとき**に出す（1 人ずつの平均は 5 件未満で出ないため）。
- **役割の札**: 拠点 = `offices.short_label`（無ければ拠点名の 1 文字目・`checkin.monitor.office_short`）／管理者 = 業務ロール `staff.role` が manager（旧 admin を含む）／准看護師 = `staff.qualification`／新人 = `staff.is_trainee`。
- **画面**: 期間は既定「今月」。「今週」「今月」は**今日まで**（先の予定は実績に数えない）。今日の運用の数字（今日の訪問・完了・未割当・重複・今週合計・今週完了率）は上段の下に 1 行で小さく残した（§4 の未決は「小さく残す」で確定済み）。QR の割合が 5 割未満の間は注意書き。§6 の 3 点は常に画面の下に出す。
- **グラフの色**: 既存のトークンだけを使う（この人 = `--sched-ghost-before`・実績 = `--sched-event-bar`・チーム平均 = `--text-muted` の破線・移動 = `--sched-now`・会議・研修など = `--sched-ghost-after`・合間 = `--border-strong`）。
- **staff ロール**: 今までのダッシュボード（自分の分に絞られる KPI と 7 日のトレンド）のまま。新しい API は呼ばない。
- **migration**: 無し。
