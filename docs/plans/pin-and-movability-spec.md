# ピン留めと可動域の仕様（PO 決定 2026-08-07〜08）

固定訪問スケジュール（型 = `patient_fixed_visits` / 以下 PFV）に対する「動かさない」
手段は 2 つある。両者は **独立した軸** であり、互いに上書きしない。

| | 実体 | 対象 | 効く範囲 | 位置づけ |
|---|---|---|---|---|
| ピン留め | `PFV.is_pinned` | 型の枠 | 毎週 | **一括で掛け外しする道具** |
| 可動域 | `PFV.movability` | 型の枠 | 毎週（ピンを外したときに効く） | **現場の判断の記録** |

`visits`（今週の実配置）には pin / lock に相当する列は無い。**週単位の固定は
現時点で存在しない**（`source='manual_week'` が「その週だけ型を上書きする」意味論を
持つが、これは別概念。将来「青ピン」として入口を付ける案が議論中）。

---

## 1. ピン留め（型のピン）

### 1.1 何を守るか

- **型の編集・削除を拒否する。** `PUT /patients/{id}/fixed-visits` は、既存の
  pinned 行に対する一切の差分を 422 で拒否する（`pfv_validator._check_pinned`）。
  同一性タプルに `is_pinned` 自体が含まれるため、**ピン留めを外すだけの差分も
  「変更」扱いで 422**。
- **生成された訪問の時刻が移動時間補正で動かない。**
  `_apply_corrections_to_visits` の凍結フェンスが engage する。

### 1.2 解除の経路

**ピン解除は `PATCH /patients/fixed-visits/{pfv_id}/pin` のみ。**
PUT に混ぜてはいけない（上記のとおり 422 になる）。

一括操作は `POST /patients/fixed-visits/pin/bulk`。

### 1.3 【規約】盤面からのピン留めは型と一致する訪問にのみ可能

> **盤面（日タイムライン・週ビュー・リスト表示）のピン留めボタンは、その訪問が
> 型の枠と一致しているときにのみ操作できる。一致とは
> `(患者, 曜日, 開始時刻, スロット)` が完全に同じであることをいう。
> 一致しない訪問はピン留めできない。**

**理由**: ピンは型の属性なので、型とズレた訪問にピンを刺しても、固定されるのは
**型の時刻**であって画面に見えている時刻ではない。操作と結果が食い違う。

**実装**: FE が突き合わせに失敗した訪問の `fixed_visit_id` を null にし、ボタンを
無効化する。無効時は理由を表示する（下記 3 章）。

**バックエンドには同じ制約を置かない。** `PATCH .../pin` は患者マスタからも
呼ばれ、そちらは今週の配置と無関係に型へピンを刺すのが**正当な操作**だから。
API に週との一致を強制すると、患者マスタ経由の正当な操作まで弾いてしまう。

この規約は突き合わせキーの実装詳細に依存するため、**FE テストで固定する**
（`PatientFixedVisitsPanel.test.tsx` / 盤面側テスト）。突き合わせ方を変えたときに
テストが落ちることで気付ける。

## 2. 可動域

### 2.1 2 段階（PO 決定 2026-08-08）

| 値 | ラベル | 意味 |
|---|---|---|
| `locked` | 完全固定 | 提案系エンジンも自動割当も動かさない |
| `unknown` | 指定なし | 制約の記録なし（希望訪問スケジュールの範囲内なら動かしてよい） |

`time_flexible` / `day_flexible` は 4 段階時代の値。**本番の利用実績は 0 件**
だったため 2 段階へ整理した。DB CHECK は 4 値のまま残してあるので、既存値が
あっても壊れない（FE は旧値をラベル表示だけして、編集すれば 2 段階に収束する）。

### 2.2 ピン留めとの関係（重要）

**可動域はピン留めの掛け外しで変化しない。**

- ピン留めしても可動域を上書きしない（旧 V6 の強制矯正は廃止）
- ピン解除しても可動域をリセットしない（旧 P4-C の解放は廃止）
- **ピン留め中でも可動域を表示・編集できる**

最後の点は要件。一括ピン解除の**前に**「完全固定」を仕込めないと、解除した瞬間に
動いてしまう。旧実装はピン留め中にセレクタを隠しており、これができなかった。

これにより PO の運用が成立する:

> 一括でピンを抜いても、裏で「完全固定」にしている枠は動かない。
> 「固定を動かしちゃいけない人」は同じ曜日・同じ時間に行くことが担保される。

### 2.3 どのエンジンが尊重するか

| エンジン | `is_pinned` | `movability='locked'` |
|---|---|---|
| 改善提案 `improvement_engine` | 除外 | 除外 |
| 範囲最適化 `scope_optimizer` | 除外 | 除外 |
| 詰まり解消 `unblock_search` | 除外 | 除外 |
| プール一括投入 `pool_bulk_inserter` | 除外 | 除外 |
| **自動割当 `auto_allocator_v2`** | 凍結 | **凍結（2026-08-07 に追加）** |

自動割当は 2026-08-07 まで `movability` を見ておらず、「提案系では不可侵なのに
自動割当では動く」という非対称があった。`V2Visit.is_movability_locked` を新設して
解消済み（`is_pinned` とは別フラグ。経路優先度や 📌 表示を変えないため）。

### 2.4 希望訪問スケジュールとの関係（P4-A 層 2）

候補が患者の希望訪問スケジュールの範囲内なら、**可動域を問わず提案でき、患者確認も
不要**。「聞き取り済みの受け入れ可能範囲＝余白」という考え方。

稼働患者 69 名全員に希望訪問スケジュールが登録されているため、この層はほぼ全員に
効く。可動域に細かい段階が要らない理由でもある。

ただし該当曜日のエントリが無い場合は層 3（可動域ルール）にフォールバックする。

## 3. 型とのズレの表示（PO 決定 2026-08-08）

今週の実配置が型と違う時刻になることがある（実測: 1 週 117 訪問中 2 件 = 1.7%、
いずれも自動割当が動かしたもの）。

**方針: ズレていることを伝えるだけ。合わせ直す導線は設けない。件数のサマリも作らない。**
どうするかは現場に委ねる。

表示は案 A + 案 B の併用（`components/schedule/timeline/masterDivergence.ts`）:

- **案 A**: カード左端の帯を破線＋警告色にする。文字を足さないので最小のカードでも見える
- **案 B**: 時刻行に「（型 HH:MM）」を併記する。2 時間半ズレる例もあり、ズレの有無だけでは
  現場が判断できないため

適用先は日タイムライン・週タイムラインの両方。

ピン留めボタンが無効なときの理由表示も、ここと同じ情報を使う:

- 固定枠が無い → 「先に固定枠登録が必要」
- **固定枠は在るが時刻が違う** → 「固定訪問スケジュールは HH:MM です。この時間帯では
  ピン留めできません」

旧実装は後者でも「先に固定枠登録が必要」と表示しており、固定枠は登録済みなのに
「登録が必要」と言われる状態だった。

## 4. 既知の残課題

- **週単位の固定（青ピン）が存在しない。** 型とズレた訪問を「今週はこのまま」と
  固定する手段がない。`source='manual_week'` に昇格させる案を議論中。
- `test_schedule_v2_api.py` の `reset_to_fixed` 系 2 件がベースラインで失敗したまま。
  移動時間補正の検証が効いていない。
