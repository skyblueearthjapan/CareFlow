# ピン留めと可動域の仕様（PO 決定 2026-08-07〜09）

> **2026-08-09 大改訂（統合）**: 旧「ピン留め (`is_pinned`)」と「可動域: 完全固定
> (`movability='locked'`)」は **1 つの概念「完全固定」に統合** された。
> 赤ピン = 完全固定の表示である。以下は統合後の正仕様。

固定の手段は 2 つ。**対象が違う**（型 vs 今週の訪問）。

| | 実体 | 対象 | 効く範囲 | 意味 | 画鋲の色 |
|---|---|---|---|---|---|
| **完全固定** | `PFV.movability='locked'`（`is_pinned` は非推奨ミラー） | 型の枠 | 毎週 | **エンジンは動かさない。人手はいつでも変更できる** | 🔴 赤 |
| **週のピン** | `visits.week_pinned`（フラグ） | 今週の訪問 | その週だけ | **今週この位置のまま。人手操作も蓋（ロック）される** | 🔵 青 |

覚え方（PO の言葉）:

- 🔴 赤 = 「いつの間にか変わらないように」。**システム（エンジン）だけを縛る**。
  人手で動かすときは「これは完全固定です」の注意書きを見たうえで動かせる。
- 🔵 青 = 「今週はこのまま」の**蓋**。刺さっている間は盤面からの人手操作
  （移動・削除）もブロックされる。編集したければ一度解除してから。
- **大元の固定訪問スケジュール（型）自体はユーザーがいつでも変更できる。
  これが本質**（PO 2026-08-09）。

---

## 1. 完全固定（赤 = 型に対する固定）

### 1.1 実体と後方互換

- 正典は `PFV.movability = 'locked' | 'unknown'`。
- `PFV.is_pinned` は**非推奨ミラー**: 全書き込み経路で
  `is_pinned ≡ (movability == 'locked')` を維持する
  （PUT / PATCH pin / bulk / place-and-fix。migration 0067 で既存行を同期済み）。
  エンジン側に `is_pinned` を読む箇所が残っていても意味が食い違わないための策。
- 旧 `time_flexible` / `day_flexible` は本番実績 0 件。DB CHECK には残るが、
  FE は「旧設定」ラベル表示のみ。編集すれば 2 値に収束する。

### 1.2 何を守り、何を守らないか

**守る（エンジンは動かさない）:**

| エンジン | 挙動 |
|---|---|
| 改善提案 `improvement_engine` | 除外 |
| 範囲最適化 `scope_optimizer` | 除外 |
| 詰まり解消 `unblock_search` | 除外 |
| プール一括投入 `pool_bulk_inserter` | 除外 |
| 自動割当 `auto_allocator_v2` | 凍結（`is_pinned or is_movability_locked` フェンス） |
| 提案 apply（個別/スワップ/週のみ apply） | 422 で拒否（エンジン経路のみ） |

**守らない（人手はいつでも操作できる / 2026-08-09 撤廃）:**

- 患者マスタの PUT — 完全固定行の時刻・コース・削除・フラグ切替すべて可。
  旧 `pfv_validator` V2（pinned 行の差分 422）は**撤廃**。
- 訪問カスケード削除 / place-and-fix / 週のみ移動 — 赤起因の 422 は**撤廃**。
  place-and-fix は旧枠の movability を新枠へ**継承**する（判断の記録を消さない）。
- 盤面のドラッグ移動・×削除・プール戻し — 可能。ただし**確認 UI に
  「⚠ これは完全固定です」を必ず出す**（移動=ダイアログ内注意、削除/プール戻し=confirm 文）。

### 1.3 設定・解除の経路

- **患者マスタ（正）**: 固定訪問スケジュールの各曜日行に「完全固定」チェック
  ボックス + 週一括ボタン「全曜日を完全固定 / 解除」。**保存 (PUT) で確定**
  （サーバーが is_pinned をミラー）。
  - PO 要件: 「1 週間分全体」と「一つ一つの時間」の両方を選べること。
- **盤面（補助）**: カード右下クラスタの赤トグル（PinScopeMenu: この曜日のみ /
  全曜日）= `PATCH /patients/fixed-visits/{pfv_id}/pin` ・
  `POST /patients/fixed-visits/pin/bulk`。**pin API は movability ごと切り替える**
  （on → locked / off → unknown）。
- **一括ボタン「全件ピン留め / 全件ピン留め解除」は廃止**（PO 2026-08-09）。
  完全固定は患者ごとの判断であり、週の盤面から全患者へ一括で掛ける道具は
  概念統合後は誤操作のもとになるため。

### 1.4 【規約】盤面からの完全固定は型と一致する訪問にのみ可能

> 盤面の赤トグルは、その訪問が型の枠と一致しているときにのみ操作できる。
> 一致とは `(患者, 曜日, 開始時刻, スロット)` が完全に同じであることをいう。

**理由**: 完全固定は型の属性。ズレた訪問に掛けても固定されるのは型の時刻で、
操作と結果が食い違う。ズレた訪問を守りたいときは青ピンを使う。

無効時の理由表示: 固定枠なし →「先に固定枠登録が必要」/ 固定枠はあるが時刻が
違う →「固定訪問スケジュールは HH:MM です。この時間帯では完全固定にできません」。

**バックエンドには同じ制約を置かない**（患者マスタ経由の正当な操作を弾かないため）。
規約は FE テストで固定する。

## 2. 希望訪問スケジュールとの関係（P4-A 層 2）

候補が患者の希望訪問スケジュールの範囲内なら、完全固定でない限り提案でき、
患者確認も不要。「聞き取り済みの受け入れ可能範囲＝余白」という考え方。
該当曜日のエントリが無い場合のみ可動域ルール（unknown = 要確認）へフォールバック。

## 5. 週のピン（青ピン）

### 5.1 何のためにあるか

赤（完全固定）は型と一致する訪問にしか掛けられない（§1.4）。**型とズレた訪問を
「今週はこのまま」と守る手段**が青ピン。

用途:
- 「今のスケジュールを変更したくないまま提案を出してほしい」→ 青を刺す
- 「その週限定のスケジュール変更をしたい」→ 動かして青を刺す（型は変わらない）

### 5.2 実体（専用フラグ / PO 決定 2026-08-09）

`PATCH /api/v1/schedule/v2/visits/{visit_id}/week-pin` body `{pinned: bool}`

- `pinned=true` → `visits.week_pinned = true`（source は不変）
- `pinned=false` → `week_pinned = false`。source が `manual_week` のときだけ
  `auto` へ戻す。import / manual は source そのまま

**なぜ source 書き換えをやめたか**: 本番はカイポケ取込週が主（119 件中 114 件が
`import`）。旧方式は出所の記録が失われ、一括解除で取込訪問が週生成に削除され得た。

保護の意味論（フラグ ∪ `manual_week` の和集合で判定）:

1. 週生成（reset / generate-week-only とも）の削除対象から除外
2. 再生成ループが当該 `(patient_id, visit_date)` を skip
3. **`import` の日も再生成 skip**（案 B: カイポケ取込が正）

### 5.3 青ピンは「蓋」— 人手操作もブロック（PO 決定 2026-08-09）

**青ピンが刺さっている間は、スケジュール画面からの人手操作をブロックする。
編集したければ一度解除してから。**

- BE（二重防御の本丸・422）:
  - `visit-move-week-only`（週のみ移動）→ 422「今週固定（青ピン）されています。
    解除してから動かしてください」
  - `DELETE /visits/{id}` → 422「…解除してから削除してください」
  - `PATCH /visits/{id}` の配置フィールド（visit_date / start_time / end_time）
    → 422（同リクエストで `week_pinned: false` を伴う場合は許可。メタ項目は自由）
- FE:
  - ドラッグ不可（掴むと shake + 理由ツールチップ）。単独カード・ペア箱・
    ⠿ 個別ハンドルすべて
  - × 削除ボタンは無効表示 + 理由ツールチップ（日ボード・日リストとも）

赤と違い**確認して突破する道は無い**。解除 → 操作 → （必要なら）再度刺す。

### 5.4 解除したときの挙動（PO 確認済み）

**解除してもその場では訪問は動かない。** 実際に型の時刻へ戻るのは**次に週生成を
実行したとき**。

### 5.5 掛け外しできない訪問

- `planned` 以外（完了・実績入力済み等）→ 422
- source による制限は無し（フラグ方式で出所に触れないため）

### 5.6 UI

**状態表示（常時・右上の画鋲）**: 赤 = 角、青 = 赤の左隣。両方刺さっていれば
2 本並ぶ。日・週タイムラインとも同じ規則。

**操作（ホバーで出現・右下クラスタ）**: `[赤トグル][青トグル][×削除]`。
日リストは `[赤▾][青][×]` の並び。

**一括操作**: ヘッダー中段は**青のみ** `今週の配置: [今週全件固定][今週全件解除]`
（赤の一括は廃止 §1.3）。
- 青の一括 = `POST /api/v1/schedule/v2/visits/week-pin/bulk`（表示中の週の
  planned 全件・カイポケ取込含む）。件数は dry_run で 2 段階確認
- 「今週全件解除」の確認文には「次の週生成で型の時刻に戻る」ことを必ず明示

**既知の制限**: 2 名体制のペアカードは行が極小のためトグルを出していない。
