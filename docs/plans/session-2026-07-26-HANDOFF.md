   「臨時」枠に合算表示される（帰属はコード'臨'のコース担当者）。コース新設改修で実質1本/日になり顕在化しないが、

5. **カイポケ画面DOM依存**: `btnIndividual`クラス・`showIndividualEdit`引数・`staffSchedule`のフォーム構造。
   カイポケ改修で壊れたら fail-fast する設計（0件+btnIndividual存在→エラー / day二重検証）
6. **イベント取得 ~90s は Cloudflare 100s 制限に近い**。524が出たら export と同じ async+ポーリング化（設計書§7）
7. **差分モードの月跨ぎ週**は現況CSVが月単位のため週後半（翌月分）がキャンセル候補に見える既知制限

## 6-c. ★提案エンジンのイベント考慮（2段階自動フォールバック）— **実装済み・本番稼働（2026-07-27 348d8ff・mig 0063）**

**背景（PO確定）**: カイポケ同期でイベントが常態化したが、提案エンジン（プール投入/改善/
詰まり解消/pool-overview）はイベントを見ていなかった（Layer3のみW27/W33でハード除外）。
訪問は優先度が高くイベントは動かせるものが多い一方、絶対に潰せないイベントもある。

**方式 = 2段階を1回の計算で**（`proposal_solver.find_available_slots_for_candidate` に
`event_windows` を渡すだけで各機能が自動で2段階になる）:
1. パスA: 全イベントを占有（前後15分バッファ = Layer3 `BUFFER_MINUTES` と同値）として
   クリーン枠を探索。1件でもあればクリーン枠のみ提案
2. ゼロ件のときだけパスB: `blocking=False` のイベントを無視して再走査し、衝突枠を
   `warnings='event_conflict'` + `event_conflicts`（タイトル/時間帯）付きで提案。
   FEは「⚠配置後にイベントの方を手動調整してください」を候補カードと採用確認に表示
3. **🔒blocking イベント**（mig 0063 `staff_events.blocking`・既定false）はパスBでも占有
   のまま = 絶対に衝突提案を出さない。トグルはスタッフ詳細のイベント編集ダイアログ
   「この時間は絶対に空けておく」。カイポケ再取込のupdateはこの列に触れないため保持される
   （**削除→再追加されるとOFFに戻る**点だけ注意）

**機能別の扱い**:
- propose-slots / pool-overview: 2段階 + 警告&-60スコア降格（「除外しない」原則に整合）
- 改善提案(move): 2段階 + event_conflicts。**swapは対象外**（時刻交換のみで新しい時間帯を
  作らない = 新規衝突が発生し得ない）
- 詰まり解消の退避 / 範囲最適化: **クリーンのみ**（既存患者を衝突枠へ自動で動かさない）
- 2名体制ペア(W-12a): クリーンのみ（衝突anchorのペア伝播は複雑化のため見送り）
- Layer3自動割当: 従来どおりハード除外（変更なし）
- スケジュール診断(schedule-health): **未対応のまま**（イベント重複の検出項目は将来課題）

**実装の正典**: `proposal_solver.py`（EventWindow/イベント擬似訪問・容量不算入・
同住所ペアフィルタ）/ `propose_slots_service.load_week_event_windows()`（naive壁時計・

## 6. 次の実装相談に備えて

POは「予定のおかしな点を1つずつ相談する」モードで進めている。直近の流れ:
1枠15件→コース付替で解消 → 誤帰属→帰属修正 → 9名枠→コース新設 → （未割当）表示→select修正。
**次も同様に「スクショ+症状」が来る可能性が高い。** 調査の型:
1. まず本番DBを実測（`ssh root@72.60.211.213 'docker exec carelink-postgres psql -U carelink -d carelink -c "..."'`）
   — 表示問題かデータ問題かを最初に切り分ける
2. データ問題なら置換ロジック（replace_inbound.py）・表示問題ならテンプレ単位ビューの合算/帰属を疑う
3. 修正→テスト→デプロイ（frontendのみなら build frontend で3分・migrationなければ --no-cache 不要）
4. **置換は冪等** — データ側の修正は「再実行してもらう」だけで反映できる
