# 前の週をコピーして週を作る — 設計（たたき台）

作成: 2026-09-30 ／ ステータス: **実装済み・未レビュー**（2026-10-01。PO がモックを承認し §4 の「案」はすべて確定。§6 はモックのとおりに解決。実装で確定した点は §8）
見た目の正典: `docs/mockups/copy-week-mock.html`

## 0. 目的（PO 2026-09-30）

今は新しい週を「固定訪問（PFV）から生成」でしか作れない。実際に回した前の週（直近の近い週）を次の週へコピーできるようにする。流れ = 固定訪問で生成 → 職員スケジュールで任意に調整 → 次の週はその週からコピー。ねらいは**患者さんの予定（曜日と時刻）を一定にしていく**こと。

## 1. PO 決定（2026-09-30）

| # | 決定 |
|---|---|
| 1 | **写すのは患者の予定（曜日・開始時刻・長さ）。担当は写さない。** 同じ患者に同じスタッフが続くのは NG で、ローテーションが基本 |
| 2 | 写す時刻は**その週の予定として確定した時刻**（`visits.start_time` / `end_time`）。QR の実績時刻ではない |
| 3 | **固定訪問（マスタ）とは別に考える。** 週のコピーは固定訪問を読まない前提で動き、固定訪問へ書き込まない。固定訪問への反映は今までどおり別の操作 |

## 2. 本番の実測（読み取りのみ・2026-09-30）

- 前週と同じ患者・曜日 67〜79%／開始時刻まで同じ 18〜26%／30 分以内 38〜44%／担当も同じ 2 割前後。
- 同じ患者・同じ曜日で 9 月に 3 回以上訪問した 127 組のうち、毎回同じ時刻は 19 組（56 組は 3 通りの時刻）。今は時刻が週ごとに動いている。
- 9/28 の週 → 10/5 の週へ写す場合: 写す訪問 147 件（月 27・火 26・水 30・木 26・金 26・土 12）、取消 5・予定外 1 は写さない、止まっている患者の訪問 0、固定訪問に無い（患者・曜日）訪問 28、臨時コース配下 23、写す元に無かった固定訪問 30（うち 10 名は訪問が 1 件も無い）。
- 祝日のある週（9/21 の週）は、1 週前より 2 週前のほうが次の週に近かった → 写す元は選べるようにする。

## 3. 今の仕組み（調査結果の要点）

- 週を別の週へ写す機能は無い。土台として使えるのは取り込み前スナップショット（`backend/app/services/kaipoke/inbound_snapshot.py` の `snapshot_week` / `restore_snapshot`）。
- 「週を生成」= `POST /schedule/generate-week-only`（Layer1）。`source='auto'`・担当なしで作る。`manual_week`・`import`・青ピンの生存行がある（患者・日）は再生成を飛ばす。
- 担当は「自動スタッフ割当」（`POST /schedule/assign-staff-only`・Layer3）が付ける。過去 4 週の担当履歴を読み、同じ担当が続かないようにする。
- 担当はコース・`visits.primary_staff_id`・`visit_staff_assignments` の 3 か所を揃える必要がある（片方だけ書いてカイポケの担当が消えた事故あり）。
- 対象の週・月を取り違えた事故あり（2026-08-31）→ 対象の明示・強い確認・実行前の保全が要る。

## 4. 仕様（確定・PO がモックを承認 2026-10-01）

### 4-1. 入口
スケジュール画面のツールバーの「週を生成」を「週を作る」にし、ダイアログで **固定訪問から生成**（今の動作）か **前の週をコピー** を選ぶ。

### 4-2. 写す元の週
過去 8 週のうち訪問がある週を一覧にする（訪問件数・利用者数・取消・予定外・QR の記録件数）。直近の週を初期選択。写す先は画面で開いている週（今週以降のみ）。

### 4-3. 写すもの・写さないもの

| 対象 | 扱い |
|---|---|
| 訪問の患者・曜日・開始/終了時刻 | **写す**（日付は同じ曜日へ +N 週） |
| 2 名体制（`visit_group_id`・`required_staff_count`） | 写す（ペアは新しい ID で組み直す） |
| サービス内容の上書き（`kaipoke_service_override`） | 写す（患者ごとの事情のため） |
| コース | 写す先の週の**同じテンプレートのコース**へ入れる（無ければ作る）。臨時コース配下の訪問は、コースなし（担当なし行）で入れ、自動割当に任せる |
| 担当（primary / secondary / mentor / VSA / コース担当 / `manual_staff_override`） | **写さない** |
| 取消した訪問・予定外の訪問・特別訪問週間の追加分 | 写さない |
| 止まっている患者（写す先の週の時点で非稼働）の訪問 | 写さない（件数を確認画面に出す） |
| 青ピン・メモ・`kaipoke_id`・打刻・実績の調整 | 写さない |
| 同行・イベント・休み | 写さない（同行とイベントは今までどおり既定から展開する） |

確認画面で選べるもの:
- **固定訪問に無い訪問**（その週だけ追加・曜日を動かした可能性）を一覧にし、まとめて／1 件ずつ外せる。初期値は「写す」。「今週だけ追加」と「今週だけ移動」はデータ上どちらも `manual_week` で区別できないため、人が選ぶ。
  ※ここで固定訪問を**読む**のは「目印を付ける」ためだけ。写す内容は固定訪問に左右されない（決定 #3）。
- **写す元の週に無かった固定訪問を補う**（新規契約・その週に休んだ利用者）。初期値はオフ。オフのままだと次の週に入らない件数を明示する。
- **続けて自動スタッフ割当を実行する**。初期値はオン。

### 4-4. 写した訪問の `source`
`manual_week`（「この週だけの決定」）にする。理由: 週生成・固定枠戻しから守る既存の規則がそのまま効き、新しい値を足すと保護の一覧を全経路で直す必要があるため（`weekly-space-design.md` の「source を触らない方針」）。「コピーで作った」という出所は監査ログと保存したスナップショットに残す。

帰結:
- 写した後に「固定訪問から生成」を押しても、写した（患者・日）は上書きされない。
- 「固定枠に戻す」では消えない。元に戻すのは「コピー前に戻す」で行う。

### 4-5. 写す先に既に訪問がある場合
残す: 打刻のある訪問、`import`（カイポケ取込済み）、青ピン、取消行。それ以外（`auto`・`reset_v2`・`manual_week` など）は置き換える。残す訪問と同じ（患者・日・開始時刻）のものは写さない。置き換える件数・残す件数を確認画面に出す。打刻が 1 件でもある週は、置き換えではなく「空いている（患者・日）だけ足す」に切り替える。

### 4-6. 安全
- 実行前に写す先の週を `snapshot_week` で保存し、「コピー前に戻す」を出す（既存の「取り込み前に戻す」と同じ仕組み）。
- 1 トランザクション。週単位の排他（自動割当と同じロック）。
- 監査ログに、写す元・写す先・件数・選んだオプションを残す。
- カイポケへは送らない。写した週は●未送信として出る（送信は今までどおり連携画面から・明日以降の予定のみ）。

### 4-7. API
- `POST /api/v1/schedule/v2/copy-week/preview` `{ source_week_start, target_week_start }` → 写す訪問（曜日別の件数と一覧）、写さない件数の内訳、固定訪問に無い訪問の一覧、写す元に無かった固定訪問の一覧、写す先の既存訪問の扱い。DB は変えない。
- `POST /api/v1/schedule/v2/copy-week` `{ source_week_start, target_week_start, exclude_visit_ids, fill_from_fixed, assign_staff, confirm: true }` → 結果（作った件数・飛ばした件数と理由・スナップショット ID）。
- 戻すのは既存のスナップショット復元 API。
- 権限は admin。

## 5. あわせて直すもの
- 実施済み訪問のある週で「週を生成」すると 500 になる既知の不具合（`CourseDayTablePanel.tsx` のコメントに記載・原因未確認）。

## 6. 未決 → 解決（2026-10-01・モックのとおり）
1. 「固定訪問に無い訪問」の初期値 → **「写す」**。1 件ずつ・まとめて外せる。
2. 「写す元の週に無かった固定訪問を補う」 → **初期値はオフ**・選べる。オフのままだと入らない件数を出す。
3. 臨時コース（臨〜臨9）配下の訪問 → **コースなしで入れる**。
4. 祝日 → **警告だけ出す**（写す元の週・写す先の週の両方。祝日の判定は §8-6）。
5. 写す元の初期選択 → **直近の週**（祝日のあった週は一覧と選択時に警告）。

## 7. テスト（実装時）
写す対象と除外の各区分、担当が一切写らないこと、2 名体制の組み直し、止まっている患者の除外、写す先に打刻・取込・青ピンがある場合、スナップショットからの復元、固定訪問（PFV）が 1 行も変わらないこと、続けて自動割当した場合に 3 か所の担当が揃うこと、月跨ぎ週、排他。

## 8. 実装で確定した点（2026-10-01）

### 8-1. 置き場所
- API: `backend/app/api/v1/copy_week.py`（`/schedule/v2/copy-week/sources`・`/preview`・本体）。スキーマ: `backend/app/schemas/v2/copy_week.py`。本体の処理: `backend/app/services/scheduling/copy_week.py`（`build_copy_plan` を preview と実行が共有 = 表示と実行の件数がズレない）。
- 写す元の候補週は `GET /schedule/v2/copy-week/sources?target_week_start=` を足した（§4-2 の一覧用）。preview は `exclude_visit_ids` と `fill_from_fixed` も受け取り、選んだオプションどおりの件数を返す（確認画面はオプションを変えるたびに取り直す）。
- 画面: `frontend/components/schedule/v2/MakeWeekDialog.tsx`（3 段のダイアログ）・`frontend/lib/queries/copy_week.ts`。ツールバーの「週を生成」は「週を作る」になり、「固定訪問から生成」は今までの処理（訪問がある週の確認ダイアログを含む）をそのまま呼ぶ。画面上の案内文の「週を生成」も「週を作る」に揃えた。
- 対象は **週全体（全拠点）**。スナップショット・復元が週単位のため、拠点で絞った表示でも写すのは週全体（続けて行う自動割当も週全体）。

### 8-2. 写す・写さない（§4-3 の実装）
- 写す: 患者・日付（同じ曜日へ +N 週）・`start_time` / `end_time`（予定の時刻）・`type`・`required_staff_count`・`kaipoke_service_override`・2 名体制（旧 `visit_group_id` ごとに新しい ID）。`source='manual_week'`・`status='planned'`。
- 写さない: `status='cancelled'`／`is_unplanned`／特別訪問週間の追加分（`special_visit_marks` の `kind='extra'`・取消以外・`placed_visit_id` が写す元の訪問）／写す先の時点で非稼働の患者（`is_schedulable_status` = `active` 以外・削除済み。ステータスに効果日は無いので今のステータスで判定）／担当 4 種・VSA・`manual_staff_override`・メモ・`kaipoke_id`・青ピン・打刻・同行。
- 2 名体制は組で扱う。**組の誰か 1 人でも写せない（取消・予定外・止まっている患者・外した・同じ日に残す訪問がある等、理由を問わない）ときは組ごと写さない**（確認画面の内訳「2 名体制の相方を写さないため」・レビュー M-3）。利用者が 1 行外すと組ごと外れる（確認画面では組を 1 行にまとめる）。
- 「固定訪問に無い」目印: 写す元の週に効く mode（特別週なら special）の固定訪問に、その（患者・曜日）が無い訪問。固定訪問は読むだけ（テストで PFV 全列の前後一致を確認）。
- コースは 8-9 の規則で決める（置き場所は計画の段階で決めるので preview と実行が一致する）。週生成と同じく M コース・既定の同行・固定イベントを展開する。

### 8-3. 写す先の既存訪問（§4-5 の実装）
- 打刻が 1 件でもある週 = **足すだけ**（`mode='add_only'`）。既存は 1 件も消さず、写す先のその（患者・日）に訪問（取消を含む）が無いものだけ足す。
- 打刻の無い週 = **置き換え**（`mode='replace'`）。残す = 打刻あり・`in_progress`/`completed`・予定外・取消・`import`・青ピン・**今日より前の日**。それ以外を論理削除（週生成と同じ soft delete）。残す取消行と同じ（患者・日・開始時刻）の訪問は写さない（本番の部分 UNIQUE にも当たらない）。
- **打刻・取込・青ピン（＋実施中・実施済み・予定外）の訪問を残す（患者・日）には、開始時刻を問わずその日の訪問を写さない**（確認画面「同じ日に残す訪問があるため写さない N 件」・レビュー M-4）。取り込んだ週が二重にならないため。**§4-5 の字面（同じ開始時刻のものだけ写さない）からの意図的なずれ — PO 確認事項**。
- 今週を写す先にした場合、**今日より前の日へは写さず、その日の訪問も置き換えない**（過去日に「やっていない予定」を作らないため・確認画面に件数を出す）。
- 置き換えの週では、**残す訪問（取消以外）の無いコースはすべて**担当を外す（置き換えに触れたコースだけでなく週の全コース・M コースを含む・レビュー M-1。`assigned_staff_id=NULL`・`staff_assigned`→`course_fixed`）。前の担当が残ると、盤面（コース担当が正典）には担当が見えるのに写した訪問の primary / VSA は空、という 3 か所の不一致になるため。M コースのマネージャーは続けて自動割当すれば固定割当で戻る。
- 担当の決まっているコースへ入れる規則は 8-9。

### 8-4. 安全（§4-6 の実装）
- 実行前に `snapshot_week(kind='copy_week')`。保存の payload に `copy_mode`（replace / add_only）を足す。「コピー前に戻す」は既存の `POST /integrations/inbound-snapshots/{id}/restore` をそのまま使う。
- スケジュール画面のツールバーの「↩ 10/1 9:30 のコピー前に戻す」（いつのコピーかを出して押し間違いを減らす）は、次をすべて満たすときだけ出す（レビュー M-5）: その週の一番新しい保存がコピー直前／まだその保存へ戻していない／置き換えのコピー（足すだけは戻せない）／今の週に打刻が無い。後に取り込み等で保存が重なっていたら、連携画面の一覧から戻す（一覧では「週のコピー直前」「この時点へ戻したことがあります」と表示）。
- 「戻した」の記録は**最も小さい変更**として、復元のたびにその保存の payload に `restored_at` を書く方式にした（復元が自分の保存を取る方式は、5 世代の剪定で古い保存を押し出し、連携画面の一覧の意味も変えるため採らなかった）。「取り込み前に戻す」は今も保存を消さずに残し、同じ時点へ何度でも戻せる（挙動は不変・表示だけ増えた）。保存一覧 API は `restoredAt`・`copyMode`・週の `hasCheckins` を返す。
- スナップショットに `kaipoke_service_override` と `is_unplanned` も保存・復元するようにした（旧スナップショットは既定値で戻る）。復元の打刻ガードの文言は「保存した時点への復元はできません」に一般化。
- **打刻のある週（足すだけ）は復元の打刻ガードで戻せない。** 確認画面にその旨を出し、実行結果は `restorable=false`。
- 自動スタッフ割当と同じ週ロック（`_get_assign_staff_only_lock`）。実行中は 409。**「週を生成」（`generate-week-only`）も同じロックを取るようにした**（週の作り直しと割当・コピーが同じ週で重ならない）。
- 確認画面で見せた件数（写す・補う・置き換え・手で付ける）を実行時に送り、実行時に計画し直した件数と違えば結果に `differs_from_preview` を立てて両方を返す（止めはしない）。画面は「確認画面の件数と、実際に写した件数が違いました」と出す。
- 続けて自動割当が失敗したときはコピーも取り消し、`detail` が dict でも読める 1 行の文言にして返す（L-2）。
- 1 トランザクション。「続けて自動スタッフ割当」がオンなら、コピーを flush したまま `_assign_staff_only_impl` を呼び、割当の確定と同じ commit で確定する（割当が失敗したらコピーも残らない・エラー文に明記）。割当の結果（レビュー・お知らせ・警告）は「自動スタッフ割当」ボタンと同じ表示に渡す。
- 監査ログ `action='schedule_copy_week'`（写す元・写す先・件数・スキップ内訳・スナップショット ID・オプション）。`confirm: true` が無ければ 422。admin のみ。写す先は今週以降（JST）・写す元は写す先の 1〜8 週前・どちらも月曜。カイポケへは送らない。

### 8-5. 固定訪問から補う（任意）
- 補う訪問も 8-9 の置き場所の規則を通す（レビュー M-2・3 か所の不一致を作らない）。`source='auto'`。固定訪問と特別訪問週間の退避日はまとめて読む（L-6）。
- 写した後の週でその（患者・日）に訪問が 1 件も無い固定訪問（稼働中の患者・その週の mode・特別訪問週間の退避日と 2 名体制の片側欠けは除く・今日より前は除く）。作るのは週生成と同じ関数（`_expand_fixed_visits_to_visits`）で `source='auto'`。固定訪問は変えない。

### 8-6. 祝日
- アプリに祝日の仕組みが無かったので `backend/app/services/scheduling/jp_holidays.py` を足した（2020 年以降の現行ルール: 固定日・ハッピーマンデー・春分/秋分の近似式・振替休日・国民の休日）。警告にだけ使う。

### 8-7. あわせて直したもの: 「週を生成」の 500（§5）
- **原因**: 週生成は `source='auto'` かつ `status='planned'` の行だけを作り直す（`_delete_existing_auto_visits`）。QR 打刻で `in_progress` / `completed` になった `source='auto'` の行は消されずに残るが、INSERT 前の衝突判定（`_fetch_manual_conflict_keys`）は「auto 以外」か「cancelled」しか見ていなかった。そのため同じ（患者・日・開始時刻）の auto 行をもう一度 INSERT し、本番の部分 UNIQUE `uq_visits_pds_group_active` に当たって IntegrityError → 500。
- **修正**: 衝突判定を「auto 以外」または「`planned` 以外（source 不問）」に広げた（`layer1_expander.py`）。回帰テスト `backend/tests/test_generate_week_completed_regression.py`（本番と同じ部分 UNIQUE を張って `completed` / `in_progress` の両方で再現 → 修正後 200）。
- 残る気になる点: 打刻済みの訪問の時刻が固定訪問と違う日は、衝突キーが一致しないため週生成が同じ日にもう 1 件作る（500 にはならないが重複しうる）。今回は触っていない。

### 8-9. 写した訪問を入れるコース（レビュー H-1 / M-6 / M-2・2026-10-01 コーディネーター決定）
- 候補の順: (1) 写す元のコースと同じテンプレート（補う固定訪問は固定訪問のコース指定）、(2) 患者の拠点の既定テンプレート（週生成と同じ `Layer1Expander._resolve_template_for_patient`）。臨時コース（`TEMP_COURSE_CODES` を再利用）配下・コースなしの訪問は (2) から。候補のテンプレートで写す先の週の同じ曜日のコースを探し、無ければ週生成と同じ関数で作る。
- 候補のコースに担当が居なければ（置き換えで外す予定のコースを含む）そのまま入れる。自動割当がローテーションで付ける。
- 担当が居るコースへは、ほかの経路と同じ検査を通ったときだけ入れ、コース・primary・VSA（2 名体制は相方の担当を secondary）を揃える:
  - NG スタッフ・性別（`collect_constraint_warnings_for_staff` = 手動配置と同じ芯）
  - その担当の写す先の週の別の訪問（残す訪問・この実行で同じ担当に入れた訪問）と時間が重ならない
  - ローテーション: 写す元の訪問の担当（primary / secondary / VSA）と同じ人のコースには入れない（同じ利用者に同じ人が続かない）
- 2 名体制の相方と同じコースにはしない。どの候補にも入れられなければ**コースなし**で入れ、preview と結果の `needs_manual_staff`（理由つき）に数える。確認画面は「担当を手で付ける必要がある訪問 N 件」を理由つきで出す。
- 8-2 にあった「臨時コース配下はコースなしで入り自動割当で担当が付かない」は、この規則で既定コースへ入るようになり解消（手で付けるのは、上の検査で入れられなかったものと、既定コースの無い拠点の利用者だけ）。
