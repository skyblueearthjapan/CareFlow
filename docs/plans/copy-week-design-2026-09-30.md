# 前の週をコピーして週を作る — 設計（たたき台）

作成: 2026-09-30 ／ ステータス: **設計中**（方針は PO 決定済み。モックの確認待ち。実装は未着手）
見た目の正典: `docs/mockups/copy-week-mock.html`

## 0. 目的（PO 2026-09-30）

今は新しい週を「固定訪問（PFV）から生成」でしか作れない。実際に回した前の週（直近の近い週）を次の週へコピーできるようにする。流れ = 固定訪問で生成 → 職員スケジュールで任意に調整 → 次の週はその週からコピー。ねらいは**患者さんの予定（曜日と時刻）を一定にしていく**こと。

## 1. PO 決定（2026-09-30）

| # | 決定 |
|---|---|
| 1 | **写すのは患者の予定（曜日・開始時刻・長さ）。担当は写さない。** 同じ患者に同じスタッフが続くのは NG で、ローテーションが基本 |
| 2 | 写す時刻は**その週の予定として確定した時刻**（`visits.start_time` / `end_time`）。QR の実績時刻ではない |
| 3 | **固定訪問（マスタ）とは別に考える。** 週のコピーは固定訪問を読まない前提で動き、固定訪問へ書き込まない。固定訪問への反映は今までどおり別の操作 |

## 2. 本番の実測（読み取りのみ・2026-09-30）

- 前週と同じ患者・曜日 67〜79%／開始時刻まで同じ 18〜26%／30 分以内 38〜44%／担当も同じ 2 割前後。
- 同じ患者・同じ曜日で 9 月に 3 回以上訪問した 127 組のうち、毎回同じ時刻は 19 組（56 組は 3 通りの時刻）。今は時刻が週ごとに動いている。
- 9/28 の週 → 10/5 の週へ写す場合: 写す訪問 147 件（月 27・火 26・水 30・木 26・金 26・土 12）、取消 5・予定外 1 は写さない、止まっている患者の訪問 0、固定訪問に無い（患者・曜日）訪問 28、臨時コース配下 23、写す元に無かった固定訪問 30（うち 10 名は訪問が 1 件も無い）。
- 祝日のある週（9/21 の週）は、1 週前より 2 週前のほうが次の週に近かった → 写す元は選べるようにする。

## 3. 今の仕組み（調査結果の要点）

- 週を別の週へ写す機能は無い。土台として使えるのは取り込み前スナップショット（`backend/app/services/kaipoke/inbound_snapshot.py` の `snapshot_week` / `restore_snapshot`）。
- 「週を生成」= `POST /schedule/generate-week-only`（Layer1）。`source='auto'`・担当なしで作る。`manual_week`・`import`・青ピンの生存行がある（患者・日）は再生成を飛ばす。
- 担当は「自動スタッフ割当」（`POST /schedule/assign-staff-only`・Layer3）が付ける。過去 4 週の担当履歴を読み、同じ担当が続かないようにする。
- 担当はコース・`visits.primary_staff_id`・`visit_staff_assignments` の 3 か所を揃える必要がある（片方だけ書いてカイポケの担当が消えた事故あり）。
- 対象の週・月を取り違えた事故あり（2026-08-31）→ 対象の明示・強い確認・実行前の保全が要る。

## 4. 仕様（案）

### 4-1. 入口
スケジュール画面のツールバーの「週を生成」を「週を作る」にし、ダイアログで **固定訪問から生成**（今の動作）か **前の週をコピー** を選ぶ。

### 4-2. 写す元の週
過去 8 週のうち訪問がある週を一覧にする（訪問件数・利用者数・取消・予定外・QR の記録件数）。直近の週を初期選択。写す先は画面で開いている週（今週以降のみ）。

### 4-3. 写すもの・写さないもの

| 対象 | 扱い |
|---|---|
| 訪問の患者・曜日・開始/終了時刻 | **写す**（日付は同じ曜日へ +N 週） |
| 2 名体制（`visit_group_id`・`required_staff_count`） | 写す（ペアは新しい ID で組み直す） |
| サービス内容の上書き（`kaipoke_service_override`） | 写す（患者ごとの事情のため） |
| コース | 写す先の週の**同じテンプレートのコース**へ入れる（無ければ作る）。臨時コース配下の訪問は、コースなし（担当なし行）で入れ、自動割当に任せる |
| 担当（primary / secondary / mentor / VSA / コース担当 / `manual_staff_override`） | **写さない** |
| 取消した訪問・予定外の訪問・特別訪問週間の追加分 | 写さない |
| 止まっている患者（写す先の週の時点で非稼働）の訪問 | 写さない（件数を確認画面に出す） |
| 青ピン・メモ・`kaipoke_id`・打刻・実績の調整 | 写さない |
| 同行・イベント・休み | 写さない（同行とイベントは今までどおり既定から展開する） |

確認画面で選べるもの:
- **固定訪問に無い訪問**（その週だけ追加・曜日を動かした可能性）を一覧にし、まとめて／1 件ずつ外せる。初期値は「写す」。「今週だけ追加」と「今週だけ移動」はデータ上どちらも `manual_week` で区別できないため、人が選ぶ。
  ※ここで固定訪問を**読む**のは「目印を付ける」ためだけ。写す内容は固定訪問に左右されない（決定 #3）。
- **写す元の週に無かった固定訪問を補う**（新規契約・その週に休んだ利用者）。初期値はオフ。オフのままだと次の週に入らない件数を明示する。
- **続けて自動スタッフ割当を実行する**。初期値はオン。

### 4-4. 写した訪問の `source`
`manual_week`（「この週だけの決定」）にする。理由: 週生成・固定枠戻しから守る既存の規則がそのまま効き、新しい値を足すと保護の一覧を全経路で直す必要があるため（`weekly-space-design.md` の「source を触らない方針」）。「コピーで作った」という出所は監査ログと保存したスナップショットに残す。

帰結:
- 写した後に「固定訪問から生成」を押しても、写した（患者・日）は上書きされない。
- 「固定枠に戻す」では消えない。元に戻すのは「コピー前に戻す」で行う。

### 4-5. 写す先に既に訪問がある場合
残す: 打刻のある訪問、`import`（カイポケ取込済み）、青ピン、取消行。それ以外（`auto`・`reset_v2`・`manual_week` など）は置き換える。残す訪問と同じ（患者・日・開始時刻）のものは写さない。置き換える件数・残す件数を確認画面に出す。打刻が 1 件でもある週は、置き換えではなく「空いている（患者・日）だけ足す」に切り替える。

### 4-6. 安全
- 実行前に写す先の週を `snapshot_week` で保存し、「コピー前に戻す」を出す（既存の「取り込み前に戻す」と同じ仕組み）。
- 1 トランザクション。週単位の排他（自動割当と同じロック）。
- 監査ログに、写す元・写す先・件数・選んだオプションを残す。
- カイポケへは送らない。写した週は●未送信として出る（送信は今までどおり連携画面から・明日以降の予定のみ）。

### 4-7. API（案）
- `POST /api/v1/schedule/v2/copy-week/preview` `{ source_week_start, target_week_start }` → 写す訪問（曜日別の件数と一覧）、写さない件数の内訳、固定訪問に無い訪問の一覧、写す元に無かった固定訪問の一覧、写す先の既存訪問の扱い。DB は変えない。
- `POST /api/v1/schedule/v2/copy-week` `{ source_week_start, target_week_start, exclude_visit_ids, fill_from_fixed, assign_staff, confirm: true }` → 結果（作った件数・飛ばした件数と理由・スナップショット ID）。
- 戻すのは既存のスナップショット復元 API。
- 権限は admin。
