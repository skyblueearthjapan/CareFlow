# スタッフイベント履歴の整理と入力省力化 — 調査・設計書

作成: 2026-08-24 / ステータス: **PO確認済み (§3 全問回答あり)・実装待ち**

**設計原則 (PO 2026-08-24・Q5回答)**: 朝会をプログラムコード上で個別定義・特別扱いしない。
あくまで汎用の「イベント設定」(ひな形・固定イベント・一括登録UI) の一操作として実現できる
こと。朝会は**データ**であって**コード**ではない。

要望 (PO 2026-08-24):
1. スタッフマスターの「研修日 / イベント」一覧が増える一方 → **絞り込み・検索**
2. 過去イベントは資産 → **プルダウン連携で入力の手間削減**
3. 朝会 (毎日9:00〜9:15) など → **毎日/毎週の固定化** (休み・早出対応時は不参加)

## 1. 現状調査

### 1-a. 画面とデータの現状

| 資産 | 場所 | 現状 |
|---|---|---|
| イベント一覧カード | `staff/[id]/page.tsx` の `EventsCard` (「研修日 / イベント」) | **-30日〜+180日を古い順で全件羅列**。絞り込み・検索なし。limit 200 |
| イベント追加 (マスタ) | `EventAddDialog` (1名宛) | 日付/種別(イベント・研修)/タイトル/時刻/備考の手入力のみ |
| イベント追加 (スケジュール画面) | `TimelineEventAddDialog` (複数スタッフ一括)。職員スケジュールタブ・運転席タイムライン・週盤面の「＋イベント」は全てここに集約 (`CourseDayTablePanel` の `slotEventState`) | タイトルは毎回手入力。履歴の再利用なし |
| **毎週の固定イベント (既存!)** | `EventDefaultsCard` + `staff_event_defaults` テーブル + `expand_staff_event_defaults` (週生成3地点で冪等展開・source='fixed') | **機能は本番稼働済みだが登録0件 = 使われていない** (下記 1-c) |
| 今週だけ外す | `POST /events/{id}/cancel-week` (cancelled_at・行は消さない) | 運転席から利用可。固定イベントの週単位不参加の受け皿は既にある |
| BE 一覧 API | `GET /staff/{id}/events` | from/to (日付範囲) と limit のみ。**検索・source・並び順パラメータなし** |

### 1-b. 本番実データ (2026-08-24 時点・読み取り調査)

- 総数 **298件** (2026-07-20〜09-30・約10週分) → 増加ペース ~30件/週
- **「朝会」が196件 (66%)**。source 内訳 = manual 127 + kaipoke取込 69。**毎回手入力 or カイポケから取込されている** = 要望3の動機そのもの
- 「休み」30件・「カンファレンス」10件・残りはロングテール:
  「面談 松岡」「新規契約：〇〇様(住所)」「△△様 担当者会議 □□中学校」「研修：…(Zoom)」「打合せ：川名」など
- **患者名はタイトル内の自由テキスト**。patients への FK は無い (=「患者さん別」は完全な構造化フィルタにはできない → テキスト検索でカバーするのが現実的)
- cancelled/blocking 該当行は現状 0件

### 1-c. 固定イベント機能が使われていない理由 (推定)

現 UI は **1回の登録 = スタッフ1名 × 曜日1つ**。朝会 (全員・月〜土) を登録するには
**7名 × 6曜日 = 42回** の操作が必要で実用に耐えない。「毎日」ショートカットも
複数スタッフ一括も無い。→ 要望3は「新機能」ではなく **既存機能の実用化** が本質。

### 1-d. 既存の設計制約 (今回の設計が守るべきもの)

- 固定イベントは送信すると **source='fixed'→'kaipoke' へ昇格** (二重化なし)。展開の冪等判定は
  外部キー+内容一致の2段 (`staff_event_defaults.py` docstring) — 今回の変更でここは触らない
- 展開は **休み(staff_off/overrides)を見ていない**。不参加の受け皿は cancel-week のみ
- イベント運用の家 = 職員スケジュールタブ (kaipoke-event-two-way-design.md)

## 2. 設計案

### Phase 1: イベント一覧の絞り込み・検索 (要望1)

**EventsCard を「既定=これから・検索できる」カードに変える。**

FE (EventsCard):
- **期間タブ**: `今後` (既定・今日→+180日・近い順) / `今週` / `過去` (新しい順・遡り) / `すべて`
- **テキスト検索**: タイトル+備考の部分一致 (300ms デバウンス)。患者名・「会議」「面談」などはこれで拾う =「患者さん別」「用事・会議別」の実装形
- **種類チップ (トグル)**: `定例を隠す` (朝会など固定イベント既定のタイトル群 + source='fixed' を除外 — 実データの66%がノイズ化している対策) / `カイポケ取込` / `手動` / `研修のみ`
- 件数表示 (「〇件 / 絞り込み中」) と 0件時の解除リンク

BE (`GET /staff/{id}/events` 拡張・後方互換):
- `q` (title/note ILIKE・部分一致) / `source` / `order=asc|desc` / `offset` を追加
- 現状298件なら FE 絞り込みでも動くが、limit 200 で「過去」が切れ始めているため BE 対応が正

構造化「患者さん別」は今回見送り (FK が無い)。将来、患者画面からイベントを作る導線を
作る時に `patient_id` 列を足すのが正道 (§4 バックログ)。

### Phase 2: イベントひな形 (プルダウン連携・要望2)

**新テーブル `event_templates` (共通+個人の両対応・PO決定 Q1):**

```
id UUID PK
staff_id UUID NULL FK staff  -- NULL=事業所共通 / 値あり=そのスタッフ個人のひな形
title String(255) / event_type ('event'|'training')
start_time, end_time Time NULL (NULL=時間はその場で入力)
blocking bool default false / note Text NULL
sort_order int / is_active bool default true
```

- **登録経路 3つ**:
  1. 管理カード — 共通ひな形は**スタッフ一覧ページ上部** (PO決定 Q2)、
     個人ひな形はスタッフ詳細ページのカード。追加・並べ替え・無効化
  2. **履歴から追加**: 過去イベントをタイトルで集約 (回数付き・定例は除外) して
     ワンクリックでひな形化 — 「過去のイベント履歴は資産」の実装形
  3. イベント追加ダイアログ内の「☆この内容をひな形に保存」チェック
     (保存先: 共通 / このスタッフの個人 を選択)
- **利用**: `TimelineEventAddDialog` / `EventAddDialog` の最上部に
  「ひな形から選ぶ」プルダウン → 選ぶとタイトル/種別/時刻/blocking/備考が埋まる
  (その後の手直しは自由・保存はこれまで通り staff_events へ)。
  プルダウンは「共通」セクション + 「個人」セクション (対象スタッフのもの。
  複数スタッフ選択時は選択中スタッフの個人ひな形を名前付きで表示)

### Phase 3: 固定イベントの実用化 (要望3)

スキーマは現行 `staff_event_defaults` (スタッフ×曜日の行) のまま。**登録UIと連携を強化**:

- **曜日の複数選択 + ショートカット**: `毎日(月〜土)` / `月〜金` / 個別チェック
  → 選択曜日ぶんの行を一括作成 (展開・冪等キーは無変更)
- **複数スタッフ一括登録**: 新 API `POST /staff-event-defaults/bulk`
  (staff_ids × weekdays × 時刻 × タイトル × blocking を 1TX で upsert・既存重複は skip)。
  入口はスタッフ一覧 or 職員スケジュールタブの「固定イベントを一括登録」。
  補助として「週間シフトで 9:00 出勤の全員を選択」ボタン (朝会ユースケース直撃)
- **過去イベントから固定化**: EventsCard の行メニュー「毎週固定にする…」→
  タイトル/時刻を引き継いで固定化ダイアログへ
- **スケジュール画面のイベント追加モーダル内**: 「☆ひな形に保存」に加えて
  「📌毎週固定にする (選択スタッフ全員)」チェック → 保存時に defaults も作成
- **休み連携 (不参加の自動化)**:
  1. 展開時、その日に staff_off / 休みoverride が既にあるスタッフは **展開 skip**
  2. 運転席の「休みにする」(staff-off-week) 適用時、その日の当該スタッフの
     固定イベント (source='fixed') に **cancelled_at を自動付与** (undo は op_group で戻す)
  3. 「早めに患者対応が入る」ケースは従来どおり手動の「今週だけ外す」(既存機能)

朝会の初期投入: 機能完成後、**汎用の一括登録UIを画面から操作して**全 active スタッフ ×
月〜土 × 9:00-9:15 を登録する (PO決定 Q5: コードやスクリプトで朝会を個別定義しない。
一括登録UIで他のどのイベントでも同じ操作ができることが条件)。以後は取込側と二重に
ならない (展開の内容一致判定が吸収) が、初週は突合で確認する。

## 3. PO 確認事項 → **全問回答済み (2026-08-24)**

- **Q1**: ひな形の単位 → **共通+個人の両方** (event_templates.staff_id NULL=共通)
- **Q2**: ひな形管理カードの置き場所 → **スタッフ一覧ページ上部** (個人ひな形は
  スタッフ詳細ページ)
- **Q3**: 休み日の固定イベント → **自動で不参加** (展開skip + 休み操作で取消印。
  手動の「今週だけ外す」は例外用に残る)
- **Q4**: 一覧の既定表示 → **「今後 (近い順)」**
- **Q5**: 朝会の初期一括投入 → **可。ただし朝会をコード上で特別扱いしないこと** —
  汎用のイベント設定 (一括登録UI) の一操作として行えることが条件。ハードコード・
  専用スクリプトでの投入は不可 (冒頭の設計原則参照)

## 4. バックログ (今回スコープ外)

- `staff_events.patient_id` (患者画面からのイベント作成導線とセットで) → 真の「患者さん別」
- イベントのカテゴリタグ列 (会議/面談/新規契約/患者対応… タイトル接頭辞の正規化)
- 固定イベントの「隔週」「毎月第N曜」対応 (現要望は毎日/毎週のみ)
