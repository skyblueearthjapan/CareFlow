## 0. なぜこの検討書か

モックは「見た目」としてPO承認済み。だが**本番に落とすと"似つかわしくない"**という懸念。
その正体を2つの徹底調査（①週ビュー/リストの機能実態 ②デザインシステム適合）で特定し、
**モックの理想を、本番の全機能と意匠に矛盾なく載せる**ための翻訳表と実装方針をまとめる。

---

## 1. 判明した「浮く原因」= 3つのギャップ

### G-1. ツールバー構造が違う（最大のギャップ）
- **モック**: 「期間[日｜週] × 見え方[タイムライン｜リスト]」の2軸トグル
- **本番**: 「**曜日タブ（月 火 水 木 金 土 週）**」＋「表示モード[タイムライン｜リスト｜テーブル]」
  （`CourseDayTablePanel.tsx:2384` の週タブ・`:2413` のモード切替）
- つまり本番では「週」は**タブの1つ**であり、日と対等な period トグルではない
- → **モックの2軸UIをそのまま持ち込むと既存操作体系と衝突**。本番の曜日タブ構造を尊重して載せる

### G-2. デザインの"使い方ルール"が違う（色そのものは同じ）
本番トークンは "Warm & Human"、ブランド=同じティール #0d9488、クリーム #faf7f2、
セリフ(Noto Serif JP) も実在。**思想は一致**。ズレるのは使い方:
| モックの流儀 | 本番の鉄則 | 翻訳 |
|---|---|---|
| カード地色 = クリーム | **カードは白地** `bg-bg-base`（クリームは"外側の地"専用） | 白地に |
| ティール = ベタ塗り・高彩度 | **薄塗り** `/5〜/10` + ティール文字 + `/40` ボーダー | 薄塗りに |
| セリフを見出しに多用 | セリフは**見出しだけ**、本文/チップ/極小は sans | 現状T-1は正しくsans |
| 影・丸み | `--shadow-xs/sm/md`・`rounded-lg`(16) | T-1は既に適合 |
| アクセント暖色 | `--brand-accent` #d97706・警告amber（空き枠と統一） | 統一 |

### G-3. T-1タイムラインの実バグ（"浮く"体感の一因・**本検討書で修正済み**）
- `bg-bg-surface`（未定義クラス）→ 列ヘッダ・空状態の地色が塗られていなかった → `bg-bg-muted` に修正
- `text-status-mismatch`（未定義）→ 満員の赤字が効いていなかった → `text-warning` に修正
- `--now`（未定義・フォールバック依存）→ tokens に `--sched-now` を正式追加

## 2. モックの各要素 → 本番の対応（機能を1つも失わないための対照表）

| モック要素 | 本番のデータ源（実在） | 絡む機能（失えない） | 落とし込み |
|---|---|---|---|
| 日: 列=コース + 担当アバター | `visitsByCourse`(CourseGridVisit) + `assignedStaff` | 担当変更(PATCH courses)・容量/開講(effectiveCapacity) | ✅ T-1で実装済み |
| 性別色(カード=患者/アバター=スタッフ) | `patient.sex`/`staff.sex`(本番実データ) | — | ✅ 実装済み。**明度を上げ薄塗りへ寄せる**（G-2） |
| 空き枠「＋n分空き」 | `freeGapsByCourse`(computeFreeGaps・容量ゲート) | 満員時は非表示(remaining>0) | ✅ 実装済み（同ロジック共有） |
| 会議イベント帯(カイポケ反映外) | `staffEventsByStaff` | イベント衝突警告 | ✅ 表示済み。T-2で登録動線 |
| 週: 列=曜日(コース選択) | 週ビューの `cellMap`/`freeGapsByCell`・`weekVisits` | **下記の週固有価値を全部移植** | ⬜ **T-3で新規** |
| 詳細ホバー | patient/visit詳細 | 患者詳細ダイアログ(既存) | ⬜ ホバーは新規・クリックは既存流用 |
| リスト | `WeekdayScheduleCard`(共有コア) | **下記のリスト固有情報を保持** | ✅ 既存を残す |

### 2-a. 週ビューが持つ「固有の価値」= 週タイムラインに必ず移植する項目
（`CourseWeekOverview.tsx` 調査より。これを落とすと機能後退）
1. 曜日ヘッダーの**受入可能数集計**（出勤スタッフ×6）＋拠点別 S/M 数
2. **開講判定**（effectiveCapacity で曜日別に「休」）→ 休講の曜日/コースは明示
3. **拠点横断**（全拠点コースを1画面に）
4. セル内: 担当名(性別色)・容量バッジ・コース合計距離・残枠・空き枠・同住所ペア囲み・ピン
5. 操作: 曜日ヘッダクリック→その曜日へジャンプ / 患者クリック→詳細 / ピントグル(scope 2択)

→ **設計判断**: 週タイムラインは「曜日=列・時間=縦・1コース選択」が基本形。ただし上記
①②③（全コース・全拠点の俯瞰と開講/容量集計）は1コースの縦タイムラインだけでは出せない。
**週は「タイムライン(1コースの深掘り)」と「一覧(全コース俯瞰=現週ビュー相当)」の2枚を持つ**か、
あるいは週タイムラインのヘッダに集計を畳み込む。要PO判断（§4-Q2）。

### 2-b. リストが持つ「固有情報」= 残す理由（タイムラインに無い）
（`WeekdayScheduleCard.tsx` 調査より）
- **実動時間**（⏱ 分）・**住所詳細**・**area_label**・**個別条件バッジ**（時間帯/固定/午前…）
- **移動警告の赤枠+tooltip**（travel_time_shortage）・**次目的地距離**(VisitArrow)
- **overflow「他N件」**・**Before/After 2ペイン**（プール一括投入で使用）
→ リストは**精読と提案系の共有コア**。撤去不可。タイムラインと**役割分担で共存**が正。
- 注意: `WeekdayScheduleCard` は `BulkPoolInsertDialog` も使う共有コア。**signature 変更は4〜5画面波及**。触るなら慎重に

## 3. 適合方針（本番の全機能を保ったままモックの体験を出す）

### 方針A. ツールバーは本番構造を尊重（モックの2軸UIは持ち込まない）
- 曜日タブ（月〜土＋週）は**そのまま**。表示モードは現状の3択
  `[タイムライン｜リスト｜テーブル]` を維持（既定=テーブル据置）
- 週タブ選択時のモード切替は現状「非表示」→ **週も[タイムライン｜一覧]の2択に拡張**（§4-Q2次第）
- モックの「コース選択ドロップダウン」は、**週タブ×タイムライン時のみ**ツールバー右にインライン
  表示（縦スペースを消費しない・PO指摘を反映）

### 方針B. 意匠は「本番トークンへ翻訳」して馴染ませる（§1 G-2の表を適用）
- タイムラインカード: **白地は使わず性別色**だが、**明度を上げて薄塗り化**し周囲(テーブル/リスト)の
  `/5〜/10` トーンに寄せる。中立色は現状クリーム系(#f4f1ea)で既に地に馴染む
- 見出し(コース名など)は `font-serif`、本文/氏名/時刻/ピルは `font-sans`（現状維持）
- 影 `shadow-xs/sm`・角丸 `rounded-lg`・アクセントは amber（空き枠・今週のみと統一）

### 方針C. 週タイムラインは既存週ビューのデータを流用（新規ソルバゼロ）
- `freeGapsByCell`・`cellMap`・容量集計は既に Panel にある → タイムライン用に整形するだけ
- API/ソルバ不変（T-1と同じ表示層だけの追加）

### 方針D. リストは意匠だけモックの言語に微調整して残す
- 情報・機能は一切削らない。行の色・余白・ピルをタイムラインと**同じ視覚言語**に寄せ、
  「タイムラインと兄弟に見えるリスト」にする（配置は違ってよい＝精読の相棒）

## 4. PO 確認事項（実装順を決める前に）

1. **意匠翻訳の方向**: モックの「クリーム地カード・ベタ塗りティール」を、本番鉄則の
   「白地・薄塗り」へ翻訳して馴染ませる方針でよいか（色思想は同じ・使い方だけ本番に合わせる）
2. **週タイムラインの形**（重要）: 週は
   - (a) 「週タイムライン(1コースを曜日列で深掘り)」＋「週一覧(現週ビュー=全コース俯瞰)」の**2枚**
   - (b) 週タイムライン1枚に集計ヘッダを畳み込み、現週ビューは撤去
   のどちらにするか。**現週ビューの"全コース・全拠点の受入可能数俯瞰"を残すなら(a)が安全**
3. **T-1タイムラインの意匠微修正**（性別色を薄塗りへ・G-3バグ修正済み）を**先に1本デプロイ**して
   実機で"馴染み"を確認してから週タイムライン(T-3)に進む、という順でよいか
4. **既定表示**: 当面テーブル据置のままか、意匠が馴染んだ段階でタイムラインを既定にするか
