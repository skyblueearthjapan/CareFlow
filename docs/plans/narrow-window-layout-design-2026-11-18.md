# 狭い窓でも崩れない らく助（Mac の見え方の手当て）— 設計

作成: 2026-11-18 / ステータス: **PO の了承待ち**（方向は PO 決定 2026-11-18「1 つの画面のまま広さに合わせる」）

## 0. 背景
- 事業所の Mac で、スケジュールの患者名が「…」になる・消えると聞いていた。PO が Mac mini（macOS 27・1920×1080・Safari）を用意し、11-18 に Windows と見比べた。
- 比べの資料: `docs/reports/agent/mac-ui-compare-2026-11-18/mac-windows-hikaku-2026-11-18.html`（git 対象外・名前入り）。前の Mac 対応: `mac-ui-crossplatform-design.md`（08-29・書体の統一・サイドバー自動で畳む）。

## 1. 分かったこと
- 原因は OS・書体ではなく **らく助に使える広さ**。Windows は Chrome のアプリで 75% 表示（約 2050×1250）、Mac の Safari はいつもの窓で 100%（約 1324×840・面積 約 43%）。Mac を画面いっぱい＋コンパクト表示にすると Windows と同じく読める。書体はどちらも Noto Sans JP。Safari だけの崩れは見つからない。
- よって Windows でも窓を狭く・100% 表示にすれば同じ崩れが出るはず（実装前に Windows で再現して確かめる）。

## 2. 直すところ（画面だけ・API と DB は変えない）
| # | 場所 | いま | 直し方 |
|---|---|---|---|
| A | コースの週の表 `components/schedule/v2/CourseWeekOverview.tsx` | 曜日の列が `minmax(120px,1fr)` まで縮む。「n 名 / 上限 N」に折り返し止めが無く、1 文字ずつ縦に並ぶ。訪問は「09:30 …」で名前が消える | 列の最小幅を 120 → **176**（訪問 1 行に「時刻・姓 名」が入る幅）。狭いときは縮めずに横に送る（職員の週の表と同じ）。札は `whitespace-nowrap`、距離と「残N枠」は入らなければ次の行へ回す（`flex-wrap`） |
| B | 上の段（見出し・道具の段・案内の帯） `CourseDayTablePanel.tsx` / `lib/stores/ui.ts` | 「コンパクト表示」と「わかった」は機械ごとの設定。初めての機械では出たままで、縦が狭いと表がほぼ見えない | 画面の縦が **900 未満の初回表示ではコンパクト表示にする**（前のサイドバー自動で畳むと同じ形：1 度だけ・利用者が切り替えた後はそれを守る） |
| C | 保留プール（右の欄） | 狭い窓でも幅 248〜320 を取る | 欄の見出しに［畳む］を付け、畳んだら細い帯にする（機械ごとに覚える）。窓の幅 1400 未満の初回は畳んでおく |
| D | タイムラインの短い予定（15 分の朝会など） | Windows でも「09:…」「…」 | 幅が足りないときは時刻を省き、名前（または予定の名前）を先に出す。時刻はマウスを載せたときの説明に残す |
| E | 患者マスタの見出し `app/(app)/patients/page.tsx` | 「患者マ／スタ」と 2 行に折れる | 見出しは折り返さない。ボタンの列のほうを折り返す。スタッフ・ほかの一覧の見出しも同じ形か確かめる |

- OS で分ける処理は入れない（どの機械でも同じ規則）。Windows の見た目は、広い画面では変わらない（A〜E は狭いときだけ効く）。

## 3. 確かめ方
- Windows の Chrome で、窓を 1324×940・100% にして、直す前に崩れが出ることを写真で確かめる（Mac がなくても再現できるかの確認）。
- 直した後、Mac mini の Safari（いつもの窓・画面いっぱい）と Windows（いつもの 75%・100% の狭い窓）で、スケジュールの 8 通り（コース／職員 × 週／1 日 × リスト／タイムライン）と患者・スタッフを撮って比べる。撮り方はメモリ `careflow-mac-mini-ui-compare`。
- frontend の試験（関係する vitest）・tsc・lint。レビュー役を別に立てる。

## 4. リスク
- B・C は「初回だけ」なので、すでに使っている Windows の見た目は変わらない。事業所の Mac は次に開いたときに畳まれた状態になる（戻すボタンはそのまま）。
- A は狭い窓で横に送る量が増える（崩れて読めないよりは良い、という判断）。

## 5. 確かめること
- A の最小幅 176 は、今の訪問 1 行（時刻 5 字＋姓名 4〜6 字＋距離）からの見込み。Windows で再現したときに決め直す。
- 事業所の Mac が Mac mini と同じ画面か（ノートの Mac ならさらに狭い）。
