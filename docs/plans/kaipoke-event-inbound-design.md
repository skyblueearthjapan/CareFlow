## 0. PO確定事項（2026-07-25 相談で確定）

1. **目的 = 週のバトンリレーの「イベント版」**。固定スケジュールは毎週 楽スケ→カイポケへ送る。
   提供中の週に発生する修正（イベント含む）はカイポケへ直接入力される。週末にカイポケの
   最終形（実際に行った予定）を楽スケへ取り込み、**その週の確定記録**として揃える
2. カイポケUIの**緑色の予定 = カイポケ「個別業務」機能**（面談/会議/休み/営業/受診同行など、
   利用者に紐づかない職員単位の予定）
3. **「休み」もそのまま純粋に取り込む**（最終確定スケジュールなので特別扱いしない）
4. **メモ系（開始=終了、例 00:00〜00:00「渡辺様：COCOLO3号館」）も含める**
5. **日曜分は不要**（楽スケは月〜土運用。スキップして良い）
6. 取得は**楽スケ側で日付を指定して手動実行**（自動取り込みしない）
7. 方向は**カイポケ→楽スケの一方向**。楽スケからイベントをカイポケへ送ることはしない
8. 患者訪問の移動（コース跨ぎ）は**既存の訪問取り込み（R-3）が吸収済み**のため本件のスコープ外
   （コース丸ごと交代/コース移動/臨時コース新設の3段構え。スタッフ別枠モデルへの転換は不要）

## 1. 調査で確定した事実（2026-07-25 本番プローブ・再調査不要）

1. **スケジュール表CSV（現行 export 経路）に個別業務は構造的に含まれない**。
   出力条件設定は「サービス提供年月・予定/実績区分・割当職員情報」の3項目のみで
   イベント包含オプションは存在しない。実CSV 529行=全行「医療保険」で実証
2. **取得可能な場所 = 職員スケジュール画面** `https://r.kaipoke.biz/bizhnc/staffSchedule/`
   （よりより着地直後の週間表示画面。PO案内の手順どおり）
   - `select[name=staffSelected]` 既定「よりより てすと」→ **「－」選択で全職員グリッド**
   - `input[name=currentDate]`（例 2026/07/25）で表示週を変更可能 → 対象週の月曜を設定すれば
     その週7日分が1画面で取れる
   - **個別業務は `a.btnIndividual` クラスで機械的に識別可能**（色に依存しない）。
     text=「HH:MM～HH:MM タイトル」、行=職員名、列=日付。
     onclick=`showIndividualEdit(yyyymm, '区分', <個別業務ID>, <日>, <職員内部ID>)`。
     行の `<tr staff-id="...">` にカイポケ職員内部IDあり
   - **★E-0実測（2026-07-25・重要）: 個別業務IDは単独では冪等キーにならない**。
     週パターン由来の予定は複数日で同一IDを共有する（実測: 宇田川 7/25・7/28 の
     休みが同一ID 690499216）。冪等キーは**複合 `{個別業務ID}:{職員内部ID}:{日付}`**
     （フィクスチャ23件で一意性を検証済み）
   - 患者訪問（青）は別系統（`showHNC097807Edit`）で確実に区別できる
   - 実証: 2026-07-25週で スクショと1対1一致の18件（面談9/休み9/会議2/契約2 ほか）を抽出済み
3. 月間側でも取得可（`monthlyShiftsList` 職員別タブ・`icon-individual`「個」バッジ）だが、
   職員ドロップダウン+ページネーション巡回が必要なため**週間画面を採用**
4. 楽スケ側の受け皿 = `staff_events`（イベント帯）。Layer3 は当該週の StaffEvent を
   ハード制約（INF）として尊重済み（W27 Phase A）。**開始=終了のゼロ長イベントは
   重複判定 `starts < e_end and ends > e_start` で自然に無害**（割当に影響しない）
5. RPA資産: `setup_yoriyori_page`（lib/common）で着地画面=職員スケジュールへそのまま到達。
   時刻レンジ・タイトルのパースは innerText で成立（プローブ実証済み）

## 2. データモデル（migration 0062）

`staff_events` に2列追加:

| 列 | 型 | 内容 |
|---|---|---|
| `source` | String(16) NOT NULL DEFAULT `'manual'` | `'manual'`（手動登録・既存全行）/ `'kaipoke'`（本取り込み由来） |
| `external_id` | String(40) NULL | 複合キー `{個別業務ID}:{職員内部ID}:{YYYY-MM-DD}`（source='kaipoke' のとき必須。E-0実測で個別業務ID単独は週パターン由来予定で重複するため複合とする） |

- 部分ユニーク索引: `UNIQUE (source, external_id) WHERE external_id IS NOT NULL`
  → 再取り込みの冪等 upsert キー
- **手動イベント（source='manual'）には取り込みは一切触れない**
  （訪問取り込みの「ラウンドトリップ汚染防止」と同じ原則。同行 `trainee_accompaniments` の教訓を踏襲）
- `event_type` は既存 canon の `'event'` 固定で保存（タイトルが意味を運ぶ。
  FE 表示は既存どおり「イベント」に collapse される）。「休み」も event_type='event'
  + title='休み'（特別扱いしない=PO確定）
- メモ系 = `starts_at == ends_at` で保存（§5 で表示のみ特別扱い）

## 3. RPA（kaipoke-api / PlaywrightTest1）新オペレーション

`POST /api/individual-tasks`（Bearer 必須・同期 ~60s・単一スロット準拠）

- payload: `{ "date": "YYYY-MM-DD"（対象週の月曜）, "credentials": {...}（任意・現行と同じ） }`
- フロー: ログイン → 職員スケジュール（着地画面）→ `staffSelected`=「－」→
  `currentDate`=date 設定+再表示 → ヘッダ行から列⇔日付対応を構築 →
  `a.btnIndividual` を全行走査
- 返却: `{ ok, week_start, tasks: [ { staff_kaipoke_id, staff_name, date, start, end,
  title, kaipoke_task_id, external_key } ] }`
  - `start == end` のメモ系もそのまま返す
  - **日曜も含めて返す**（RPA は絞らない。フィルタは CareFlow 側の責務 = ダム維持）
  - external_key = `{個別業務ID}:{職員内部ID}:{日付}`（§2 の冪等キー）。
    onclick から抽出不能な行は null で返し要確認へ
  - パーサは onclick 引数の day と列日付の一致を検証（不一致は fail-fast・
    無言のズレ取り込みを防ぐ）。E-0 でフィクスチャテスト9件作成済み
    （23件全抽出・キー一意性・スクショ突合・訪問混入なし・全角空白名寄せ互換）
- 既存 export と同じく結果ストア/ログ/ステータスに載せる（op名 `individual_tasks`）

## 4. バックエンド（CareFlow）

### 4-1. プレビュー `POST /integrations/events-inbound-preview`（admin）

1. **取り込みゲート = 訪問取り込みと同一**（対象週に dry_run=false の実 apply 記録が必要。
   `real_apply_record` 流用）※「バトンが渡った週だけ追いかける」の一貫性。§7-1 参照
2. RPA `/api/individual-tasks` 呼び出し（週の月曜を渡す）
3. フィルタ: 日曜分を除外（PO確定）
4. スタッフ名寄せ: `load_staff_name_index`（訪問取り込みと同一機構）。
   未解決（楽スケに居ない職員: 例 菅野/佐藤氏ら）→ `unmatched` として一覧返却・適用対象外
5. 差分計算（対象週の `staff_events` source='kaipoke' と突合・キー=external_id）:
   - カイポケにあり楽スケに無い → **add**
   - 両方にあり時刻/タイトル/職員が異なる → **update**
   - 楽スケ（source='kaipoke'）にあり カイポケに無い → **delete**（カイポケで消された）
6. 返却: `{ weekStart, eligible, adds[], updates[], deletes[], unmatched[], memoCount }`
   （書込なし・シート永続化はしない=イベントは軽量なので都度計算。§7-2）

### 4-2. 適用 `POST /integrations/events-inbound-apply`（admin）

- payload: `{ weekStart, dryRun=true }`（プレビュー結果の再計算→適用。曜日絞りは不要=週丸ごと。
  将来必要なら days を足す）
- add=INSERT / update=UPDATE / delete=物理DELETE（source='kaipoke' の行のみ・履歴は
  KaipokeJob 結果に残る）。**manual 行には決して触れない**
- KaipokeJob（op=`import_events`）で監査記録・失敗時は admin/manager 通知
  （`_create_idempotent` 流用）
- 冪等: 同週再実行は差分ゼロに収束。二重適用の害なし（upsert キー=external_id）

## 7. 設計判断・リスク（レビュー観点）

1. **ゲート改訂（2026-07-26・PO確定）**: カイポケは請求と紐づく最終的な「正」であり、
   提供が始まる週は必ずカイポケに入力されている（④反映の有無は無関係）とのPO判断で、
   ゲートを「apply実績」から**時間ベース**へ改訂:
   `取り込み可 = 週開始(月曜) <= 今日(JST) or 実apply記録あり`（訪問・イベント共通・
   `inbound_week_eligible`）。未来週だけ実apply記録を要求するのは、らく助が計画中で
   カイポケ未入力の週を取り込むと計画訪問が全てキャンセル候補になる「週全滅事故」の防止。
   セットで FE に**大量キャンセル警告**（キャンセル候補 >= 10 件で赤警告+曜日自動選択の
   停止 = `MASS_CANCEL_THRESHOLD`）を追加し二段構えとした
2. **シート永続化なし**: 訪問取り込みは CorrectionSheet に永続化するが、イベントは
   軽量・低リスク（staff_events のみ・manual 不可侵）のため都度計算+即適用とする。
   監査は KaipokeJob 結果で担保
3. **DOM 変更耐性**: `btnIndividual` クラス名・onclick 形式に依存。カイポケの画面改修で
   壊れ得る（現行 RPA 全般と同じ性質）。パーサは「0件時に画面テキストを添えて failed」
   にして無言の空振りを防ぐ
4. **勤務予定（シフト）との関係**: 「休み」はイベントとして入るだけで、楽スケの
   staff_shifts / 週間上書きは変更しない（Layer3 はイベント時間帯を避けるので実害なし）。
   シフト側との二重管理は将来課題として明記
5. 楽スケ未登録職員の予定は取り込まれない（unmatched 表示のみ）。必要になったら
   スタッフマスタ登録で自然に対象化（マスタ駆動の原則）
6. RPA 単一スロット: 取得は export と同格の占有 (~60s)。取り込みカードの実行中表示は
   既存のジョブ監視に載せる

## 7-b. 置換取り込みモード + 差分モード根治（2026-07-26 追補・PO確定）

7/20週の初回 dry-run で「一度も同期していない週」の差分モードの限界が露呈
（キャンセル63/失敗15 — 氏名の空白違いによる偽 delete+add ペア・同時刻衝突・
新人担当1）。POの明言「カイポケは請求と紐づく最終的な正。らく助側がそれを
受け入れる。取り込み時はらく助の週を白紙にしてカイポケを移すイメージ」を受け、
**2本立て**とした:

1. **置換取り込みモード（新規・`POST /integrations/replace-inbound`）**
   - 対象週 (月〜土) のらく助訪問を全 soft delete → カイポケ現況CSVの行を全挿入
     （患者/スタッフ名寄せ・スタッフのその日のコースへ配置・無ければ臨時コース）。
     突合が無いため名寄せ差・同時刻衝突が構造的に発生しない。必ずカイポケの
     完全コピーに収束（冪等）
   - 安全装置: ゲート共有 / **実績(打刻)ガード**（1件でもあれば422 → 差分モードへ誘導。
     打刻・写真・レビューの紐付け先を消さない）/ 空CSV拒否（週全滅の安全弁）/
     dry-run 既定 / 白紙化+挿入は単一トランザクション / 確認ダイアログに
     **「らく助側のこの週の情報はすべて削除される可能性がございます」を明記（PO指示）**
   - **月跨ぎ週対応**: export は月単位のため、週が月を跨ぐ場合は両月を取得し
     日を月別に絞って結合（`export_current_week_csv`）。7/1 の行が 8/1 週に
     誤混入しない
   - 名寄せ不可・新人担当1は skipped として一覧可視化（挿入されない = らく助の
     週から抜ける。新人フラグの実態確認は PO 判断）
2. **差分モードの根治（実績週の主力）**
   - **氏名の空白正規化**: `_compare_entries(normalize_names=True)`（inbound のみ）。
     NFKC+空白除去キーで同一人物に束ね、偽 delete+add ペアを根絶。outbound は
     RPA の画面行特定に原名が要るため不変
   - **キャンセル枠の復活**: add 先の同時刻に「同じ患者のキャンセル済み訪問」
     （本実行でキャンセルされる分も pending_cancelled で予測）がいれば INSERT
     せずその行を復活・上書き。delete+add ペアが安全に収束し、dry-run と実適用の
     結果が一致する
   - **適用順序の明示ソート**: キャンセル/変更 → 追加（従来はシート挿入順依存）
- FE: 取り込みカードに「差分取り込み（実績を守る）/ 置換取り込み（丸ごと上書き）」
  のモード選択。置換は ❶=dry-runプレビュー（削除n/挿入n/臨時n/対象外一覧）→
  ❸確認ダイアログ→実行。イベント取り込みは両モード共通で併走
