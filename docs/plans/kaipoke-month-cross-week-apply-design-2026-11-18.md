# 月をまたぐ週も画面からカイポケへ送れるようにする — 設計

作成: 2026-11-18 / ステータス: **PO の了承待ち**（方向は PO 2026-11-18「システム上でできないと NG。毎回こちらで対応は NG」）

## 0. 背景
- 2026-11-18 12:31〜13:23、松岡さんが 11/30 の週（11/30〜12/6）を［この週で本番反映］で 6 回送り、6 回とも `API 422 (/api/v1/integrations/apply)` で止まった。カイポケへは何も書いていない。
- 理由：`/integrations/apply` は、選んだ行が 2 つの月にまたがると 422 で断る（カイポケの画面は月ごとのため）。週の差分（171 件）は 11/30 の分と 12/1〜12/6 の分が混ざっている。
- 画面の週の流れ（`WeeklyApplyControls.tsx`／`useWeeklyApply.ts`）は、シートの全件を 1 回で送るだけで、月ごとに分ける手段がない。
- 断った理由（「月をまたぐ週です。先に 2026-11 分だけを…」）は API が返しているが、画面は `API 422 (…)` しか出さない。
- 11 月の 5 週は Claude が道具で月ごとに送った（毎回の手作業）。

## 1. 直すところ
| # | 場所 | 直し方 |
|---|---|---|
| A | API `POST /integrations/apply`（`backend/app/api/v1/integrations.py`） | 要求に `month`（"YYYY-MM"・省略可）を足す。指定があれば、送る行を `resolve_item_date` の月がその月のものだけに絞る（その月の行が 0 件なら 422 で理由を返す）。今の部分送信（`item_ids`）と同じく、送った行は `include=False`、シートは `partial` になり、残りの月をあとで送れる。`month` なしの動きは今と同じ |
| B | 画面 ④カイポケへ反映（`WeeklyApplyControls.tsx`・`useWeeklyApply.ts`） | 週が 2 つの月にまたがるとき、ボタンを月ごとに 2 つ出す：［11 月分（11/30）を本番反映］［12 月分（12/1〜12/6）を本番反映］。dry-run も同じく 2 つ。件数はボタンに出す。片方を送ったら、そのボタンは「送信済み」にする。1 つ目の送信がカイポケで動いている間に 2 つ目を押したときは「前の送信が終わってから押してください」と出す（API の 409 kaipoke busy を言いかえる） |
| C | 画面のエラーの出し方（`useWeeklyApply.ts` の toast） | `ApiError` の本文に `detail` があれば、それを出す（`API 422 (…)` だけにしない）。既にある `lib/api` の文言の取り出し（errorMessage の試験がある関数）を使う |
| D | 展開の確かめ | 月をまたぐ週では、2 つ目の月が展開済みかも見て、未展開ならそのボタンの横に「12 月の展開がまだです」と出す（押す前に気づけるように） |

- 月の境をまたぐ「日の移動」（例 11/30→12/1）は今までどおり送らずに明細に残る（カイポケの画面で手で動かす）。件数を画面に出す。
- DB・migration は変えない。

## 2. 試験
- backend：`month` 指定で、その月の行だけが送られ、残りが `include=True` のまま・シートが `partial`／その月の行が 0 件なら 422／`month` なしは今と同じ／2 回目の `month` で残りが送れる。
- frontend：またぐ週でボタンが 2 つ・件数・送信済みの表示／またがない週は今と同じ 1 つ／422 の理由が toast に出る。
- 実画面：本番の 11/30 の週で dry-run を月ごとに 2 回（書き込みなし）。

## 3. リスク
- 2 つ目を 1 つ目の完了前に押すと 409。B の言いかえで案内する。
- `partial` のシートは、差分を取り直すと新しいシートになる。古いシートの送信済み行は新しいシートの差分から消える（カイポケに入ったため）ので二重送信にはならない。
