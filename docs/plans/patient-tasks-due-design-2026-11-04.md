# やることの期日（任意）と「何回目の訪問待ち」— 設計（2026-11-04）

PO：今泉さん。モック：`docs/mockups/patient-tasks-due-mock.html`。
前の設計：`patient-tasks-design-2026-11-01.md`（やること）、`patient-tasks-recurring-design-2026-11-02.md`（毎月のやること）。

## 1. きっかけ

- 11/4 小林様：「期日を過ぎた」が、期限前のやることにも全部出ている。
- 同日、判定を「出す訪問の日が過ぎても未完了」に合わせて本番へ出した（a94dd9b4）。
- そのうえで PO から次の案が出た。
  - 期日は任意で付けられるようにする。付けたものは期日をはっきり出し、過ぎたら「期日を過ぎた」にする。
  - 期日がないものは「期日を過ぎた」にせず、「1 回目の訪問待ち」「2 回目の訪問待ち」…と出す。

## 2. 決まったこと（PO 2026-11-04）

| # | 内容 |
|---|---|
| a | 期日（`due_date`）は任意。やることを付けるときに入れても入れなくてもよい |
| b | 期日を過ぎた＝未完了で、期日が今日（JST）より前。期日がないものは「期日を過ぎた」にならない |
| c | 期日があるものは一覧・訪問の札に期日を出す（「11/10 まで」「今日まで」） |
| d | 何回目の訪問待ち＝日付（この日から）以降の、取消・削除でない訪問のうち、予定の終わりの時刻が過ぎたものの数＋1。訪問 1 件ごとに数える（同じ日の 2 回も別に数える） |
| e | 毎月のやることの設定に「毎月何日まで」（任意・1〜28 日か末日）を足す。作るやることに、その月の期日を入れる |
| f | 進め方は設計＋動くモックで判断してから実装する |

## 3. 変える場所

### DB（migration 0106）
- `patient_tasks.due_date`（date・NULL 可）。
- `recurring_task_rules.due_day`（int・NULL 可・1〜28、または 0＝末日）。
  - 制約：NULL か 0〜28。
- 既存のやることは期日なし（NULL）のまま。今の 99 件は、どれも「期日を過ぎた」から外れ、「何回目の訪問待ち」になる。

### backend
- `services/patient_tasks.py`
  - `overdue_clause(today)`：`done_at IS NULL AND cancelled_at IS NULL AND due_date < today` に変える（a94dd9b4 の訪問の判定から置き換える）。
  - `visit_wait_counts(db, tasks, now)`：やることごとに、日付以降で予定の終わり（`visit_date + end_time`、JST）が `now` より前の訪問の数を 1 回の問い合わせで数える。札の数字は「その数＋1」。
  - 訪問の詳細（`tasks_for_visits`）では、その訪問より前にある訪問の数＋1 を出す（その訪問から見た何回目か）。今の `carried_over` は「2 回目以降」と同じ意味なので残す。
- `api/v1/tasks.py`
  - 作成（POST /tasks）と、新しく足す期日の変更（PATCH /tasks/{id}、管理者だけ）に `due_date`。
  - 期日が日付より前なら 422。
  - 一覧の絞り込みに `waiting2plus`（2 回目以降の訪問待ち）を足す。`overdue` は期日の判定に変わる。
  - 返す値に `due_date`、`visit_round`（何回目）を足す。
- `services/recurring_tasks.py`・`api/v1/recurring_tasks.py`
  - 設定の作成・変更に `due_day`。作るときの期日は、その月の `due_day` 日（0 なら末日）。ただし作った日（今日）より前になるときは、作った日を期日にする（§6-2）。
- 監査ログ：期日の変更は `task_due_change` で残す。

### frontend
- `AddTaskDialog`：期日（任意）の欄。早押し（今週中・1 週間後・月末）。日付より前は注意。
- タスク管理の一覧：列「期日」、上の件数に「2 回目以降」、絞り込みに「2 回目以降」。札は「N 回目の訪問待ち」「期日を過ぎた」「〇/〇 まで」。
- `VisitTasksBox`（PC）・`MobileVisitTasks`（スマホ）：札に期日と何回目を出す。a94dd9b4 の「訪問日を過ぎて未完了」は「N 回目の訪問待ち」に置き換える。
- `TaskCountBadge`（訪問モニター）：赤＝期日を過ぎたものあり、橙＝2 回目以降あり、に分ける。
- `RecurringTasksPanel`：「毎月 〇日 まで（任意・末日）」の欄。

## 4. 試験の観点

- 期日なし：何回目が 1 → 訪問の終わりの時刻を過ぎて 2 → 次の訪問の後で 3。取消・削除の訪問は数えない。日付より前の訪問は数えない。
- 同じ日の 2 回：朝の訪問の終わりを過ぎたら 2、午後の訪問の詳細では 2。
- 期日あり：期日の当日は過ぎていない、翌日から「期日を過ぎた」。完了・取消は過ぎたにしない。
- 期日が日付より前は 422。期日の変更は管理者だけ、職員は 403。
- 毎月：`due_day` が 0 なら末日（2 月は 28／29 日）。月の途中で作るときの期日。
- migration 0106 の upgrade／downgrade。

## 5. リスク

- 「期日を過ぎた」の件数が、期日を入れない限り 0 になる。事務所が期日を入れる運用に慣れるまで、赤が出ないことを見落としとして受け取らないよう、案内が要る（小林様への説明）。
- 予定の終わりの時刻で数えるので、訪問が遅れて長引いたときは、実際より先に「2 回目」になることがある。打刻（QR の退出）で数える案もあるが、打刻がない訪問を数えられなくなるので採らない。

## 6. PO の決定（2026-11-04・モックを見て）

1. 期日が日付（この日から）より前なら、赤い注意を出して「付ける」を押せなくする（API も 422）。
2. 毎月の分を月の途中で作り、その月の期日がもう過ぎているときは、作った日を期日にする。
3. 期日を後から変える操作は、タスク管理の一覧の行の期日を押して選ぶ（管理者だけ・「なし」にも戻せる）。
4. 何回目の数え方：一覧は「いまの時刻から見て」、訪問の詳細とスマホは「その訪問から見て」（モックのとおり）。
