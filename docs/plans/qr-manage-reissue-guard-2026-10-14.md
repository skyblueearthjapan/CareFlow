# QR の管理画面と再発行の守り（設計メモ・2026-10-14）

## 1. きっかけ（事実）
- 10/14 09:40〜09:42、篠原千晶様の訪問で QR 打刻が 5 回失敗（404×4・410×1）。手動で記録して時間変更で調整。
- 稼働中の篠原様の QR は **10/7 12:46:28 と 12:46:51 に 2 回再発行**（23 秒）。同姓同名の休止中の登録（旧 QR）もある。
- 患者画面の右上で［QRを印刷］と［QR再発行］が**同じ見た目で隣り合い**、確認画面は押すだけで進める。再発行すると古いシールは**即時に無効**。

## 2. PO の決定（2026-10-14）
| 論点 | 決定 |
|---|---|
| 置き場所 | 右上は［QRを印刷］だけ。小さな「QRの管理 ›」で開く画面の**一番下にたたんで**再発行を置く |
| 確認の重さ | **理由を選ぶ ＋ チェック**で、はじめて赤いボタンが押せる |
| 追加の守り | **最後に読めた日を出す**・**古い QR に猶予を残す**（「続けての再発行を止める」「管理者に知らせる」は選ばれなかった＝しない） |
| 猶予の決め方 | **理由で自動**: 汚れた・読めない＝7 日／なくした・他人に使われた恐れ＝即時 |
| 貼り替え後 | **新しいシールが一度読めたら、猶予中の古いシールはその時点で使えなくする** |

## 3. 画面
### 3-1. 患者画面の右上
`[📄カルテ出力] [QRを印刷] [編集]  QRの管理 ›`（再発行ボタンは右上から消す）

### 3-2. 「QRの管理」ダイアログ
```
┌ QRの管理 ───────────────────────┐
│ 篠原 千晶 様（P-0123）                 │
│ 今の QR : 第3版（10/7 発行）           │
│ 最後に読めた日 : 10/13 09:35 熊澤さん  │
│ 古い QR : 第2版は 10/21 まで使えます    │  ← 猶予中だけ
│                                        │
│            [ QRを印刷する ]            │
│                                        │
│ ▸ シールをなくした・汚れた時だけ        │  ← 押すと開く
└────────────────────────┘
```
開くと:
```
│ 理由: ( ) 汚れた・読めない → 古いシールは 7 日間使えます │
│       ( ) なくした          → 古いシールはすぐ使えなくなります │
│       ( ) 他人に使われた恐れ → 古いシールはすぐ使えなくなります │
│ [□] 新しいシールを印刷して貼り替えます                     │
│                      [やめる] [作り直して印刷へ](赤)      │
```
- 理由とチェックがそろうまで赤いボタンは押せない。
- 最後に読めた日が**7 日以内**なら、黄色で「10/13 に QR が読めています。本当に作り直しますか？」と添える（最後の読み取りは古いシールの場合もあるので「今のシール」とは言い切らない・レビュー指摘）。
- 実行後は今と同じく印刷画面へ移る。

## 4. サーバー
### 4-1. DB（migration 0096）
- `revoked_qr_tokens.valid_until TIMESTAMPTZ NULL` を追加。NULL＝即時無効（既存行はすべて NULL＝今と同じ）。
- `revoked_qr_tokens.reason VARCHAR(16) NULL`（`damaged` / `lost` / `misuse`）。

### 4-2. API
- `GET /patients/{id}/qr/status`（admin）: `{version, issued_at, last_scanned_at, last_scanned_staff_name, grace: [{version, valid_until}]}`。
  - `issued_at` = 直近の `revoked_qr_tokens.revoked_at`（無ければ null＝初回発行）。
  - 最後に読めた = `visit_checkins` で `patient_id` 一致・`checkin_source='qr'` の最新 1 件と職員名。
- `POST /patients/{id}/qr/regenerate` に本文 `{reason}` を追加。
  - `damaged` → 旧トークンを `valid_until = now + 7日` で退避。`lost` / `misuse` → `valid_until = NULL`。
  - 本文なし（古い画面）→ 今と同じ即時無効。
  - `audit_logs` の after に reason を残す。
- 判定（`judge.py` の `_resolve_patient` / `resolve_qr_patient`）: 失効トークンでも `valid_until > now` かつ患者が稼働中なら、その患者として通す（打刻の記録方法は `qr`）。期限切れ・NULL は今と同じ 410。
- **新しいシールが一度読めたら、その患者の猶予中の旧トークンは即時に失効**（`valid_until = now`）。貼り替えが済んだら古いシールは自動で使えなくなる。

- 「なくした」「他人に使われた恐れ」（と本文なし）で作り直したときは、前の再発行で猶予中の古いシールも今の時刻で打ち切る（レビュー指摘）。

### 4-3. 既知の制限
- 電波のない所で猶予中の古いシールを読んで退避した打刻が、届く前に猶予が切れた（期限・新しいシールの読み取り）場合は 410 になり記録されない。前から失効トークンは 410 だったので悪くはなっていない。必要になったら `device_time` が猶予の内側なら通す形で足す。

## 5. 範囲外（今回はしない）

## 6. 試験
- BE: 理由ごとの valid_until、猶予内は 200・期限後と NULL は 410、新しい QR を読んだら旧トークンが失効、本文なしは今と同じ、status の最後に読めた日。
- FE: 右上に再発行が無い、理由とチェックがそろうまで赤いボタンが押せない、7 日以内に読めていれば黄色の注意、猶予中の表示。
