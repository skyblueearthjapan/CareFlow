# 設計書: 変更反映先の統一（この週だけ / 固定訪問週間）＋ 操作の戻る/進む

作成 2026-07-03 / PO 構想起点（プール採用が型のみに書かれ今週の表に出ない混乱）。
**PO 設計第一原則: 範囲最適化を含む全変更操作を例外なく同じ「反映先の選択」体験に統一する。**
棚卸し調査（操作×書込先マトリックス・2026-07-03 architect レポート）に基づく。

## 1. 現状の非対称（調査で確定した問題）

データは2層ある: **型**（patient_fixed_visits = 固定訪問週間・毎週の源）と
**週**（visits/VSA = 今週の実予定。表に見えるのはこちら）。

| 非対称パターン | 該当操作 |
|---|---|
| 型に書いたのに今週の表に出ない | プール採用 / apply-individual / **範囲最適化 apply** / 改善提案 swap / 固定枠直接編集 |
| 今週に書いたのに週生成で消える | fix-or-pattern(this_week_only, source=auto) / 欠勤対応(source=auto) |
| 今週に書いたが固定枠戻で消える | apply-week-only / this_week_only |
| 全件保存で**ピン留めが消失** | from-week-bulk（既存 PFV 無条件 DELETE→is_pinned=False で再作成） |

一方で土台は既にある: place-and-fix の `fix_pattern` / fix-or-pattern の
`this_week_only|pattern_change` は**まさに求める2択**。sync-week-visits-to-fixed
（1患者の週→型 upsert・dry_run 付き）は「後で型に反映」の部品。

## 2. 統一モデル

### 2.1 反映先は常に2択（＋キャンセル）
すべての配置変更操作の確定時に、共通の確認ステップで選ぶ:

- **A. 固定訪問週間に登録** = 型に書き、**今週にも即反映**する（型だけ変えて週に出ない、
  という今回の混乱パターンを選択肢として存在させない）
- **B. この週だけ反映** = 週にのみ書く。型は不変（来週は従来どおり）。
  後から「この配置を固定訪問週間に反映」で**昇格**できる

適用ルール:
- 選択を出す操作: DnD配置 / 時刻移動 / プール採用 / 一括プール投入採用 /
  **範囲最適化 apply** / 改善提案 apply(move・swap) / シミュレーション採用 / 固定枠直接編集 /
  **新規提案の採用**（PO 確認済み 2026-07-03: 入口は操作別・出口の確認は全操作共通）
  （固定枠編集の既定は A。編集画面の文脈上、型を編集する意図が明確なため B は補助）
- **手動ドラッグの現状事実（要修正）**: FE は place-and-fix を `fix_pattern: true` 固定で
  呼んでおり（CourseDayTablePanel 内4箇所）、**ドラッグのたびに確認なしで型も書き換わる**。
  BE の週だけモード（fix_pattern=false）は既存だが FE 未使用。U-2 で2択確認に置換する。
  ドラッグは高頻度操作のため、既定値つき軽量確認（トースト内選択等）も D-2 で検討
- 選択を出さない操作（=「週の運用」と定義し UI にもそう表示）: 担当スタッフ変更・
  欠勤対応（型にスタッフ概念がない）/ 週を生成・固定枠戻・全件保存（層間の変換操作そのもの）

### 2.2 共通プリミティブ（BE の統一部品・新設2つ＋修正2つ）
1. **patient-scoped 型→週同期** `sync-fixed-to-week` （新設）: 1患者の今週 visits を
   PFV ベースで再生成（reset-to-fixed の1患者版。manual/completed 保護は同一規則）。
   A 選択時の後段として全 PFV 系操作から共通利用
2. **週だけ配置の統一書込**（新設 or 既存流用）: B 選択時の visits 書込。挿入系は
   place-and-fix(fix_pattern=false) 相当、移動系は bulk-apply-week-only-visit-changes 相当を
   操作種別ごとに正規化。**source='manual_week'（新値）で書き、週生成・固定枠戻の両方で保護**
   ＋「週だけ例外」バッジの表示根拠にする
3. **sync-week-visits-to-fixed の is_pinned 保持**（修正）: 昇格導線で使うため
4. **from-week-bulk（全件保存）のピン消失修正**（修正・独立バグ）

### 2.3 「週だけ例外」の可視化と昇格
- source='manual_week' の visit にバッジ（例: 「今週のみ」チップ）を表示
- 行アクション/患者詳細に「この配置を固定訪問週間に反映」（=sync-week-visits-to-fixed
  患者単位・dry_run プレビュー付き）

### 2.4 統一確認 UI
- 共通コンポーネント `ChangeScopeConfirmDialog`: 操作内容サマリ＋2択＋説明文
  （「固定訪問週間 = 毎週の型。登録すると来週以降も同じ配置になります」）。
  全操作がこの1コンポーネントを使う（文言・順序・色を統一）
- 既定値: 操作の意図に合わせる（プール採用=A 既定 / DnD 微調整=B 既定 等は現場FBで調整可能に）

## 3. 戻る/進む（undo/redo）— 同じパイプラインに載せる

- 統一確認を通る全操作は **操作ジャーナル**（新テーブル schedule_op_log:
  user_id / iso_week / office_id / op_kind / scope(A|B) / forward_payload /
  inverse_payload / created_at）に記録する
- FE: 「↶ 戻る」「↷ 進む」ボタン（＋Ctrl+Z / Ctrl+Y）。スタックは ユーザー×週。
  undo = inverse_payload の実行、redo = forward_payload の再実行
- 楽観ロック: inverse 実行前に対象の現在値を検証し、他者変更があれば
  「他の変更があったため戻せません」で中断（黙って上書きしない）
- 一括操作（範囲最適化 apply 等）は inverse をスナップショット方式（適用前の
  対象 PFV/visits 集合）で記録
- 対象外操作（週を生成等）が入った時点でスタックをクリアしボタン無効化

## 4. Wave 分割（実装順）

| Wave | 内容 | 価値 |
|---|---|---|
| U-0 | 共通プリミティブ（§2.2 の 1・2・3）＋ from-week-bulk ピン消失修正（4） | 土台＋既存バグ解消 |

## 5. PO 決定事項（2026-07-03 回答・確定）

- **D-1 確定**: A/B の2択（第3選択肢なし）
- **D-2 確定**: 軽量・直感的・作業を止めないこと（「さっくり進められる」）が要件。実装方式:
  - 既存ダイアログがある操作（プール採用/範囲最適化/新規提案/シミュレーション採用/改善提案）:
    既存確認画面に A/B ラジオを埋め込む（追加ステップゼロ）
  - ドラッグ（ダイアログなし・高頻度）: 既定 B（この週だけ）で**即時反映**し、成功トーストに
    「毎週の型にも登録」アクションボタン（=昇格プリミティブをワンクリック実行）を添える。
    ※ 現状のドラッグは暗黙 A 相当（両方書込）のため、**既定が B に変わるのは仕様変更**。
    リリース時に現場周知する
- **D-3 確定**: 担当変更・欠勤対応・自動スタッフ割当は「患者スケジュール」とは別の
  「**スタッフ割当**」系として扱い、A/B 選択は出さない。ただしスタッフ割当系も
  それ自体として統一的に扱う（用語・確認体験・操作ジャーナル(undo)への記録は共通）
- **D-4 確定**: 戻る/進むは自分の操作のみ（他管理者の操作は対象外・楽観ロックで衝突検知）
