# スケジュール・アドバイザー構想（設計書 v1）

作成 2026-07-02 / 前提文書: `docs/plans/scheduling-logic-normalization.md`（正規化ルール N-1〜N-8・不整合 I-01〜I-20）

## 0. 背景（なぜ方向転換するか）

現場の実運用は「**固定スケジュール＋例外処理**」: 手動で組み、固定化し、空きに新規・変更患者を
どんどん入れる。距離や経路の無駄を検討する余裕はなく、非効率が蓄積してコストとストレスになっている。

既存の自動化（全面最適化・プール投入）は「毎週白紙から最適解」を志向しており、
患者との約束（同じ曜日・同じ時間）を大量に動かす提案は採用不能。**使われないのは必然**。

クライアントが求めているのは「隣に座る超優秀なベテラン管理者」:
1. **診る** — 今のスケジュールの無駄を数字で示す
2. **囁く** — 「Aさんをこちらに動かした方が効率的」と *1件ずつ* 提案する
3. **弁える** — 「この人はこの曜日この時間でないとダメ」という人間の事情を踏み越えない
4. **節目に見直す** — 3〜6ヶ月の劣化・スタッフ増減を検知し「見直しどき」を知らせる

## 1. 設計原則

| # | 原則 | 内容 |
|---|---|---|
| P1 | 提案は1手単位 | 1患者の時刻/曜日移動 or 2患者のスワップまで。全体組み替えは提案しない。1件ずつ採用/却下 |
| P2 | 効果を数字で語る | 「移動 -18分/週」「-2.1km/週」。効果の物差しは Phase 1 の健康診断指標と同一 |
| P3 | 可動域は患者データ | 「動かせない事情」を患者ごとの可動域フラグとして永続化し、システムは絶対に踏み越えない |
| P4 | 却下を記憶する | 見送り時に理由を記録し、同じ提案を蒸し返さない。却下行為が制約データを育てる |
| P5 | 信頼が先、賢さは後 | 少数精鋭の提案から開始。スタッフ実態を知らない提案・適用事故は一発で信頼を失う → Phase 0 が前提工事 |
| P6 | 自動適用しない | 提案の採用は常に人間。適用APIは N-4 の最小再検証を通す |

## 2. 既存資産との対応

| 欲しい機能 | 実現方法 | 新規開発 |
|---|---|---|
| 実行可能性判定（正典） | proposal_solver（両方向制約・90分占有・営業枠・昼窓）= N-1 | なし |
| 「本当は11時の方がいい」 | propose-slots を配置済み患者に適用し、現在枠スコアと候補スコアの差分を提示 | 薄い比較層 |
| 「Aさんを動かすと効率的」 | 移動時間の悪化要因患者を抽出 → propose-slots で代替探索 → 差分上位のみ提案化 | 薄い探索層 |
| 健康診断（無駄の可視化） | 既存 travel モデル（20km/h・バッファ8分・90分占有）で週次集計 | 集計＋UI |
| 週次スタッフローテ | Layer3（完成済）。導線・儀式化のみ | 導線 |
| 定期見直し・スタッフ増減 | 健康スコア推移＋イベント検知 → 提案を増量。full-optimize は「白紙比較シミュレーション」に再定義 | 通知層 |

## 3. フェーズ計画

### Phase 0 — 前提工事（信頼の土台）

**P0-1: propose-slots にスタッフ実態チェック（N-3: L0→L1.5 / I-01）**
- 候補コースの割付スタッフについて以下を検出し、**除外せず理由付き警告＋スコア降格**:
  - `staff_unassigned` … コースにスタッフ未割付
  - `staff_absent` … 割付スタッフが当該曜日に非番（StaffShift is_on=false）または当週休（StaffWeeklyOverride off）
  - `staff_sex_mismatch` … 候補患者の sex_restriction と割付スタッフの性別が不適合
- 降格ペナルティは命名定数（スコア式に統合）。FE の警告ラベル辞書（PROPOSE_WARNING_LABEL_JA）へ訳語追加。
- ④⑤（新規提案/プール候補）の両UIに自動反映（同一エンジンのため）。

**P0-2: 適用経路の安全網（N-4 / I-03, I-04, I-05）**
- PUT /patients/{id}/fixed-visits と /v2/apply-individual に最小再検証
  （患者間時間衝突[90分占有込み]・H10・容量480分）を追加。
- **手動運用を壊さないことが最優先**: 手動編集は現場の生命線のため、v1 は
  「検出→レスポンスに警告を返し FE がトースト/確認表示」を基本とし、
  ハードブロック(422)は 構造破壊（同患者同曜日重複等）と pinned 違反（現行維持）に限定。
  昇格（force フラグ付き422化）は運用実績を見て判断。
- H10 の individual/week-only 受理基準を「警告＋明示 force」モデルに統一する設計をとる。
- 実装前に architect の設計パスを必須とする（既存の手動編集フロー・FEマージ規約 I-03 への影響が大きいため）。

### Phase 1 — 診る（スケジュール健康診断）
- 週次・コース別・曜日別に集計: 総移動時間(分)・総距離(km)・隙間時間・コース間偏り・
  同住所ペア成立率。計算は既存 travel モデルを流用（= 提案効果と同じ物差し）。
- API: GET /v2/schedule-health?iso_year&iso_week&office_id（read-only 集計）。
- UI: スケジュール画面に「健康診断」パネル（コース別バー＋前週比）。管理者の
  「無駄が多いのでは？」に最初に答える成果物。クライアント初回デモの主役。

### Phase 2 — 囁く（改善提案 MVP）
- **可動域フラグ**（P3）: PatientFixedVisit / Patient に可動域属性を追加
  （時刻変更可・曜日変更可・完全固定。既定は「不明=保守的扱い」）。
  既存 is_pinned / time_type=固定 との整合を設計時に定義。
- **単発改善提案**: 配置済み患者に propose-slots を適用し、`効果差分 = 現在枠コスト − 候補枠コスト`
  が閾値超のものだけ提案カード化。まず患者詳細画面、次にスケジュール画面の提案フィード。
- **却下記憶**（P4）: 提案却下テーブル（患者×提案種別×理由×期限）。理由が「曜日変更不可」なら
  可動域フラグへ昇格提案。
- 提案カード表記: 効果(分/km/週)・変わるもの/変わらないもの・患者確認要否・実行可能性根拠。

### Phase 3 — 弁えて広げる
- 2患者スワップ提案・新規患者への「希望より良い枠」上乗せ提案（④の拡張）。
- 見直しどき通知: 健康スコアの悪化トレンド・スタッフ増減イベントで提案を増量。
- full-optimize を「白紙比較シミュレーション」として管理者専用に再定義（運用ボタンから外す）。
- 当日欠勤の代替スタッフ提案（Layer3 の適格性判定資産を日粒度に再利用）— 別設計書で扱う。

## 4. 非ゴール
- 提案の自動適用・無人運転
- pinned／可動域「完全固定」患者を動かす提案
- 毎週の全体再最適化の運用復活（シミュレーション専用）

## 5. 進行規約
- 各項目は「実装 → 独立レビュー（code-reviewer/security-reviewer）→ 検証 → デプロイ」を1単位。
- 判定基準は正規化ルール文書（N-1〜N-8）。差異を作る場合は本文書に追記して理由を残す。
- Phase 1 完了時にクライアントへ実物デモ → フィードバックを Phase 2 の提案閾値・文言に反映

## 6. 余白の原則と予防・保全・救急の分業（PO 確認 2026-07-05 — 本ソフトの要）

W-12d 詰まり解消相談の設計対話で PO が「このソフトの要になる考え方」と明言した思想。
以後の新機能の設計・レビューは本節との整合を判定基準とする。

### 6.1 余白の原則（P3 権威3層の帰結）

システムが患者の予定を動かすとき、使ってよいのは**その患者様が予め差し出した
「希望訪問スケジュールの余白」だけ**。ピン留め=絶対不可侵／希望範囲=確認不要で使える余白／
それ以外=動かさない。「固定時間の新患者 vs 希望時間帯の既存患者」では、余白を持つ側だけが
その範囲内で動く — 誰の約束も破らない。「際限のなさ」への歯止めは:
①発動条件（候補0件＋明示操作のみ）②範囲（余白のみ＋不可侵リスト＋動かせない事情の会計表示）
③手数（最大3手・全体組み替え禁止）。

### 6.2 予防・保全・救急の分業（道具の「問い」を混ぜない）

- **スケジュール診断 = 予防**: 詰まりかけ・無駄の蓄積を早期に診る
- **スケジュール最適化 = 保全**: 定期的に余白を回復する。余白のあるスケジュールはそもそも
  詰まらない — これが本当の「先々先手」
- **詰まり解消相談 = 救急**: 候補0件の例外時のみ出動する

救急の技術（他患者を動かして開通させる）を日常画面（改善提案・最適化）へ持ち込まない。
囁きが騒音になり「弁える」が壊れるため。救急車は車庫にいる時間が長いのが健全な街。

### 6.3 詰まり解消相談の将来拡張（PO 承認済み候補 — これ以外に広げない）

担当エージェントが誰であっても、この2件のみが拡張候補である:
1. **一括投入との橋渡し**: bulk の投入不能患者に「ずらせば入る手あり」バッジ → 個別相談へ
   （W-5b 定員超過橋渡しと同じ実証済みパターン）
2. **定員起因への拡張**: ブロッカーを別コースへ移して定員を空ける = 方式b との合流
   （`unblock-consult-design.md` §5 バックログ）。
