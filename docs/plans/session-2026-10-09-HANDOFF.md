## 7. 気になる点・罠（このセッションで踏んだもの）
- **ssh が途中で切れる**（Connection reset）。長い処理はサーバー側 `nohup` で走らせ、結果はファイルで見る。
- `pkill -f watch_rpa.py` を ssh のコマンド文字列に入れると **自分の ssh も殺す**（exit 255）。PID を見て止める。
- ssh の `'...'` の中に Python の f-string や `'` を書くと引用が壊れる → 手元でファイルを書いて `scp`。
- Chrome の headless PDF は **日本語ファイル名だと失敗** → 一時的に ASCII 名で出して `mv`。
- カイポケの RPA は **17〜18 時台に失敗しやすい**（10/9 は 17:56〜21:34 に流して失敗 0 だったが、原則は日中）。1 件 30〜60 秒・172 件で約 1 時間 50 分。
- カイポケの export は **担当なし（-）の行を出さない**。送る前に担当なしが 0 件か確かめる。
- **准看の追加も送れる**（本番 `.env` `KAIPOKE_RPA_SERVICE_BRANCH_ENABLED=True`・コードの既定は False）。
- 「今週だけ取消」では保留プールに出ない（取消も件数に数える）。プールへ移すのは `DELETE /visits`。
- `sync-fixed-to-week`（1 名の週を固定訪問の枠から作り直す）は manual_week を消さず、よその担当・同行の既定・固定イベントまで書き換える → 使わない。
- 患者の状態「終了」は内部では `cancelled`。予定・枠を消すのは確認画面でチェックしたときだけ（PATCH・申請の承認・取込では消えない）。
- お客様がカイポケ側で直接直す運用がある → らく助から週を送り直すと、その手直しを上書きして戻してしまう。**送る前に必ず差分を見る**。
- 本番の患者数（10/9）: 稼働中 89・休止 5・入院 6・開始前 7・終了 16。1 週間に約 80 名・平均 1.9 回。
