# 青ピンの廃止と「週の作り方」の安全化 — 設計書（確定・2026-10-12）

調査: `B1-code-survey-2026-10-12.md`（コード）・`B2-production-usage-2026-10-12.md`（本番の使われ方）
関連: `../red-pin-simplify-design.md`（赤ピン＝曜日・時刻だけの固定。同じ画面部品を触るので一緒に進める）

## 0. 背景（PO 2026-10-12）
- 以前: コースのスケジュールだけ → 「週を生成」で型から作って手で直し、青ピンで固定していた。
- 今: **コースの最適配置を先に出す → 職員スケジュールで担当を割り振り、休み・余りをならす**。職員スケジュールは週の前や当日に何度でも組み直す場所なので、固定する必要がない。
- カイポケの運用: 最初の 1 週間はらく助で組んでカイポケへ送る → その後の現場の変更（急なキャンセル・午前休・イベントなど）は**カイポケで直す** → それをらく助へ取り込む。だから**取込はカイポケが正**。
- 本番の事実（B2）: 人が青ピンを刺したのは 8/8〜8/11 だけ。止めた実績 0。画面の青は週43・44 で 99%＝ほぼ「今週だけ」の印。手で直した訪問を実際に消しているのはカイポケの置換取込（10/12 週42 で 102 件・カイポケが正の決まりどおり）。

## 1. 決まったこと（PO 2026-10-12）
| # | 決定 |
|---|---|
| BP-1 | **青ピンをなくす**: 盤面の青トグル・「今週全件固定／解除」・青の画鋲・青ピンで人の操作を止める仕組み（422）・API（`PATCH /schedule/v2/visits/{id}/week-pin`・`POST /schedule/v2/visits/week-pin/bulk`）を外す。本番に残る `week_pinned=true` 126 件は false に戻す。列 `visits.week_pinned` は 1 リリース残して読まない → 次のリリースで migration で消す |
| BP-2 | 「今週だけ」（`manual_week`）・「取込」（`import`）などの**作り方の印は残す**（週を生成で消えない守りはこれで足りている・B1）。画面の表示は今の「今週のみ」チップのまま（青い画鋲にはしない） |
| BP-3 | **「週を生成」は空の週でだけ押せる**（取消の記録と打刻・実績のある訪問以外に予定が 1 件でもあれば押せず、「先に『この週を空にする』を押してください」と理由を出す）。理由（PO 2026-10-12）: 型と今ある予定の「どれとどれが同じか」は確実に見分けられない（例: 曜日をまたいで動かした訪問を型から足すと二重になる）ので、推し量る仕組みを持たない |
| BP-4 | **「この週を空にする」**: 打刻・実績・サインのある訪問（と取消の記録）だけを残し、**それ以外はすべて消す**（カイポケ由来・送信済みも消す）。確認は「この週の予定 N 件を消します。うちカイポケへ送った訪問 M 件は、次の送信で削除になります（残す K 件: 打刻・実績あり）」を落ち着いた文で。消す前の状態を自動で保存し「元に戻す」で戻せる（PO 2026-10-12: 全部消す方向でよい） |
| BP-5 | 型から作り直したいとき = 「空にする」→「週を生成」。1〜2 件だけ入った週も同じ（必要な分は生成の後に入れ直す） |
| BP-6 | **カイポケの取込**: 今ある取込の確認（プレビュー）の中に、らく助で調整した訪問が置き換わるときだけ、落ち着いた 1 行「らく助で調整した訪問のうち N 件が、カイポケの内容に合わせて変わります ▸ 見る」。押したときだけ一覧（どの訪問がどう変わるか・「取り込み前に戻す」で戻せる旨を小さく）。**新しい確認画面・クリックは足さない。0 件なら何も出さない。警告色にしない**（認知負荷・うっとうしさを増やさない） |

## 2. 作るもの
### 2-1. backend
- 青ピン API 2 本を外す。`week_pinned` を読む守り（visit-move-week-only・DELETE /visits・PATCH /visits の配置・今週だけ取消・職員の休み・コースの曜日移動・週のコピーでの置き換え 等 B1 §1 の全箇所）を外す。週の生成の「消さない」判定は作り方の印（manual_week/import/manual/manual_cancel）だけにする（青の和集合をやめる）。
- 「週を生成」（generate-week-only 等の画面が使う経路）を BP-3 のとおり空の週だけに制限する（予定があれば 409 と理由）。消す処理は「空にする」へ移す。reset-to-fixed（型に戻す）など、既存の消して作り直す経路は画面から使っていなければ admin 専用のまま残し、エージェントの禁止操作にする（B1 で使用箇所を確認）。
- 新規 `POST /schedule/v2/weeks/{iso_year}/{iso_week}/clear`（dry_run で件数・内訳を返す → 本実行）。残すものは BP-4（打刻・実績・サイン・取消の記録だけ）。実行前に週のスナップショット（既存の inbound_snapshot の仕組みを流用できるか確認・なければ同等の保存）と「元に戻す」API。
- 取込のプレビュー API に「らく助で調整した訪問のうち置き換わるもの」の件数と一覧を足す（読み取りだけ）。
- 本番の `week_pinned=true` 126 件を false にする SQL（実行は director がリリース時に・件数確認つき）。
### 2-2. frontend
- 青トグル・BulkWeekPinAllButton・青の画鋲・青ピン関連の 422 の文言とツールチップを外す（赤の画鋲の位置は角に寄せる）。
- 週の画面: 「この週を空にする」ボタン（確認ダイアログ BP-4）と、「週を生成」の確認文を BP-3 に。
- 取込の確認に BP-6 の 1 行と一覧。
### 2-3. agent / tools
- ops: 「空にする」op（`clear-week`、元に戻すは保存から）と「週を生成」op（空の週だけ）を追加。青ピン前提の注記（visits.py の 422）を外す。
- ならしの道具・AGENTS.md・スキル: 青ピンの記述を外す。禁止操作の一覧を更新（丸ごと作り直しは「空にする→生成」の手順で、案→了承→バックアップ）。

## 3. 完了の条件
- 青ピンの UI・API・守りが残っていない（grep で `week_pinned`・`week-pin` が読み取り以外に無い）。
- 「週を生成」は予定のある週では押せない／空の週では型から作る（テスト）。
- 「空にする」が BP-4 のとおり残すものを残し、元に戻せる（テスト）。
- 取込の確認に置き換わる件数が出る／0 件なら出ない（テスト）。
- 本番反映は PO 了承・pg_dump の後（赤ピンの整理と同じリリース）。
