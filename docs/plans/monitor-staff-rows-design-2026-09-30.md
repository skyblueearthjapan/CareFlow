# 訪問モニターを職員単位に — 設計（Phase 3）

作成: 2026-09-30 ／ ステータス: **設計済み・未着手**（Phase 2「実績の時刻を合わせる」のレビュー後に着手）
見た目の正典: `docs/mockups/monitor-staff-rows-mock.html`（職員別・置き場所は ③ 行の下に開く）

## 0. なぜ変えるか

訪問モニターの行は 2026-07-10 からコース単位。当時は 1 人 = 1 コースだったので職員単位と同じ絵だった。その後、カイポケ正での取込の定着・都賀への応援・臨時コースで、1 人が複数コースを持つのが普通になった。

本番 2026-09-28 週の実測（読み取りのみ）:
- のべ 29 人日のうち 15 人日が 2 行に割れる。うち 6 人日は 2 コースの訪問が時間順に入り混じる。
- 9/30 は訪問 30 件が 9 行。人で数えると 6 人。「都賀 臨2」の行に 2 人の同時刻の訪問が同居。
- 割れた人日の推移: 7/6・7/13 週 0 → 8/31 週 19 → 9/7 週 16 → 9/14 週 15 → 9/21 週 8 → 9/28 週 15。臨時コースの行は 0 → 9〜11 本。
- コースは日替わりの枠の名前（同じ人が月 B・火 A・水 A・木 B・金 A）。

7/10 にコース単位へ変えた理由（訪問の担当欄が空・不整合で職員単位だと行が潰れた）は解消している（9/28 週: 担当が空の訪問 0 件、コース担当と訪問の担当の食い違い 1 件）。スマホ「今日の訪問」とスケジュールの「職員スケジュール」タブは既に職員単位。

## 1. PO 決定（2026-09-30）

| # | 決定 |
|---|---|
| 1 | モニターの行を職員単位にする（考え方は「問題ない」） |
| 2 | 右側に固定していた地図・順路・詳細は、**選んだ行のすぐ下に開く**（モックの ③）。選ぶまでは出さない。タイムラインは常に全幅 |

仮置き（PO 未回答・この前提で進め、違えば直す）:

| 論点 | 仮置き |
|---|---|
| 「コース別」への切り替え | **残さない**（コース単位で見るのはスケジュール画面の役目） |
| 並び順 | 所属の拠点（`offices.sort_order`）→ 職員コード順（職員スケジュールと同じ） |
| 予定外の訪問 | 読み取った本人（= `primary_staff_id`）の行に「予定外」の印つきで入れる。専用行は廃止 |
| 同行・2 名体制 | 主担当の行に出す。同行者・副担当の行にも薄く出す（押すと主担当側の訪問を選ぶ） |
| 拠点の絞り込み | その拠点の訪問を 1 件でも持つ人を出す（行の中身はその人の 1 日全部）。訪問の無い人は所属で判定 |
| 訪問が無くイベント・休みだけの人 | 出す |
| 担当が空の訪問 | 「担当なし」の行にまとめ、⚠ を出す |

## 2. 行の決め方（BE `services/checkin/monitor.py` `build_monitor`）

- 行キー = 訪問の担当（`visits.primary_staff_id`）。NULL のときはコース担当（`courses.assigned_staff_id`）へフォールバック（スマホ・職員スケジュールと同じ規則）。どちらも無ければ「担当なし」行。
- 当日に訪問が無くても、**その日にイベント（`staff_events`・取消でないもの）または休み・時間変更（`staff_weekly_overrides`）がある在籍中の職員**は行を作る（`visits: []`）。
- 行の拠点 = 職員の `primary_office_id`。
- 行内の訪問は時刻順。`distance_to_next_m` は行内（= その人の 1 日）の順で計算する（今はコース内の順）。
- 予定外の訪問は専用行に集約しない。
- 並び: 拠点の `sort_order` → 職員コード。「担当なし」行は末尾。

変えないもの: 訪問ごとの判定（phase・alert_level・代行・ペア補正・確認済み・実績時刻）。集計の入力が変わるだけで、1 訪問の状態は今と同じ。

## 3. 応答の形（`GET /api/v1/monitor`）

`MonitorStaffRow`（名前は据え置き）:

| 項目 | 内容 |
|---|---|
| `staff_id`, `staff_name` | 行の職員。「担当なし」行は null |
| `office_id`, `office_name` | 職員の所属拠点 |
| `course_tags` | その人がこの日持つコースの札（重複なし・初出順）。`[{ "label": "稲D", "course_id": "...", "office_id": "...", "office_name": "稲毛" }]`。ラベル = 拠点の 1 文字目 ＋ コースコード |
| `visits` | 主担当の訪問（時刻順） |
| `companion_visit_ids` | 同行・副担当として関わる訪問の id（主担当の行にある訪問）。画面はその訪問を探して薄く描く |
| `staff_ids` | `[staff_id]`（互換。イベント帯の取得に使っている） |
| `course_id`, `course_label`, `course_staff_id`, `course_staff_name` | **常に null**（互換のため項目は残す） |

`MonitorVisit` に足す:

| 項目 | 内容 |
|---|---|
| `course_id`, `course_tag` | 訪問のコースと札（「稲D」）。コース無し・予定外は null |
| `course_office_id`, `course_office_name` | コースの拠点（拠点の絞り込みと札の色に使う）。コース無しは患者の主担当拠点 |
| `course_staff_mismatch` | コースの担当とこの訪問の担当が違う（手動の付け替えを除く）。札に ⚠ |

`offices`（絞り込みチップ）= 当日の訪問のコース拠点 ∪ 行の職員の所属拠点。

## 4. 画面（`frontend/app/(app)/monitor/page.tsx`・`components/monitor/*`）

- 右の `<aside>`（地図＋詳細）を撤去し、タイムラインを全幅にする。
- 行ヘッダ: 番号、職員名、2 行目に「所属 ・ N 件」（訪問なしは「訪問なし」）、3 行目にコースの札。拠点が変わる所に「所属: 稲毛」の区切り行。
- 訪問のカード: 1 行目の先頭にコースの札（色 = 拠点）。予定外は「予定外」の札。拠点をまたぐ次の訪問の前に「→ 都賀へ」。
- **行の下に開くパネル**（決定 #2）:
  - 行を押す → その行のすぐ下に開く。中身は 左 = 地図（既存 `MonitorMap`。その人の 1 日の順路）／右 = 順路の一覧（拠点をまたぐ所に「稲毛から都賀へ移動」）。
  - 訪問のカードを押す → 同じパネルに、その訪問の詳細（既存 `MonitorDetailPanel` の中身: 到着・退出・滞在・位置の判定・調整・確認済みにする）を並べる。
  - 開いているのは 1 つだけ。✕ と Esc と、同じ行をもう一度押すことで閉じる。
  - 横スクロールしてもパネルは左に留まる（`position: sticky; left: 0`、幅はスクロール領域の見えている幅）。
  - **開け閉めで画面が飛ばない**ようにする: 開いたとき、選んだ行が見える位置に残るようスクロール位置を保つ（上の行のパネルが閉じて下の行が開く場合は、閉じたぶんだけスクロールを戻す）。
- 要対応トレイから訪問を選んだときは、その訪問の行を開いてそこへスクロールする。
- 集計（本日の訪問・記録済・要確認・未訪問・平均到着ズレ）の数え方は変えない。
- 凡例から「📌予定外訪問（専用行）」の説明を外し、コースの札の説明を足す。

## 6. テスト

- BE: 1 人が 2 コースを持つ日に 1 行になる／担当が空でコース担当がある訪問はコース担当の行へ／どちらも無い訪問は「担当なし」行／予定外の訪問が本人の行に入る／訪問が無くイベントだけの職員の行ができる／休みの職員の行ができる／並び順（拠点 → 職員コード）／`course_tags` の重複なし・初出順／`distance_to_next_m` が行内の時刻順／`companion_visit_ids`／拠点の絞り込み。
- FE: 行ヘッダと札、拠点の区切り行、行を押すとその下にパネルが開く・1 つだけ・✕ と Esc で閉じる、訪問を押すと詳細がパネルに出る、トレイから選ぶと行が開く、拠点チップの絞り込み、イベントだけの行。

## 7. 注意

- メモリ `careflow-monitor-course-rows` の「モニター改修時は行=コースを崩さない」は、この変更で**逆になる**。実装後に更新する。
- 行 = 職員にしても「訪問の担当 = `visits.primary_staff_id` = スマホの今日の訪問と同じ源」という保証は変わらない。
- 1 人が同じ時刻に 2 件持つ日（同住所ペア・重複登録）は、今と同じくレーンを分けて描く。
