発端 = 松岡様 9/4 報告「特別訪問週間の ○ が押せない」「プールで移動できない人がいる」。PO 仮説（9/7）= 「○ の仕組みが理解されていない。○ を押すと**濃くなって選択される**と思ったら、実際は**消えた**」。
正典（現行仕様）= `special-visit-week-design.md`（PO 確定 2026-07-29）。本書は現状の事実整理と改善案。**コードは変更していない。**

## 0. 結論（先に）
1. PO 仮説は**データで裏付けられた**。○ は「未配置の追加枠。**クリック＝取消（確認なし）**」であり、押した瞬間に消える。9/7 21:09〜21:11 の PO ご自身の操作ログ（唐鎌様: DELETE 5 件・POST 5 件）がそのまま再現になっている。※データは元の状態に戻っている（§4）。
2. このダイアログには**「配置する」操作が存在しない**。配置はスケジュール画面右の保留プール「⭐特別訪問週間」からだけ。ダイアログの説明文にもプールへ行く導線が無く、利用者はダイアログ内で完結すると思う。
3. プール側は「候補 0 件」で行き止まり（8/31 決定の M 出口は未実装）。青栁様 木曜は 9/7 週・9/14 週とも候補 0 件（空きなし・定員いっぱい）を実測。
4. 改善の骨子: **ダイアログのセルを「状態を切り替えるボタン」から「その日をどうするかを選ぶメニュー」に変え、配置までダイアログ内で完結させる**（本日稼働した「＋訪問」の提案エンジンと M 受け皿を流用）。○ の取消は必ず確認を挟む。

## 1. 現状の状態モデル（事実）
### 1-1. 期間（special_visit_periods）
| 状態 | 意味 | 作り方/終わり方 |
|---|---|---|
| active | 有効。患者 1 人につき同時に 1 本 | ダイアログで開始日・終了日（延長可）・目標回数（週 N 回以上・既定 5）を作成 |
| ended | 終了 | ダイアログ上部の「期間を終了する」ボタン（**確認なし・目立つ位置**） |

### 1-2. セル（週 × 曜日）の状態と、クリックで起きること
| 見た目 | 状態 | クリックで起きること | 確認 |
|---|---|---|---|
| グレー | 期間外 | 何も起きない | — |
| 破線の「＋」 | 追加枠なし | **○ を作る**（POST marks・status=pool）→ プールに ⭐ チケットが積まれる | なし |
| **○**（桃色枠） | 追加枠あり・**未配置**（status=pool） | **○ を消す**（DELETE・status=cancelled）→ プールからチケットが消える | **なし** ← 誤操作の温床 |
| **●**（桃色塗り・時刻/コース小書き） | 追加枠あり・**配置済み**（status=placed・placed_visit_id あり） | ● を消す＝**配置済みの訪問も削除** | あり（window.confirm） |
| 固定訪問カード＋「この日はプールへ退避」 | 固定訪問がある日 | その日の固定訪問を盤面から外しプールへ（kind=displaced） | なし（配置済みを戻すときのみ確認） |
| 打ち消し線＋「プールへ退避中」 | 退避中 | 「固定どおりに戻す」 | 配置済みなら確認 |

- 行末「週合計 N 回 ✓／N 回 / 目標 M」= 固定訪問の残数 ＋ ○/● ＋ 退避チケット（未配置でも数える）。
- **○ → ● にする操作はダイアログには無い。** ● になるのはプールから配置したときだけ。

### 1-3. 配置の経路（現行）
1. スケジュール画面 → 右の保留プール最上段「⭐特別訪問週間」に、表示中の週の ○ が「氏名・追加枠/固定退避・曜日・週 N 回以上」のカードで並ぶ。
2. カードをクリック → 候補提案（propose-slots・その曜日限定・その週の実スケジュールで判定）。
3. 候補を採用 → `POST /special-visit-marks/{id}/place`（course_code＋開始時刻）→ その週だけの訪問（source=manual_week）を作り、○ が ● になる。型（固定訪問）は変えない。
4. 候補 0 件のとき: **出口なし**（⭐ カードはドラッグ不可・M へ入れるボタン無し）。通常プール患者は列へ直接ドラッグすれば空き・定員に関係なく置ける（強制配置済み）が、列の外で離すと無言。

### 1-4. 盤面での見え方
- 配置済みの訪問は普通の「今週のみ」訪問として表示（⭐ の印は無い）。カイポケ送信も普通の行として乗る。
- 週生成は ○ を無視し（プール専用）、退避マークの曜日だけ固定訪問の展開を止める。

## 3. 改善案（シンプルな入れ方）
### 3-1. 利用者に見せる考え方（3 つの状態だけ）
「**この日に 1 回追加したい（○）**」→「**この日の何時にどのコースで行くか決めた（●）**」→ 終わり。取消はメニューから。

### 3-2. ダイアログの変更
1. **セルをクリック＝メニュー**（ボタン即実行をやめる）
   - 追加枠なし: 「この日に追加枠を付ける（○）」「この日の固定訪問をプールへ退避」
   - ○: 「**この日の配置先を決める…**」「追加枠を取り消す」（取消は確認あり）
   - ●: 「配置を変更する…」「配置を取り消す（訪問も削除）」（確認あり）
2. **「配置先を決める…」はダイアログ内で完結**: 本日稼働した「＋訪問」モーダルを **患者・日付固定・反映先「新しく 1 件追加」固定** で開く。提案（時刻を入れると入れるコースを提示・0 件なら自拠点 M）はそのまま流用。登録後に ○ を ● にする。
   - BE: `POST /special-visit-marks/{id}/place` に `course_template_id`（M を含む・Course 未生成なら作る＝8/31 案 F-2）と `start_time` を追加。または place-and-fix の結果 `visit_id` でマークをリンクする小 API。どちらかで **M 受け皿**が特別枠にも効く。
3. **凡例と次の一手を常時表示**: 「○ 未配置 → クリックで配置先を決める／● 配置済み」＋「未配置の ○ は N 件（このダイアログから配置できます）」。
4. 「期間を終了する」はメニュー（…）に格納し確認を付ける。○ の取消も確認。
5. セルと文字の基準は `add-visit-anywhere-design.md` §3-5（14px・行全体クリック）に合わせる。

### 3-3. プール側（併用）

- 列の外で離したときは「列の上で離してください」を出す。

### 追跡事項
1. **入替の 1 トランザクション化（BE）**: 「配置を変更する…」は新訪問を作ってから旧を消すため、**同じ時刻のまま**の入替は一意制約で失敗する（FE で事前案内: 時刻を変えるか取り消してから）。BE `place` に「既配置マークへの visit_id 指定＝旧訪問を削除して差し替え」を 1 トランザクションで実装すれば解消。
2. **過去日ガードの適用範囲（PO 判断）**: 新 2 モードのみ適用中。既存のプール ⭐ 経路（course_code）と place-and-fix には過去日ガードが無い。過去週の入力運用（実績合わせ等）を踏まえて統一方針を決める。
3. **実機確認**: モーダル Dialog の中の Popover メニュー（Radix の入れ子）はテストでは Dialog をモックしているため、本番でクリック/フォーカスを 1 度確認する。
