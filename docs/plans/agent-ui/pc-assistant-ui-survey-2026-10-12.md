## 0. 結論（先に）

- PC Assistant の「感じ」の正体は 4 つ：**(1) 枠なし・角丸・影つきの 420px 幅の小窓が作業領域の右下に下端固定で置かれ、上へ伸びる**、**(2) 1 回のやり取りを小窓の中で完結させる（状態ごとに中身が 1 つ：待機→作業中の 1 行→質問カード→確認カード→結果カード）**、**(3) 普段は普通の窓で、答えが要る時だけ最前面＋縁が一度光る・フォーカスは奪わない**、**(4) しまってもトレイの点・Windows 通知・Ctrl+Alt+A で戻れる**。
- (2) は**ブラウザーで 100% 再現できる**（中身の設計の話。スマホ PWA `PH\app.js` が HTML/JS で既に同じことをしている）。
- (1)(3)(4) の「**ほかのアプリの上に浮く**」「**画面の右下に寄せる**」「**トレイ・全体ホットキー・Windows 起動時に起動**」は**ブラウザーのページ単体ではできない**。
- おすすめの段取り【推測】：
  1. **まず (a) らく助のページ内の右下ウィジェット**（全ページ共通の `AppShell` に載せる）。らく助の画面で作業しながら隅のエージェントに頼む、という PO の使い方の 8 割はこれで足りる。EXE 不要。
  2. 「らく助以外のアプリ（カイポケ・Excel）を見ながら頼みたい」が本当に要るなら、**(b) Document Picture-in-Picture**（Chrome/Edge のみ、ボタン 1 押しで最前面の小窓に切り出す）を**追加の機能**として足す。EXE 不要だが制約が多い（§5.2）。
  3. 「Windows 起動時から常に右下にいる」「Ctrl+Alt+A で呼ぶ」まで PC Assistant と同じにしたいなら、**(d) 薄いデスクトップ殻（Tauri か WPF＋WebView2）で同じ Web UI を包む**。その場合も中身は (a) と同じ React 部品を使い回す。
- 結論の一行：**EXE は必須ではない。ただし「ほかのアプリの上に常に浮かぶ」を完全に再現したい時だけ EXE（薄い殻）が要る。**

### 1.2 位置の決め方【事実】
- **右下に寄せる**：保存した位置が無い・画面外なら `left = 作業領域.Right − Width + 16 − 4`、`bottom = 作業領域.Bottom + 16 − 4`（影の余白を外へはみ出させ、見える板が作業領域の端から 4px）（`APP\MainWindow.xaml.cs:308-315`）。
- **作業領域＝タスクバーを除いた範囲**：`NativeWindows.WorkArea` / `WorkAreaAt`（`MonitorFromPoint`＋`GetMonitorInfo` の rcWork）（`APP\NativeWindows.cs:95-130`）。→ タスクバーの上に置かれ、重ならない。
- **下端を固定して上へ伸びる**：`KeepBottomAnchored()` が `Top = max(作業領域.Top − 16, _bottom − 高さ)`、`MaxHeight = _bottom − 作業領域.Top + 16`（`MainWindow.xaml.cs:337-372`）。やり取り部分は「作業領域の 50%（160〜560）」で頭打ちしてスクロール（`UI\CompactUi.cs:94`、`ExchangeCap` 103 行）。
- **ドラッグで動かせて覚える**：見出しの `MouseLeftButtonDown`（`MainWindow.xaml:725-726`、Cursor=SizeAll）。覚えるのは左端と下端（`window.json`、`SavePlacement` `MainWindow.xaml.cs:374-` 付近）。
- **マルチモニター・DPI**：仮想画面の範囲で保存位置を検査（`MainWindow.xaml.cs:308-312`）、`DpiChanged` で下端を取り直す（119-126 行）。詳細の窓は物理ピクセルで角を覚え、混在 DPI でもモニターを特定（`DESIGN.md:268-274`）。大きくした面は「最も重なるモニター」の 88%（`AgentFrame.MonitorOf`）。
- タスクバーには出さない `ShowInTaskbar="False"`（`MainWindow.xaml:15`）→ 戻り道はトレイ・Ctrl+Alt+A・二重起動。

## 2. 小さい面積に会話を収める工夫（Interaction design）

正典は `PA\NEXT_PLAN.md` A1〜A10 と `PA\DESIGN.md` §3a（232-321 行）・§3d（927-1010 行）。オーナーの要望は「**入力欄の大きさのまま、やり取りを全部その中で終える**」（`NEXT_PLAN.md:5`）。

### 2.1 小窓：状態ごとに中身は 1 つ【事実】（`DESIGN.md:238-246`、`UI\CompactUi.cs:152`）

| 状態 | 小窓に出るもの | 実測の高さ（板・100%） |
|---|---|---|
| 待機 | 例のチップ、「頼みたいこと」、続きチップ、添付、入力、［頼む］ | 244 |
| 作業中 | 依頼の要約＋［詳細］／**生きた 1 行**（くるくる・いまの手順を平易な日本語で・「4/7」や「57 手順目」・経過時間・細い進み具合の線）／「＋ 終わったら続けて頼む」／［止める］ | 211 |
| 質問 | 「教えてください」カード：本文 3 行まで、答え 1〜4 をボタン（数字キー可）、長い本文・5 つ目以降は「ほかの答え」に畳む | 264 |
| 確認 | 「実行する前に確認します」カード：**1 行の見出し**＋小さな副行（「ほか N 件」）、［承認］（既定ボタン）／［やめる］／⋯（この頼みでは確認しない）、［中身を見る］で全文（最大 150px スクロール） | 272 |
| 結果 | 答えの最初の 1〜2 行＋かかった時間＋［全文］［詳細］［×］、覚える／覚えないの提案。下に入力が戻り「続き」チップ | 349 |
| 失敗／止めた | 赤いカード・「止めました（N 手順目 まで）」 | 324 / 321 |

- 目標は「作業中 ≤ 待機＋40px、質問・確認・結果 ≤ 待機＋120px」（`NEXT_PLAN.md` A8）。**会話の履歴は小窓に積まない**：手順の全履歴は横に出す「詳細の窓」へ（`DESIGN.md:262-284`）。
- 道具の名前は画面に出さず、日本語の作業行にする（`DESIGN.md:204-206` の対応表）。
- **フォーカスを奪わない**：カードが来たら縁が光るだけ。窓に既にフォーカスがある時だけ最初の答え／承認へ移す。カードは出てから 400ms は押せない（誤爆防止）、押しっぱなしの Enter や数字では答えない（`DESIGN.md:254-257`）。
- 作業中に思いついたことは「＋ 終わったら続けて頼む」で控えておき、終わったら入力に入れる（途中で割り込まない）（`NEXT_PLAN.md` A7）。
- 入力の例文（灰色）は空・フォーカスなし・IME 変換中でない時だけ（`DESIGN.md:260-262`）。

### 2.2 縦長の面（エージェント＝会話型）【事実】（`DESIGN.md:946-970`、`UI\AgentChat.cs`）
- 上から：見出し（アイコン・名前・切り替え・📁・⤢・📌・─）／係の行（名前▾・新しい会話・「● 作業中 1:42」点滅＋止める・モデル）／フォルダーの行／会話／入力（「エージェントへ」、＋、🎤、送る）。
- 会話の部品：
  - 自分の発言＝右の淡い青の吹き出し、添付は小さなチップ、「送信待ち／順番待ち」。
  - エージェントの文＝左、**畳まない・切らない**、Markdown（表・コード＋コピー・リンク）。
  - **作業行**＝1 行ずつ（状態の印 くるくる→✓／⚠／■、道具のアイコン、日本語、灰色の補足「212 行」「+5 −2」、経過時間、30 秒無反応で「応答を待っています」）。押すと差分・出力・サブエージェントの行。
  - **作業のかたまり**＝文と文の間の作業行。ターンが終わると「✓ 作業 N 手順・M 秒 ▸」の 1 行に畳む。**⚠ は畳まない**。
  - 質問カード（AskUserQuestion）：見出しチップ、番号つきの選択肢、複数選択、「ほかの答え」。1 問・単一選択なら 1 押しで答える。
  - お知らせ行（薄い「12 秒」「止めました」、琥珀の注意、赤＋ボタン「再開」「サインイン」）。
  - 生きた行（最後尾）：「考えています… 0:08」「混み合っています・再試行中」「あなたの答えを待っています」「順番待ち（同時に 3 つまで）」。
  - 「前の会話（N 件）▸」で過去を畳む。
- 描画の工夫：流れてくる文は 1 秒 4 回まで、最後の段落以降だけ作り直す（20,075 字で 1,089ms→79ms、`DESIGN.md:1002-1004`）。

- `app.js`（7,093 行、素の JS・IIFE）。**DOM を `textContent` だけで作る**（エージェントの文を HTML として解釈しない）（`PH\app.js:1-3`）。`file://`＋`window.PCA_FIXTURE` で固定データのプレビューができる。
- 状態は 1 つの `S` オブジェクト、変わらない部品は `R` にとっておき**会話は差分で直す（作り直さない）**（`app.js:9-31`）。
- 通信：読む＝`GET /api/state`・`/api/agents/{id}`、書く＝`POST /api/...`、流れ＝**SSE `EventSource("/api/events")`**（イベント `ping` 20 秒ごと・`changed`・`assistant`・`live`・`shot`・`rec`）。切れたら 3→30 秒のバックオフで張り直し、張り直すたびに状態を読み直す（`app.js:1376-1420`）。オフライン時は「PCが見つかりません」＋確認項目＋［もう一度］（`app.js:34-41`）。

## 5. ブラウザーでできないこと・代わりの手

### 5.1 デスクトップ EXE とブラウザーの差

| PC Assistant の振る舞い | ブラウザーのページ単体 | 補足 |
|---|---|---|
| ほかのアプリの上に浮く（Topmost） | **できない**（ページはブラウザーの窓の中だけ） | (b) Document PiP なら可【一般知識・要確認】 |
| 画面の右下（タスクバーの上）に寄せる | **できない**（ページ内の右下なら可） | `window.open` の小窓は left/top を指定できるが最前面ではない。Window Management API（`getScreenDetails`、許可が要る）で画面の大きさは取れる【一般知識・要確認】 |
| 枠なし・透明・影 | ページ内なら CSS で完全に可 | 別窓（PiP・ポップアップ）はブラウザーの枠が付く |
| トレイのアイコンと点 | **できない** | インストールした PWA ならタスクバーのアイコンに数字（Badging API `navigator.setAppBadge`）【一般知識・要確認】 |
| 全体ホットキー（Ctrl+Alt+A） | **できない**（ページにフォーカスがある時のキーだけ） | — |
| Windows 起動時に起動 | **できない** | Chrome/Edge の「サインイン時にアプリを起動」設定がインストール済み PWA にある【一般知識・要確認】 |
| 通知（トースト） | **できる**：Notification API／Web Push（許可が要る、ブラウザーが動いていること） | Windows の通知センターに出る【一般知識・要確認】 |
| フォーカスを奪わずに知らせる | ページ内：縁を光らせる・タブのタイトルに「(1)」・ファビコンに点、で代用可 | — |
| 質問・確認の時だけ前に出す | 不可（ブラウザーの窓を前に出す API は無い）。通知を押すと前に出る | — |

### 5.2 代わりの手の比較

**(a) らく助のページ内の右下ウィジェット**【推測：設計案】
- `frontend\app\(app)\layout.tsx` → `components\AppShell` に 1 つ置けば全ページに出る（ログイン済み・同じオリジン・同じ認証）。ページを移っても会話は消えない（SSE は AppShell の中で 1 本）。
- 状態：**閉じた丸（マスコットの顔＋未読の点）** ⇄ **小窓（幅 400 前後・下端固定で上へ伸びる、最大は画面の高さの 50〜60%）** ⇄ **大きく（右側のドロワー 1/3〜1/2、または全画面の /agent ページ）**。
- 長所：EXE 不要・作るのが一番軽い・らく助の画面を見ながら頼める（「この週を直して」→ 開いている週の画面がそのまま変わるのが見える）。らく助の画面の文脈（いま開いている週・職員）をエージェントに渡せるのはページ内ならではの利点。
- 短所：らく助のタブを閉じる・ほかのアプリに切り替えると見えない（通知で補う）。
- PC Assistant との一致度：中身（§2）は 100%、「いつも隅にいる」感じは**らく助を開いている間だけ**。

**(b) Document Picture-in-Picture API**【一般知識・要確認】
- `documentPictureInPicture.requestWindow({ width, height })` で、**ほかのアプリの上に常に浮かぶ小さな窓**を作り、そこへ React の部品を移す（同じ JS の文脈なので状態・SSE をそのまま共有できる。CSS は複製して入れる）。
- 制約：
  - **Chrome / Edge のデスクトップ版のみ（116 以降）**。Firefox・Safari・スマホは不可。
  - **利用者の操作（クリック）の直後でないと開けない**。ページを開いた時に自動で出すことはできない＝毎回［小窓で出す］を 1 押し。
  - **開いた元のタブを閉じる・別ページへ移る（全面再読み込み）と PiP も閉じる**。Next.js のクライアント内遷移なら残る見込みだが、要実測。
  - 1 つのタブから 1 つだけ。位置はブラウザーが決める（既定は画面の右下付近・利用者が動かした位置を覚えるとされる）。ページから自由には動かせない。大きさには上限がある（画面に対する割合で制限）。
  - アドレスバーは無いが、ブラウザーの細い枠と閉じるボタンが付く。枠なし・透明・角丸の窓にはならない。
  - PiP の窓の中から別の URL へは移れない。ファイル選択・通知などは使えるが一部の挙動が異なる可能性。
- 長所：**EXE なしで「ほかのアプリの上に浮く」に一番近い**。カイポケや Excel を見ながら頼める。
- 短所：毎回 1 押し・Chromium だけ・元のタブに縛られる。会社の PC で Chrome/Edge が使えるなら実用範囲【推測】。

**(c) インストールした PWA の小さな窓**【一般知識・要確認】
- らく助は既に PWA の殻を持つ（`frontend\public\sw.js`、`app\manifest.ts`）。`/agent` 専用の小さな PWA（`display: standalone`）を作り、`window.resizeTo/moveTo` で右下へ置く（アプリ窓ではこれが効く場合がある）。
- **最前面にはならない**（PWA に always-on-top の仕組みは無い。Isolated Web Apps 向けの提案はあるが一般の PWA では使えない）。
- タスクバーにアイコンと未読の数字（Badging API）、サインイン時の自動起動（ブラウザーの設定）、通知は可。
- 評価：「タスクバーから 1 押しで出せる小さな窓」としては良いが、PC Assistant の「隅に浮いている」感じには届かない。(a)(b) の補助。

**(d) 薄いデスクトップの殻（Web の UI をそのまま包む）**【推測】
- 中身は (a) と同じ React の画面（例：`/agent?shell=1`）を読み込むだけ。殻がやるのは **最前面・右下に寄せる・タスクバー回避・トレイ・全体ホットキー・自動起動・トースト**だけ。
- 候補：
  - **Tauri**（Rust＋OS の WebView＝Windows では WebView2）：数 MB、`always_on_top`・枠なし透明・トレイ・グローバルショートカット・自動起動・通知のプラグインがそろう。Mac にも出せる【一般知識・要確認】。
  - **WPF＋WebView2**：PC Assistant のノウハウ（右下の置き方 `MainWindow.xaml.cs:270-372`、Topmost の決まり、トレイの点、Ctrl+Alt+A、通知の条件）を**ほぼそのまま移せる**。PC Assistant 自体が WebView2 を使っている（`PA\src\PCAssistant.Core\PCAssistant.Core.csproj:14-15`）。Windows 専用。
  - Electron：一番楽だが 100MB 超・更新の手間【一般知識】。
  - **PC Assistant 本体に「らく助」の係として載せる**：PC Assistant の係は MCP を足せる（前回の調査 §4.4）ので、らく助の MCP を公開すれば PC Assistant の小窓から頼める。ただしお客様に PC Assistant（Windows 専用・大きい）を入れてもらう前提になる。
- 認証：殻の WebView で らく助にログイン（Cookie を殻の profile に保存）。Cloudflare Tunnel 越しでも普通のブラウザーと同じ【推測】。
- 長所：**PC Assistant と同じ感じを完全に再現**。短所：配布・署名・更新・会社 PC へのインストール許可が要る。

### 5.3 どれが PC Assistant に一番近いか

| 案 | 他アプリの上に浮く | 右下に寄せる | トレイ/ホットキー/自動起動 | 通知 | EXE | 作る量 | PC Assistant らしさ |
|---|---|---|---|---|---|---|---|
| (a) ページ内ウィジェット | × | ○（ページ内） | × | ○（Web 通知） | 不要 | 小 | 中身◎・常駐△ |
| (b) Document PiP | ○（1 押し後） | △（ブラウザー任せ） | × | ○ | 不要 | 小（(a) に足す） | ○ |
| (c) PWA の小窓 | × | △ | △（バッジ・自動起動のみ） | ○ | 不要 | 小 | △ |
| (d) 薄い殻（Tauri/WPF） | ○ | ○ | ○ | ○ | **要** | 中 | ◎ |

**おすすめ【推測】**：**(a) を本体として作り、(b) を「小窓で出す」ボタンとして足す**。これで EXE なしに「らく助を開いていれば右下にいる」「必要ならほかのアプリの上にも浮かべられる」までいける。使ってみて「起動時から常にいてほしい」「Ctrl+Alt+A が欲しい」が出たら (d) を後から足す（中身の React 部品は共通なので無駄にならない）。

## 6. らく助で作る時の UI 仕様の叩き台（PC Assistant から写すもの）【推測】

1. **3 つの大きさ**：丸（56px・マスコット・未読の点／待ちの琥珀の点）→ 小窓（幅 400、下端 16px・右端 16px、上へ伸びる、やり取りは画面の高さの 50% で頭打ち）→ 大きく（右ドロワーか /agent ページ）。PC Assistant の 420/640/88% に相当。
2. **小窓は状態ごとに中身 1 つ**（待機／作業中の 1 行／質問カード／確認カード／結果カード）。履歴は「詳細」か「大きく」で見る。
3. **作業行は日本語の 1 行・終われば「✓ 作業 N 手順・M 秒 ▸」に畳む・⚠ は畳まない**。
4. **確認カード**：1 行の見出し（「週 43 の訪問 12 件を動かします」）＋「ほか N 件」＋［承認］既定・［やめる］・［中身を見る］（差分表）。らく助では「案 → 確認 → 反映 → 取り消し」（構想 §4）の確認がここ。
5. **知らせ方**：小窓が閉じている／らく助のタブが裏の時は、丸に点・タブのタイトル「(1) らく助」・Web 通知（作業完了・承認待ち）。**勝手に開かない・フォーカスを奪わない**（PC Assistant D72 の学び）。
6. **カードの誤爆防止**：出てから 400ms は押せない、Enter 押しっぱなしで答えない。
7. **キー**：Esc＝止める／やめる、1〜n＝選択肢、Ctrl+Enter＝送る。ページ内の呼び出しキー（例 Ctrl+K や Alt+A。ブラウザーの既定と被らないもの）。
8. **色**：意味の色（青＝作業・質問、琥珀＝承認待ち・注意、赤＝失敗、緑＝完了）は PC Assistant と同じ考え、主色はらく助のピンク。トークン名は PhoneTheme の kebab-case（`--ink` `--accent` `--amber-bg` `--r-card` …）を参考に CSS 変数で。
9. **マスコット**：状態で表情を変える（作業中＝think、質問＝puzzled、承認待ち＝idea、完了＝cheer/clap）。PC Assistant には無い、らく助の強み。
10. **安全**：エージェントの文は HTML として描かない（スマホ版の `textContent` 原則／React なら `dangerouslySetInnerHTML` を使わない）。
