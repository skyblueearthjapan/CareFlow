# らく助エージェント — 構想（下書き・2026-10-12）

状態: **下書き・PO と議論中**（実装・本番操作はまだしない）
調査: `pc-assistant-survey-2026-10-12.md`（PC アシスタントの仕組みと実現性）

## 1. ねらい（PO 2026-10-12）
- 管理者がエージェントに相談・依頼してスケジュールを回せるようにする。例:
  「この人が休みになったので反映して」「その上で職員スケジュールを作って」「コーススケジュールを事前に最適化したいので相談に乗って」「急に特別訪問週間が入ったので反映して」「この週は人が足りていない、と教えてほしい」
- 二段の考え方:
  - **コーススケジュール** = 事業所の全員が休みなく稼働できると仮定した最適（型）
  - **職員スケジュール** = 急なキャンセル・特別訪問週間・欠勤・余剰など、週の間際や週に入ってからの変化に合わせる
- 将来はお客様側でもエージェントを使い、スクリプト・スキルで最適化と自動化を進める。

## 2. 形（PO 決定の方向）
```
お客様のブラウザ ── URL（らく助の中の「エージェント」ページ。らく助の見た目）
      │
VPS ┌ らく助（今のアプリ：Next.js + FastAPI + Postgres）
    └ エージェントの部屋
         ├ Claude Code の CLI（または Codex の CLI）を常駐させる
         ├ スキル一式（VPS 上に置き、git で更新）
         └ 中継: CLI の入出力 ⇄ ブラウザ（文字・承認ボタン・進み具合）
```
- CLI は VPS のターミナルで動かす。画面は URL で出すだけ。
- 公開は既存の Cloudflare Tunnel（らく助と同じドメイン・らく助のログインで入る）を第一案。Tailscale は予備。
- スキルは VPS 上に 1 か所。更新は VPS で `git pull` するだけで全員に効く（お客様の PC へ配る必要がない）。
- アカウント（誰の契約で CLI を動かすか）は**後で決める**。試作の間は VPS 上の CLI に 1 つのアカウントでサインインして使う。

## 2-2. 画面（PO 要望 2026-10-12: 右下の小さな窓口）
- 画面いっぱいではなく、**右下の小さな窓**にエージェントがいて、主の画面で作業しながら頼める形。
- 手本: PC アシスタントの小窓（調査 `pc-assistant-ui-survey-2026-10-12.md`）。幅 420px・右下から上へ伸びる・小／縦長／拡大の 3 段・一度に 1 つ（待機／今していること 1 行／質問／承認／結果）・作業手順は終わると 1 行に畳む・色の意味は 青=作業中/質問・琥珀=承認待ち・赤=失敗。スマホ用 Web 画面（`Resources\phone`）がそのまま画面仕様になる。
- 作り方（案）: **(a) らく助の全ページ右下に浮かぶ窓を基本**＋**(b) 「小窓で出す」ボタン（Document Picture-in-Picture・Chrome/Edge）で他のアプリの上にも浮かせる**。EXE で包む (d) は要望が出てから（中身の Web 部品はそのまま使える）。
- らく助のマスコットとピンク（#e15a7f）を使う（PC アシスタントにはマスコットが無い）。

## 2-2b. 出す場所と人（PO 2026-10-12）
- **らく助と同じ URL**（`carelink.kaipoke-api.net`）の中に置く。別の URL・別のログインは作らない。AppShell に 1 回置き、どのページでも右下にいて会話が続く。
- **管理者（admin）だけ**に出す。職員のスマホ画面（/m）・現場ボードには出さない。
- 裏の中継は同じドメインの別の道（例 `/agent/…` → エージェントの部屋のコンテナ）。案の HTML の表示だけは安全のため別オリジン（例 `preview.` のサブドメイン）か sandbox iframe にする（利用者が意識する必要はない）。

## 2-3. 案（成果物）を広げて見る（PO 2026-10-12）
- 反映の前に、エージェントが案を出し、**HTML の案を大きく見て**から反映する。
- 並びは PC アシスタントの成果物の欄と同じ: **会話は左に残し、窓を左へ広げて右側に案の欄**（A4 縦・A3 横の幅が見える）。スマホでは全画面。
- 欄の下端に「この案で反映する／やめる／直してほしい所を書く」。会話の承認カードと同じ承認を指す（先に押した方）。作り直した案は「案 1／案 2」のタブで見比べ、反映は最新の案から。
- 案の HTML はエージェントに書かせず、エージェントが渡すデータ（誰を誰へ）から**らく助のサーバーが決まった様式で作る**（安全・見た目がそろう）。表示は別オリジン or sandbox iframe。
- 調査: `pc-assistant-artifact-view-survey-2026-10-12.md`。モック: `docs/mockups/rakusuke-agent-widget-mock.html`。

## 2-4. Claude と Codex の両方（PO 2026-10-12）
- PC アシスタントと同じく、**Claude Code の CLI と Codex の CLI のどちらでも動く**ようにする。中継は両方の出力（`claude -p --output-format stream-json`／`codex exec --json` または `codex app-server`）を同じ画面用の形に揃える。
- スキル・らく助の道具（MCP）は両方から同じものを使う。画面では「AI: Claude／Codex」を選べる。

## 3. 中継のやり方（案）
| 案 | 中身 | 長所 | 短所 |
|---|---|---|---|
| A（推奨） | CLI を `claude -p --input-format stream-json --output-format stream-json` で常駐させ、やり取りをデータで受け渡す（PC アシスタントのエージェント窓と同じ） | らく助の見た目で、承認・質問・進み具合を画面の部品として出せる。PC アシスタントで実測済みの使い方を流用できる | 中継の部品を作る必要がある |
| B | ターミナルの画面をそのままブラウザに映す（Web ターミナル） | 作るものが最小 | 見た目がターミナルのまま。承認も文字入力。お客様向きではない |

B は開発・保守用（私たち向け）として持ってもよい。

## 4. 安全の決めごと（案）
- エージェントの部屋は、らく助本体と分けたコンテナ／Linux ユーザー。
- 渡さないもの: 本番の `.env`、Docker、データベースへの直接接続、シェルでの任意のコマンド。
- できること: **らく助の窓口（API）を、その管理者の権限で呼ぶこと**と、スキルの中の決まったスクリプトだけ。
- 書き込みは「案 → 確認（画面で承認） → 反映 → 取り消し」の順。操作はすべて記録。
- ログイン情報の書き換え・送信先の変更を防ぐ隔離設定（PC アシスタントの `isolation.json` の考え方）。
- 患者さんの個人情報が AI に送られる点は、お客様の了承と契約を別途確認する。

## 5. 作る順番（案）
1. **窓口（API）**: エージェント用の鍵、読むための窓口（週・職員・患者・固定訪問・希望・休み・特別訪問週間・カイポケとの差分）、案をまとめて反映・取り消す窓口。
2. **コースのならし**（新規）: 赤（固定）を先に置き、残りは希望の幅の中でコースへ割り振る（`../red-pin-simplify-design.md` と合わせる）。まず案を出すだけ → 窓口から反映。
3. **職員のならし**を窓口経由に移す（今は SSH でデータベースを直接読んでいる）。
4. **スキル集**: 休み・特別訪問週間・職員スケジュール作成・コースの相談・人が足りない日の指摘・カイポケとの差分。
5. **エージェント画面と中継**（§3 案 A）。まず私たちだけで試し、その後お客様 1 か所で試す。

## 5-2. 進め方（PO 了承 2026-10-12「あなたの提案で」）
1 本の筋を端から端まで先に通す。最初の筋は **「職員が急にお休み → 振り分け案 → A4/A3 で見る → 反映 → 元に戻す」**。
| 段 | やること |
|---|---|
| 1 | 窓口と案の仕組みの最小限（鍵・読む窓口・案の保存・A4/A3 の作成・反映・取り消し）＋職員のならしをサーバー側で動かす |
| 2 | スキル「休みを反映」。まず私たち自身がターミナルの Claude Code から使う（週の運用に使いながら育てる） |
| 3 | 小窓の画面と中継（まず Claude、次に Codex）。**試験用の環境（本番の写し）**で動かす |
| 4 | 残りのスキル（人手の確認・特別訪問週間・カイポケとの差分） |
| 5 | 赤ピンの整理（`../red-pin-simplify-design.md`）とコースのならし |

- 各段は 設計メモ → PO 了承 → 実装（別担当レビュー）→ pg_dump → 反映 の順。

## 6. 決めていないこと

- 同時に何人が使うか（1 人ずつ部屋を分けるか、1 つの CLI を順番に使うか）。
- 試作をどこで動かすか（本番の VPS か、別の環境か）。
