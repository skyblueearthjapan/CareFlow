## 0. 結論（先に）

- PC Assistant は**成果物を「別の窓」にも「全画面」にもしない**。会話の窓そのものを**左へ広げて、右に成果物の欄を足す（2 列の分割）**。会話は残ったまま、✕ で元の大きさにぴったり戻る。スマホ版は**下から 92% のシート**（後ろの会話は暗くなる）。
- 成果物は**ターンの後に「作った・直したファイル」を探して、会話にチップ（名札）として並べる**。押した時だけ欄が開く。表示中のファイルは見張られ、エージェントが書き直すと 0.5 秒後に**同じスクロール位置で描き直す**。版の履歴・タブはない（1 度に 1 ファイル）。
- 承認（許可カード）と成果物の表示は**つながっていない**。「見てから承認する」流れは PC Assistant には無い → らく助では新しく作る所。
- 安全面は徹底している：エージェントの HTML は**スクリプトは動かすが、外への通信・別ページへの移動・ダウンロード・印刷・権限要求は止める**。スマホ（＝本物の 1 つのオリジンを持つ Web）では **`sandbox="allow-scripts"`（allow-same-origin なし）の iframe＋CSP `sandbox` ＋ `frame-ancestors`＋ HMAC 鍵つき URL**。らく助（ログイン済みのアプリと同じオリジン）では、これをそのまま真似るのが最低線。
- **らく助への案**：小窓（400）→ 縦長（460）→ **「案を広げる」＝画面右側に“会話 380 ＋ 案 A4 の欄”の 2 列ドロワー**（スマホは全画面シート）。案の欄の**下端に「反映する／やめる」を固定**し、会話のカードと同じ承認を両方から押せる。HTML は**別オリジン（例 `preview.<ドメイン>`）か `srcdoc`＋sandbox iframe**で出す。

## 5. 安全の作り（らく助に効く所）【事実】

PC（`DESIGN.md:1724-1813`、`CORE\Ui\ArtifactWeb.cs:73-84`）
- オーナー判断：**スクリプトは ON、外へのアクセスは OFF**（`DESIGN.md:1724`）。
- エージェントごとに**別のオリジン**（`https://a<フォルダーの SHA-256 先頭 16 桁>.pcassistant.local/`）。localStorage・Cookie が混ざらない。アプリの閲覧用スクリプトは別オリジン `app.pcassistant.local`（`DESIGN.md:1758-1762`）。
- 全リクエストを自前で答える（パスの検査・リンク禁止）。エージェント HTML の CSP：`default-src 'self' data: blob:; script-src 'self' 'unsafe-inline' 'unsafe-eval' …; connect-src 'self'; worker-src 'none'; object-src 'none'; form-action 'self'; base-uri 'self'`（`ArtifactWeb.cs:73-76`）。閲覧ページは `script-src` をアプリのオリジンだけ（`ArtifactWeb.cs:82-84`）。
- 抜け道対策：死んだプロキシで WebSocket/WebRTC も外へ出さない、`RTCPeerConnection`・`Worker`・`serviceWorker` を消す、`<link rel=preconnect>` での持ち出しも自己検査で確認、効かない環境ではスクリプトを止める（`DESIGN.md:1725-1757`）。
- ナビゲーション：外へは行かせない。人がリンクを押した時だけ「外のページを開こうとしています：<全アドレス>」を出し、［ブラウザーで開く］で初めて開く（`DESIGN.md:1781-1790`）。ダウンロード・画面共有・権限要求・印刷・alert/confirm は止める（`DESIGN.md:1772-1780,1791-1801`）。
- 正直な限界：「悪意あるページを書かれたら欄の中では変な動きをし得るが、ネットと PC には届かない」（`DESIGN.md:1811-1813`）。

スマホ（＝ Web。らく助と同じ条件）（`CORE\Phone\PhoneArtifacts.cs:6-13,403-426`、`PH:4146-4152`、`CORE\Phone\PhoneHub.cs:143-147`）
- ページは**本物のオリジン 1 つ**なので、成果物は **CSP `sandbox allow-scripts`（allow-same-origin なし）＝不透明オリジン**として配信し、iframe にも `sandbox="allow-scripts"`・`referrerpolicy="no-referrer"`。→ 親ページの Cookie・ストレージ・API に届かない。
- CSP はそのエージェントのパスだけを許可、`frame-ancestors <自分のオリジン>`、`form-action 'none'`、`worker-src 'none'`。
- 応答に `Access-Control-Allow-Origin` を**付けない**（sandbox のページが fetch でファイルを読めない。その代わり Word ビューアはスマホでは出ない）。sandbox からの API 呼び出しは Origin `null`・専用ヘッダー無しで門前払い。
- 成果物の URL に **HMAC 鍵**（実行ごとの秘密×エージェント ID）。あるページが知った自分の URL で別エージェントの物は開けず、再起動で無効。
- PDF だけは sandbox にしない（ブラウザーの PDF ビューアが開かないため）、代わりに `script-src 'none'`。
- アプリ本体の CSP は `script-src /app.js` だけ（前回調査 `pc-assistant-ui-survey` §PWA）。

## 6. らく助ウィジェットへの提案【提案】

### 6.1 形（モックの mini 300×64／compact 400×560／tall 460×全高 に 1 段足す）

| 形 | いつ | レイアウト |
|---|---|---|
| 丸・小窓・縦長 | 今のモックどおり | 右下固定 |
| **案を広げる（split）** | 案カードの「案を見る（A4）」・チップを押した時 | **右側ドロワー**：画面右端から `min(1240px, 100vw-32px)` 幅、上下 16px。**左＝案の欄（残り全部）／右＝会話 380px**（PC Assistant は「会話が左・欄が右」だが、らく助はウィジェットが右下にいるので**会話を右に残して、欄が左へ伸びる**方が「窓が左へ広がる」PC Assistant の動きと同じ見え方になる）。境目はドラッグ可（キーボード ←→ でも）、幅は localStorage に覚える |
| 大きく（全画面） | 欄の ⤢ | 欄が画面いっぱい、会話は右に 320px か畳んで「会話 ▸」 |
| スマホ（< 768px） | 同上 | **下から 92% の全画面シート**（PC Assistant のスマホと同じ）。下端に「反映する／やめる」固定、上端「会話に戻る ⌄」、下スワイプ・Esc で閉じる |

- 後ろのらく助の画面は**暗くしない（PC）**：反映前に「今の予定」と見比べたいはず。スマホだけ暗くする。
- ✕ で**押す前の形（縦長など）に正確に戻す**（PC Assistant の「元の矩形に戻る」）。
- 動きは幅・高さの transition 0.28s（モック既定）、`prefers-reduced-motion` で即時。

### 6.2 案の欄の中身

1. 見出し：バッジ「振り分け案」・題名（「10/22（木）田中さんの 5 件」）・「作成 14:03／更新 1 分前」・［新しいタブで開く］［印刷］・⤢・✕。
2. 版の切替（PC Assistant に無いので足す）：エージェントが作り直すと **「案 1 ／ 案 2（最新）」の小さなタブ**。前の版は読み取り専用で残す（会話で「さっきの方が良い」と言えるように）。反映は**表示中の版**に対して行い、版の ID をサーバーへ送る（古い案を誤反映しない）。
3. 本文：A4 ページ。既定は**「幅に合わせる」**（A4 794px を欄幅へ CSS `zoom`／`transform: scale`）、［100%］［幅に合わせる］の 2 つだけ。スマホは PC Assistant と同じ自動 1 通り（比 0.55 で判断）。
4. **下端に固定の帯：「反映する」（主ボタン）／「やめる」／「直してほしい所を書く」**（＝入力欄に「この案について：」を入れて会話へ。PC Assistant の「これについて頼む」）。会話のカードの「反映する」と**同じ承認 ID**を押す：どちらで押しても片方は「反映しました」に変わる（PC Assistant の「先に答えた方が勝つ」`AGENT_PLAN.md:164`）。
5. 生成中：骨組み（灰色の行）＋「案を作っています…」。失敗：1 行＋［もう一度］。古くなった（予定が先に変わった）：琥珀帯「この案を作った後に予定が変わりました。作り直しますか」→ 反映ボタンを止める。

### 6.3 案カード（会話側）との結び付け

- 案カードに表の要約（5 件程度）＋［反映する］［案を見る（A4）］［やめる］（モックの「A4 で見る」をこれに）。
- 案は**ファイル名ではなく「提案 ID」**で持つ：`proposal_id`・版・HTML（サーバー生成）・差分データ（JSON）・状態（待ち／反映済み／取りやめ／古い）。会話の記録に残し、後から開ける。
- 欄を開いたら、会話内の該当カードに「表示中」の印。欄を閉じるとフォーカスをカードのボタンへ戻す。

### 6.4 HTML の出し方（安全）— らく助はログイン済みアプリと同じオリジンなので最重要

推奨順：
1. **案の HTML はエージェントに自由に書かせず、サーバー（らく助の API）が決まったテンプレートで作る**。エージェントが渡すのは JSON（誰を誰へ）だけ。→ そもそもスクリプト入りの HTML が出ない。A4 の見た目も揃う。**これが一番効く**。
2. それでも iframe で出す時（エージェントが HTML を書く場合も含む）：
   - `<iframe sandbox="" referrerpolicy="no-referrer" title="振り分け案">`（スクリプト不要なら `allow-scripts` も付けない。付けるとしても **`allow-same-origin` と同時には絶対付けない**）。
   - 配信は**別オリジン**（例 `https://preview.<らく助のドメイン>/p/<proposal_id>/<版>?k=<HMAC>`）にし、Cookie を送らない。別オリジンを用意できない間は `srcdoc` ＋ sandbox（不透明オリジン）でも可。
   - 応答ヘッダー：`Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:; form-action 'none'; base-uri 'none'; frame-ancestors https://<らく助のオリジン>`（スクリプトを許すなら `sandbox allow-scripts` と `script-src 'unsafe-inline'` を足し、`connect-src 'none'`）。`Access-Control-Allow-Origin` は付けない。`X-Content-Type-Options: nosniff`。
   - URL は短命の HMAC 鍵つき（利用者×提案×版）。PC Assistant の `ArtKey` と同じ考え。
   - 親ページは iframe からの `postMessage` を**受けない**（反映ボタンは親側にだけ置く。iframe 内に「反映する」を置かない）。
3. 患者名が入るので、外のブラウザーへ渡す［新しいタブで開く］も同じ preview オリジン・鍵つき URL にし、印刷は `@media print` の A4 CSS をテンプレートに入れて親から `iframe.contentWindow.print()` …は sandbox で不透明オリジンだと呼べないため、**印刷は「新しいタブで開く」→ ブラウザーの印刷**に寄せる（PC Assistant も欄では印刷を止めてブラウザーに任せている）。
4. ダーク表示：A4 は紙なので**常に白地**（PC Assistant も「エージェントの HTML は作ったまま」）。欄の外枠だけテーマに従う。

### 6.5 キー・アクセシビリティ

- 欄は `role="region" aria-label="振り分け案"`（PC）／シートは `role="dialog" aria-modal="true"`（スマホ）。Esc で閉じる、閉じたらカードへフォーカスを戻す、Tab の閉じ込め（スマホのみ）。
- 境目のスプリッターは `role="separator" aria-valuenow` で ←→ 20px。
- 「反映する」は Enter に結び付けない（誤反映防止。モックは `data-k="Enter"` になっているので**欄側では外す**ことを推奨）。数字キー回答も承認には使わない（PC Assistant も許可カードは数字キーで答えない `AGENT_PLAN.md:164`）。

### 6.6 PC Assistant に無く、らく助で新しく決める所

- 版の保持と「どの版を反映するか」。
- 承認と表示の一体化（欄の下端の反映ボタン）。
- 「案を作った後に予定が変わった」検知（らく助のデータ版／更新時刻で比べる）。
- A4 の幅合わせ（PC Assistant はズーム任せ、スマホだけ自動）。
