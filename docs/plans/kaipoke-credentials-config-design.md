# 設計検討書：カイポケ ログイン情報の汎用化（アプリ内設定化）

作成 2026-07-07 / ステータス: **調査完了・設計たたき台（PO認識合わせ前・実装未着手）**
関連正典: `docs/plans/kaipoke-rpa-revival-HANDOFF.md` / `docs/plans/kaipoke-reverse-sync-design.md`

## 0. PO の意向（確認済み）

- ログイン情報（カイポケの認証情報）を**アプリの設定画面からユーザーが登録**できるようにする
- 初回にそれを設定すれば、カイポケ連携の全機能（展開・差分・反映・取り込み）が使える
- **ログイン情報だけが事業所ごとに変わる「データ」**になり、ロジック本体は
  全事業所共通のまま（カイポケ仕様に基づく共通実装）→ 他事業所への横展開が
  コード書き換えなしで可能になる

## 1. 現状調査（2026-07-07・確定事実）

- 認証情報は **3点**: `KAIPOKE_CORP_ID`（法人ID）/ `KAIPOKE_USER_ID` / `KAIPOKE_PASSWORD`
- 保管場所: RPA側コンテナの `/root/PlaywrightTest1/.env`
- **重大な副発見**: `login_action.py` の `os.environ.get(...)` の**デフォルト引数に
  実際の法人ID・ユーザーID・パスワードがハードコード**されている
  （= GitHubリポジトリ PlaywrightTest1 にログイン情報が入っている状態。private でも
  「コードに秘密が書いてある」問題。本対応で除去＋**カイポケ側パスワードローテーション推奨**）
- セッション: `state.json`（Cookie保存）。失効時は上記認証情報で自動再ログイン
- CareFlow側は認証情報を一切持っていない（Bearer トークンで kaipoke-api を呼ぶだけ）

## 2. 設計案（たたき台）

### 2-1. 保管 = CareFlow DB（暗号化）を唯一の正とする

- 新テーブル `kaipoke_credentials`: `corp_id` / `user_id` / `password_encrypted` /
  `updated_by_user_id` / `updated_at`。**当面1行**（1デプロイ=1法人の前提）だが、
  複数行を許すスキーマにして将来に備える
- 暗号化: 対称暗号（Fernet 等）。**鍵は `/opt/carelink/.env` に新キーとして置く**
  → DBバックアップ(pg_dump)が漏れても単体では復号不可（鍵とデータの分離）
- API は**パスワードを絶対に返さない**（設定済みか否か＋更新日時のみ返す・書き込み専用）。
  audit ミドルウェアの redaction 対象にフィールド追加

### 2-2. 受け渡し = ジョブ起動時にリクエストへ同梱（RPA側は永続保持しない）

- CareFlow バックエンドの `KaipokeClient` が expand / export / apply 呼び出し時に
  復号した認証情報を payload に同梱（同梱箇所は1関数に集約）
- RPA側 (`PlaywrightTest1`) の変更:
  - ジョブ payload の認証情報を優先使用（後方互換で env フォールバックは残す→
    移行完了後に env とハードコード既定値を削除）
  - `login_action.py` のハードコード既定値を**除去**
- 経路の安全性: 127.0.0.1 バインド＋Docker内部ネットワーク＋Bearer 必須（K-0bの3層は不変）。
  RPA側はメモリ上でのみ扱い、ログに出さない（api.log への credential 出力禁止を確認）

### 2-3. 設定UI（カイポケ連携画面に「接続設定」カード・admin専用）

- 入力: 法人ID / ユーザーID / パスワード（パスワードは type=password・保存後は
  「設定済み（YYYY-MM-DD 更新）」表示のみ・再入力で上書き）
- 未設定時: 連携画面の各操作ボタンを無効化し「先に接続設定をしてください」と案内
  （= PO要望「最初にその設定を行うことで利用可能に」）
- 「接続テスト」ボタン: 実ログインを1回試行（noVNCで目視可・~30秒）して
  成否を表示（RPA側に軽量な login-test 操作を追加）

### 2-4. 移行手順（本番）

1. UIで現行の認証情報を登録 → 接続テスト
2. 数ジョブを payload 経由で運用し安定確認
3. RPA側 `.env` の3キーとハードコード既定値を削除（コミット）
4. **カイポケ側でパスワード変更**（GitHub に載っていた経緯のローテーション）→ UIで更新

## 3. PO 確認事項

1. 設定の置き場所はカイポケ連携画面内の「接続設定」カード（admin専用）でよいか
2. 保存時の「接続テスト」（実ログイン試行・約30秒・noVNCで見える）を付けるか、

3. 実装完了後の**カイポケ側パスワードローテーション**を行うか（強く推奨）
4. 認証情報は 法人ID/ユーザーID/パスワード の3点で完結か（ほかに事業所ごとに
   変わる設定があれば教えてください）
