# 赤ピン（完全固定）の廃止 — 棚卸しのまとめ（2026-10-12・読むだけの調査）

> **【方針変更 2026-10-12・同日の議論】赤ピンは廃止せず残す方向。** ただし意味を「曜日と時刻だけの固定」に絞り、コース（担当職員）には紐づけない。
> 希望訪問スケジュールは「最初にお客様に聞いた余裕しろ」として残し、赤は「事情があって曜日・時刻を変えない」という管理者の意図を表す。
> 以下の棚卸しは「赤を読む／書く箇所の一覧」として引き続き有効（廃止ではなく意味の付け替え・整理に使う）。下の D1〜D8 は廃止前提の論点なので、方針変更後の論点に置き換える。

PO 方針（2026-10-12）: **赤ピン（`patient_fixed_visits.movability='locked'` とミラー `is_pinned`）をなくす。
動かせる範囲は希望訪問スケジュール（`patients.weekly_pattern`）で決める。動かせない患者は希望の幅をゼロにして表す。**
UI の修正漏れを出さないこと。設計を PO と合意してから設計書 → 実装に移る。

青ピン（`visits.week_pinned` / `manual_week`）はこの文書の範囲外。ただし絡む箇所は各報告の「青ピンとの絡み」に記録した。
コースと固定訪問の切り離し（PO 案）も別の論点として後で扱う。

## 分かった事実（要点）
- 赤が出る画面: 患者マスタの固定訪問、盤面（コース×日）、日／週タイムライン、日リスト、改善提案・見送り・範囲最適化・詰まり解消の文言、週次ガイド FAQ、管理画面の機能フラグ説明。
  モバイル・現場ボード・訪問モニター・コックピット・e2e には無い。
- 赤が 136/143 なのは **migration の名残ではない**（0065 で機械の赤は全部外れ、0067 時点で本番 1 件）。10/3 の枠の作り直しで人が付けた可能性が高い。本番で確かめる SQL は `4-docs-tools.md` §7（未実行）。
- ならしの道具は赤を読まず、すでに希望の時間帯で動かしている（PO 10/3 判断 D-1）。
- 提案系 3 エンジンは青ピンも読んでいない。赤を外すと、それらが既存の訪問を守る仕組みは無くなる。
- 改善提案は 2 名体制を除外していない（片方だけ動かす提案が出得る）。撤去と同時に除外を足す。
- 固定訪問の保存と見送りの受け口は未知の項目を 422 で拒否する（`extra="forbid"`）→ リリース順に注意。
- 関連テスト 32 ファイルは今すべて成功（SQLite・1 本 skip）。
