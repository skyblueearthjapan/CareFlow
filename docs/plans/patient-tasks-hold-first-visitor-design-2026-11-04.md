# やることを「最初に訪問した看護師が預かる」— 設計（2026-11-04・相談中）

PO：今泉さん。モック：`docs/mockups/patient-tasks-hold-first-visitor-mock.html`。
前の設計：`patient-tasks-design-2026-11-01.md`（やること）、`patient-tasks-recurring-design-2026-11-02.md`（毎月）、`patient-tasks-due-design-2026-11-04.md`（期日と何回目）。

## 1. きっかけ

11/4 13:56 小林様（Slack）：

- GAF は、その月の初回に訪問した看護師さんに付けてほしい。
- タスクを他の人に持ち越さず、初回に訪問した看護師さんに残しておけるか。
- 期日は、初回の訪問がいつになるか分からないため「期日なし」でよい。

今の仕組みでは、済んでいないやることは看護師に関係なく、その方の次の訪問へ移る。
看護師が完了にできるのは「そのやることが出ている、今日の自分の訪問」からだけ。

## 2. 決まったこと（PO 2026-11-04）

| # | 内容 |
|---|---|
| a | 「最初に訪問した看護師が預かる」は **項目ごと** に決める（項目の設定に印）。毎月の分・手で付けた分・今ある分がそろって同じ動きになる |
| b | 預かるのは、その訪問の **主担当だけ**（2 人目・同行・指導役は預からない） |
| c | 期日は付けない（GAF の毎月の設定は「なし」のまま） |
| d | 進め方は設計＋動くモックで判断してから実装する |

## 3. 動き（案）

印の付いた項目のやることについて：

1. 最初の訪問が終わるまでは、今と同じ。日付（この日から）以降の最初の訪問に出る（「1 回目の訪問待ち」）。
2. 最初の訪問の予定の終わりの時刻が過ぎて、まだ済んでいなければ、その訪問の主担当が **預かる**。
   - 「最初の訪問」は、日付以降の、取消・削除でない訪問のうち、予定の終わりが過ぎた最初のもの。主担当が決まっていない訪問（担当なし）は飛ばす。
   - 預かる人は保存せず、毎回の計算で決める（今の「出す訪問」と同じ考え方）。あとで最初の訪問の担当を替えたり取り消したりしても、自動で合う。
3. 預かったあとは、ほかの訪問には出さない（同じ看護師の次の訪問にも出さない。重ねて出さないため）。最初の訪問の詳細には「預かり中」で残る。
4. 預かった看護師は、訪問がなくても完了にできる。完了の訪問は最初の訪問として記録する（`done_visit_id`）。
5. 管理者は今までどおり、いつでも完了・取り消しできる。

## 4. 変える場所

### DB（migration 0107）
- `task_item_types.hold_by_first_visitor`（boolean・NOT NULL・既定 false）。

### backend
- `services/patient_tasks.py`
  - `holders_now(db, tasks, now)`：印の付いた項目の未完了のやることについて、最初に終わった訪問と、その主担当（`visit_staff_map` の primary）を 1 回の問い合わせで求める。
  - `tasks_for_visits`：預かり中のやることは、最初の訪問にだけ出す（`held=True`）。ほかの訪問には出さない。
  - 「何回目の訪問待ち」は、預かり中には使わない（状態は「預かり中」）。
- `api/v1/tasks.py`
  - 一覧と 1 件の読み出しに `held_by`（`staff_id`・名前・最初の訪問）を足す。
  - 看護師で絞る（`staff_id`）に、その人が預かっている分を含める。
  - 完了：職員は、自分が預かっているやることなら訪問なしで完了できる（`done_visit_id`＝最初の訪問）。
  - 新しく `GET /tasks/held`（自分が預かっているやること）。スマホの今日の画面が使う。
  - 件数（`/tasks/counts`）に「預かり中」を足す。
- `api/v1/tasks.py` の項目の作成・変更に `hold_by_first_visitor`。監査ログに残す。

### frontend
- 項目の設定：各項目に「最初に訪問した看護師が預かる」の切り替え。
- タスク管理の一覧：状態に「預かり中」（青の札）。出す訪問の欄に「〇〇さんが預かり中（11/2 の訪問から）」。上の件数に「預かり中」。
- スマホの今日の画面：上に「預かっているやること N 件」の帯。開くと一覧と「完了」。
- 訪問の詳細（PC・スマホ）：最初の訪問では「預かり中」と出す。

## 5. 試験の観点

- 印なしの項目は今までどおり（次の訪問へ持ち越し・何回目）。
- 印ありで、最初の訪問の終わりの前：最初の訪問に出る。終わった後：主担当が預かり、次の訪問（別の看護師）に出ない。
- 最初の訪問が取消・削除 → 次の訪問が「最初」になる。主担当なしの訪問は飛ばす。
- 最初の訪問の主担当を替えた → 預かる人も替わる。
- 預かった看護師は訪問なしで完了できる。ほかの看護師は 403。管理者はできる。
- 2 名訪問：主担当だけが預かる。2 人目は完了できない（管理者は可）。
- 項目の印を外す → 今までどおりの持ち越しに戻る（計算なので、すぐ戻る）。
- migration 0107 の upgrade／downgrade。

## 6. リスクと気をつけること

- 預かった看護師が辞めた・長く休むと、預かり中のまま残る。一覧で「在籍なし」と分かるように出し、事務所が完了か取り消しをする。
- 予定の終わりで「訪問した」とみなすので、実際には行かなかった（取消の入れ忘れ）訪問でも預かりになる。取消を入れれば自動で外れる。
- 印を付けた時点で、今ある GAF のやることにも当てはまる。2 回目以降の訪問待ちになっている分は、最初に訪問した看護師の預かりに変わる（実装前に本番の件数を数えて伝える）。
- 預かった後に期日を付けた場合は、期日を過ぎたら「期日を過ぎた」も出す（期日の決まりは変えない）。

## 7. PO の決定（2026-11-04・モックを見て）

1. 預かった後、同じ看護師がその方をまた訪問しても、その訪問には出さない。スマホの帯の一覧だけに出す。
2. 預かったときのベルは出さない（今日の画面の帯で分かる）。
3. 預かり中が長く残っても色は変えない。一覧に預かってからの日数だけ出す（例：「12/2 から 5 日」）。
