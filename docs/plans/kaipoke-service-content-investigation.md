## 3. RPA(auto_apply.py)側の現状

新規追加(`fill_medical_insurance_fields`)は固定値:
1. 保険区分=医療保険 → 2. サービス区分 `#inPopupEstimate1`=「精神科訪問看護」を含む option → 3. 基本療養費 `#inPopupEstimate2`=「Ⅰ」 → 4. 職員資格 `#inPopupEstimate3`=「看護師等」を含む option。
→ **准看護師の訪問・一般(非精神)患者の訪問は、現状の RPA では正しく登録できない**(常に精神・正看になる)。サービス内容欄は上記3選択から自動算出(read-only)。
変更(edit)は時刻/職員の書換のみでサービス内容は触らない。

## 4. 対応案

### らく助(データ)
- 患者マスタに「訪問看護区分」(精神科 / 一般)を持つ。既存列 `kaipoke_service_content` を**ベース値**として使い、`精神基本療養費Ⅰ`(既定) / `基本療養費Ⅰ`(一般) を保持。兼行・近藤 の 2 名を一般に設定。
- スタッフマスタの資格(看護師 / 准看護師)は現状どおり。

### らく助(コード)
- `csv_builder`: サービス内容 = 患者ベース + (職員1 の資格が准看護師 → 「・准看」/ それ以外 → 「・正看」)。同行は職員1基準。
- 患者編集画面に「訪問看護区分」セレクトを露出(現状 `kaipoke_service_content` は UI に無い可能性 → 要確認)。

### RPA(auto_apply.py)
- `Correction.service_type` を解釈し、(a) 「精神」が含まれなければ `#inPopupEstimate1` で一般の訪問看護を選ぶ、(b) 「准看」なら `#inPopupEstimate3` で准看護師の option を選ぶ。
- **未知**: `#inPopupEstimate1` の一般側 option 文言と `#inPopupEstimate3` の准看 option 文言(「准看護師」?)。→ headed dry-run で実画面の option 一覧を採取してから実装(本番登録はしない)。

### 順序
1. PO 確認: ①規則(職員1の職種で正看/准看)で合っているか ②例外 3 件の扱い(カイポケ側を直すか) ③一般患者 2 名の登録
2. らく助 CSV 生成の修正 + 患者区分の設定 → 再突合で「正看/准看」の偽差分が消えること(例外 3 件だけ残ることを確認)
3. RPA の option 採取 → 准看/一般の新規登録対応 → 1 件テスト → 運用
