④ 固定イベントの実用化 試案 — 一括登録と休みの自動不参加

「毎週の固定イベント」機能は既にあるが、1回の登録=1名×1曜日のため朝会（全員×月〜土）は42回操作となり使われていない。曜日の複数選択+複数スタッフ一括登録で1回の操作にする。朝会はコード上の特別扱いをせず、この汎用ダイアログから普通に登録する1件にすぎない。

📍 変更A: 一括登録ダイアログ（スタッフ一覧の「固定イベントを一括登録」ボタンから。試しに操作できます）

固定イベントを一括登録

選んだスタッフ × 曜日のぶんだけ「毎週の固定イベント」を作成します。週生成のたびに自動で予定に入ります。
7名 × 6曜日 = 42件の固定イベントを登録します（既に同じ登録がある分は自動でスキップ）

水曜: 「休みにする」操作をした時点で、その日の固定イベントに自動で取消印（打ち消し表示・カイポケへは送らない・エンジンからも除外）。金曜: 早出の患者対応など休み以外の理由は、従来どおり手動の「今週だけ外す」。

一括登録のしくみ（汎用）

  • スタッフ×曜日の組をまとめて1回で登録（例: 朝会=7名×6曜日=42件が1操作）
  • 「☀ 9:00出勤の全員」は週間シフトから自動選択する補助ボタン
  • 既に同じ登録がある組は自動スキップ（二重登録なし）。朝会専用の処理は作らない — どのイベントでも同じ操作

休みとの連携（自動不参加）

  • 週生成時: その日に休みが入っているスタッフへは展開しない
  • 後から「休みにする」: その日の固定イベントに自動で取消印（元に戻すと復活）
  • 展開済みの行を消さないので、週生成をやり直しても二重にならない（既存のしくみを流用）

運用イメージ

  • 実装後、この画面から朝会を一括登録 → 以後は毎週自動。手入力もカイポケ取込との二重も解消
  • 時間変更・廃止はカードの ✎ / 🗑（次の週生成から反映）
