# QR訪問チェックイン — UIモック & 設計メモ

患者宅の固定QRをスマホで読み取り、GPS付きで訪問の到着/退出を記録し、PCの「訪問モニター」で管理者がスタッフの動き・予定との乖離（未訪問・場所違い・遅延）を一目で把握する機能の **UIモックと設計素案**。

> ステータス: **UI設計フェーズ（モックのみ）**。実装は未着手。まず本モックで構成を固め、必要ならデザインエージェントへ `mobile.html` / `pc.html` を渡して磨き込む。

## ファイル
**静的ストーリーボード（全状態を並べて俯瞰）**
- `mobile.html` — モバイル全状態フロー（①今日の訪問 → ②QRスキャン → ③到着確認 → ④訪問中 → ⑤退出確認 → 異常系：場所違い）。横スクロール。
- `pc.html` — PC「訪問モニター」＝スタッフ別タイムライン（ガント）+ KPI + 異常検出 + 詳細パネル。

**動的プロトタイプ（実際にクリックして遷移を確認）**
- `pc-proto.html` — **タイムライン専用**（地図/一覧の上部トグルは廃止）。右パネルに **Leaflet実地図（OpenStreetMap・要ネット接続）**。**行クリック→そのコースの目的地を地図にピン表示**（番号付き・順路ライン・区間距離）、**バークリック→訪問詳細＋該当ピンにフォーカス**。予定バーは患者名を表示。拠点・異常フィルタ動作。
- `qr-print.html` — **患者QR印刷（個別＆一括・1名1枚・二つ折り）**モック。**2つの入口を上部トグルで再現**：①個別（患者詳細の「QRコード生成」→その1名）②一括（患者一覧の「QRコード生成」→拠点絞り込み＋選択で全員分を各A4 1枚）。A4は中央の折り線で半分に折ると上半分=掲示面（患者名・拠点・大QR・案内）、下半分=説明面（ご家族向け説明・注意・事業所連絡先・発行日）。患者宅へお渡し／掲示できる体裁。実QR描画（`qrcodejs`・要ネット）、`window.print()`。
- `mobile-proto.html` — **患者カードタップ→詳細→QRフロー（スキャン→GPS判定→到着→訪問中タイマー→退出→完了）** を実際に体験。完了で一覧の状態が更新。「鈴木みどり」を選ぶと場所違い(340m)の異常系。**「訪問できなかった（理由を記録）」→未訪問＋理由入力（クイック選択チップ付き）** も追加。画面遷移はiOS風スライド（中央ぴったり停止）。

### 場所違い・未訪問の強化（PC/モバイル連携）
- **地図で自宅↔実GPSを明示**: 場所違い時、登録住所は🏠（teal・しきい値100m円付き）、実GPSは📍（赤・波紋）で別アイコン表示し、**両者を赤破線＋「340m 離れています」ラベル**で結ぶ。
- **近隣患者宅の推定**: DB全患者の住所/緯度経度（`HOMES`、実装では `patients` テーブル）から、GPS近傍の宅を**「〇〇様宅？」**の点線ピンで表示し「実際はどこへ行ったか」を補助。
- **要対応アラートトレイ**: KPI直下に、**未訪問→場所違い→要確認の優先順**で理由付きカードを横並び表示。未訪問カードは赤く点滅＋**「📞 すぐ連絡」**ボタン。クリックで該当訪問へジャンプ。
- **未訪問の強調＋即アクション**: タイムラインの未訪問バーは赤ハッチ＋⛔＋点滅。詳細に**「即対応」赤ボックス（患者/スタッフへ発信・最後の記録位置）**。
- **次までの距離**: 各訪問間の距離を Haversine 算出し、**タイムライン（バー間 →1.2km）・地図（区間ラベル）・詳細（次の訪問まで）** に表示。
- **モバイル→PC連携**: モバイルで入力した場所違い理由／未訪問理由が、PC詳細とアラートカードに**スタッフ入力として優先表示**される想定（実装では `visit_checkin.reason`）。

単体で開ける自己完結HTML（ビルド不要）。CareFlowの Warm & Human デザイン（teal `#0d9488` / クリーム `#faf7f2`）に準拠。

## 確定した設計判断（2026-06-30 合意）
| 項目 | 決定 |
|---|---|
| QR方式 | **患者宅に固定QR**（印刷して自宅に掲示）。到着・退出とも同じQRを読む＝現地証明力が最強 |
| 記録範囲 | **到着＋退出の両方**（滞在時間・予定との差を計測） |
| PC主役ビュー | **タイムライン（ガント）**。副ビューに地図・一覧（セグメントトグル） |
| 位置判定 | **距離しきい値で自動判定**：〜100m=一致(○) / 100〜300m=要確認(△) / 300m超=不一致(×)。しきい値は設定可 |
| 異常時の記録 | 不一致でも記録は止めず「理由付きで記録」を許容。PC側で⚠フラグ |
| フォールバック | QR読めない時の「手入力で選ぶ」、チェックイン/アウトAPI不通時の localStorage 退避（既存実装を踏襲） |

## 既存コードとの接続点
- モバイルは既存 `frontend/app/(mobile)/m/today/[visitId]/page.tsx`（チェックイン/アウト＋写真UIが未完・localStorageフォールバック中）を **置き換え/拡張**。
- 既存フック `lib/queries/me.ts` の `useCheckIn`/`useCheckOut`（**バックエンド未実装**）を、GPS・QR・判定付きに拡張するのが自然。
- PC「訪問モニター」はサイドバー（`components/Sidebar.tsx`）に新規ナビ項目として追加。データは既存スケジュール（予定）＋新規チェックイン記録（実績）を突き合わせ。
- 位置判定の距離計算は既存の Haversine ユーティリティ（schedule 距離表示で使用中）を再利用可能。

## データモデル素案（バックエンド）
新テーブル `visit_checkins`（1訪問に到着/退出の2行、または1行に両方）。
```
visit_checkin
  id
  visit_id          → 予定（visits）への紐付け。突き合わせの軸
  patient_id        → QRが指す患者（QRに patient コードを埋め込む）
  staff_id          → 打刻したスタッフ（セッションから）
  kind              'arrival' | 'departure'
  scanned_at        サーバ受信時刻（端末時刻も別途保持し改ざん検知）
  device_time       端末側時刻
  lat, lng          GPS座標
  accuracy_m        GPS精度（measure信頼度）
  distance_m        登録住所(patient.lat/lng)からの距離（サーバ計算）
  match_status      'match' | 'review' | 'mismatch'（しきい値判定・サーバ確定）
  reason            不一致時のスタッフ入力理由（任意）
  reviewed_by       管理者が「確認済み」にした場合
```
QRの中身は患者識別子（例 `careflow:patient:P095`）。署名/有効期限トークンにして使い回し・偽造を防ぐ案も検討。

## GPS取得とデータ連携（モバイル）
1. QR読取（`getUserMedia` + JS QRデコーダ、例 `@zxing/browser` / `jsQR`）で patient_id を取得。
2. `navigator.geolocation.getCurrentPosition({enableHighAccuracy:true})` で lat/lng/accuracy 取得（HTTPS必須、iOS Safariはユーザー操作起点が必要 — 既存設計メモ §10-12 に記載）。
3. `POST /api/v1/visits/{visit_id}/checkin`（到着）/`/checkout`（退出）に `{patient_id, lat, lng, accuracy, device_time, qr_token}` を送信。
4. サーバが患者登録座標との距離を計算 → `match_status` を確定して保存・返却（判定はクライアントを信用せずサーバで行う）。
5. 圏外/権限拒否時は精度低下フラグを立てて記録、または localStorage 退避（既存フォールバックを流用）。

## PCタイムライン（訪問モニター）の要点
- 行＝スタッフ（拠点でグルーピング）、横軸＝時刻（8–19時）。
- 各訪問を **予定バー（薄・破線）** と **実績バー（到着〜退出・判定色）** の2段で重ね描き → 予定と実績のズレが視覚化。
- 実績色：一致=teal / 要確認=橙 / 不一致=赤 / 未訪問=赤ハッチ。異常は行に🔴🟠⚠️マーカー。
- 「今」ライン（現在時刻）で進行中を把握。
- KPI帯：本日訪問 / 一致 / 要確認 / 未訪問 / 平均到着ズレ。
- フィルタ：日付・拠点・「異常のみ」「未訪問のみ」。
- 右の詳細パネル：選択訪問の予定/実績時刻・滞在・距離・GPS精度・地図・スタッフ理由・「確認済み」操作。

### しきい値設定（2026-06-30 合意 / `pc-proto.html` の⚙で操作可）
- **適用スコープ＝全社一律**（まず最小。将来は拠点別上書きを検討）。
- 既定値：一致 **100m以内** / 要確認 **〜300m**（超で不一致）/ GPS精度許容 **±50m超は「測位不良」で要確認** / 未訪問の猶予 **予定開始＋20分** / 遅延 **予定＋15分**。
- 判定はハードコードせず「距離・時刻・GPS精度」から自動分類（`classifyWith`）。⚙モーダルでスライダー変更→プレビュー件数→「保存して再判定」でタイムライン/アラートが即再評価される。
- 実装方針：生の距離・精度・時刻は常に保存し、判定は記録時のしきい値で確定保存（使ったしきい値も記録）。後からしきい値を変えても過去記録の判定は遡及変更しない（証跡の一貫性）。**未訪問は時間ベース**（猶予超過でスキャン無し）。

> **CSV出力は当面スコープ外**（不要との判断 / 2026-06-30）。将来必要になれば実績エビデンス・勤怠集計・介護ソフト連携・異常レビューの用途別フォーマットで再検討。
