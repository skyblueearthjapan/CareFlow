# rakusuke-kaipoke — カイポケとの差分・送信・突き合わせ

カイポケ＝お客様の介護請求ソフト。らく助はロボット（RPA）でカイポケの画面を操作して送る・読む。
**お客様がカイポケで直接手を入れる運用がある**（週42 は 10/7 以降に約 45 件）。だから**送る前・取り込む前に必ず差分を見る**。どちらを正にするかは PO が決める。

部品: `agent/rk/ops/kaipoke.py`（操作 `kaipoke-send` と読むための関数）。小さなコマンド:
```
PYTHONPATH=. python -m rk.ops.kaipoke unsent --week-start 2026-10-19          # ●未送信（保存した写しと比べる・ロボットは動かない）
PYTHONPATH=. python -m rk.ops.kaipoke diff --month 2026-10 --week-start 2026-10-19 --week-end 2026-10-25 --approved "PO 10/19 10:02"
PYTHONPATH=. python -m rk.ops.kaipoke items --sheet <sheetId> --week-start 2026-10-19 [--include-only]
PYTHONPATH=. python -m rk.ops.kaipoke jobs --week-start 2026-10-19 [--sheet <sheetId>]
PYTHONPATH=. python -m rk.ops.kaipoke job --id <jobId>
```
（起動時の RuntimeWarning は無害。出力に利用者名が入る → 画面に見せるだけ。ファイルにするなら `../docs/reports/agent/` だけ）

## 0. 先に知っておくこと（罠）
- **ロボットを動かす読み取り**（`diff`＝diff-local・`export`・`smart-inbound-preview/start` など）はカイポケにログインして 1〜2 分かかる → **PO の了承を取ってから**。`unsent`・`rk get /integrations/reconcile-report` はロボットを動かさない。
- 保存した写し（カイポケ CSV）と比べる答えには、**写しの時刻を必ず言う**（`unsent` の `snapshot` 行・`rk sql kaipoke_snapshot_latest`）。写しより後にお客様がカイポケで手を入れた分は見えない。
- **月をまたぐ週**（例 9/28〜10/4）: ●未送信は空になる（警告つき）。diff-local は両月を export する。送信は**月ごとに分けて**（`item_ids` にその月の行だけ）。
- カイポケの export は**担当なし（職員1 が「-」）の行を出さない** → 「らく助だけにある（追加）」に化けて二重登録の原因になる。担当なしの行はらく助が送らない（ガード）。送る前に担当なしを 0 件にする（`rakusuke-visit-change`／`rakusuke-week-optimize`）。
- **当日以前の行は送られない**（実績の保護・サーバーが除外）。送れるのは明日以降だけ。
- 准看の追加も送れる（本番の設定）。請求区分（正看/准看）のずれは職員の資格で決まる（`grade_change` の印）。
- 氏名の表記違い（齋藤/齊藤・真理奈/真里奈）は「利用者が見つかりません」で失敗する → 送る前に名前をそろえる相談を。
- 1 件 30〜60 秒（172 件で約 1 時間 50 分）。**17〜18 時台はロボットが失敗しやすい** → 送信は 09:00〜17:00 に終わる量だけ。
- **職員の休み**（個別業務の「休み」「AM休み」「PM休み」「有給」）は、この週の送信とは別の流れ。**カイポケが正**で、照合は画面の「休み・勤務表」の「カイポケと比べる」、承認した休みは「この月を確定」でまとめて送られる（その月の照合が一度済んだ月だけ）。休みを 1 件ずつカイポケへ送ることはしない。送った後にらく助で休みを取り消す・種類を変えると「カイポケで要対応」になる → カイポケ側も合わせるよう管理者に伝える。
- カイポケの取込（差分・置換）では、休む方に訪問の担当が戻ることがある（カイポケが正のため、らく助は担当なしに戻さない）。取込のプレビューの「休みの時間帯に担当が付く訪問 N 件」と、実現性チェックの「休みの時間帯に担当」で知らせる。
- **送ったものはらく助からは戻せない**。カイポケを戻すには、らく助の予定を元に戻してから差分を取り直して送り直す。らく助のバックアップを戻してもカイポケは戻らない。
- 月初展開（`expand`）・置換取込（`replace-inbound`）・取り込み前に戻す（`inbound-snapshots/{id}/restore`）・カイポケのログイン情報は**扱わない**（PO が名前を挙げたときだけ別の手順。取り込みは §6 の `kaipoke-import`）。

## 1. 差分を確かめる（読むだけ）
1. 週を確定（月曜〜日曜の日付を曜日つきで）。月をまたぐか確かめる。
2. まず `unsent`（ロボットなし）で件数と写しの時刻を言う:
   「●未送信 12 件（送れるのは明日以降の 9 件・当日以前 3 件）。カイポケの写しは 10/18 01:00 時点です。」
3. 写しが古い（前の送信や取り込みより前・半日以上前・お客様が手を入れた可能性がある）なら、**差分を取り直すか**を選択肢で聞く:
   「カイポケから今の予定を読み直して差分を取る（1〜2 分・カイポケにログインします）／保存した写しのまま進める／やめる」。了承されたら `diff`。
4. `items` で**前→後の表**を作り、次に分けて見せる（`summary` の数）:
   - 追加（らく助にあってカイポケに無い）／削除（カイポケにあってらく助に無い）／変更（時刻・担当）／日の移動
   - **カイポケ側の手直しの疑い**: 削除・変更のうち、らく助の今の予定より新しくカイポケで変えたと思われる行（担当・時刻がカイポケの方が現実に近い、お客様からの連絡があった等）→ 送るとその手直しを上書きして戻す。1 行ずつ PO に確かめる。
   - 担当なし・当日以前・非稼働の患者（入院中なのに予定が残る等）・請求区分のずれ・月
5. 件数の予告と所要時間（件数 × 約 45 秒）を添える。

## 2. 送る範囲の了承
- 選択肢で:「表の全部を送る（N 件）／カイポケの手直しの疑いを除いて送る（M 件）／やめる」。部分なら `item_ids` を決める。
- 了承した時刻を記録する（`diff_reviewed_at`・タイムゾーンつき）。**3 時間を過ぎたら差分を取り直す**（その間にお客様が手を入れるかもしれない）。
- 月をまたぐ週は月ごとに別の案（`month` と `item_ids` を分ける）。

## 3. 送る（日中だけ）
案（plan.json）:
```json
{ "kind": "kaipoke-send", "title": "週43 をカイポケへ送る（9 件）",
  "target": {"iso_year": 2026, "iso_week": 43},
  "summary": ["追加 5・削除 2・変更 2", "担当なし 0・当日以前は送られない", "所要 約 7 分"],
  "ops": [ { "op": "kaipoke-send", "sheet_id": "…", "month": "2026-10",
             "week_start": "2026-10-19", "week_end": "2026-10-25",
             "expected_item_count": 9, "diff_reviewed_at": "2026-10-19T10:05:00+09:00",
             "item_ids": ["…"], "label": "週43 9 件をカイポケへ" } ],
  "checks": ["差分を PO が確認", "日中", "担当なし 0"], "warnings": ["送った内容はらく助からは戻せない"] }
```
- `rk plan check` が時間（09:00〜17:00・終わりの見込みも 17:00 まで）・件数・月・確認の古さを検査する。`rk apply` の直前にも、**送る行を読み直して件数が違えば止まる**（別の人が送った・シートが変わった）。
- `rk backup` → `rk apply <plan.json> --approved "…"`。送信は**実際の通信で 127.0.0.1:18001** に届く（rk が行う。サーバー内で直接呼ぶ方法は裏の処理が止まるので使わない）。
- 応答はジョブ ID（`jobId`）。送信は裏で続く。

## 4. 進み具合を報告
- 10 分おき程度に `python -m rk.ops.kaipoke job --id <jobId>`（明細の成功/除外/失敗の数）と `rk get /integrations/live`（ロボットの今）を見て 1 行で報告:「カイポケへ送信中: 9 件中 4 件 済み（失敗 0）。あと約 4 分。」
- ジョブの完了は 5 分おきの見回り（reconcile cron）が付ける。running のまま長く残ることがある（過去の残りが 34 件ある）→ 時間で判断せず、明細と export で確かめる。
- 失敗があれば理由を平易に（利用者が見つからない＝名前の表記・時刻の重なり・ロボットの時間切れ）。送り直しは差分を取り直してから。

## 5. export で突き合わせる（成否の確定）
- 送信が終わったら、了承を得て **差分を取り直す**（`diff`。カイポケの今を読み直す）→ 送った行が差分から消えたかを数える:「送った 9 件のうち 9 件がカイポケと一致しました（10/19 11:20 にカイポケを読み直して確認）。」
- 一覧が要るときは `rk get /integrations/reconcile-report -q weekStart=<月曜> -q format=json`（一致・相違・らく助のみ・カイポケのみ・非稼働）。これは**保存した写し**と比べる → 写しの時刻を添える。
- 連携結果レポート: `rk get /integrations/kaipoke/jobs/<jobId>/report -q fmt=json`（unknown＝人の目で確かめる）。
- 結果は 3〜5 行で報告。残った差分は「どちらを正にするか」を PO に聞く。

## 6. カイポケ側の手直しの取り込み（カイポケ → らく助）【危険・提案まで】
- 画面の「⇩カイポケから取り込む」（smart-inbound）は、**打刻のある日は差分、打刻の無い日は置換**（その日のらく助の予定を全部消してカイポケの今で作り直す）。置換は名寄せできない行をらく助から消す。新人の職員名 2 は同行として扱う。打刻のある週は「取り込み前に戻す」ができない（422）。
- エージェントがすること（ふだん）:
  1. 差分（`diff-inbound` などのプレビューは**ロボットを動かす**ので了承の後）か保存した写しから、「カイポケで何が変わったか」を人の言葉で要約（誰の何曜の何時が、どう変わったか・何件）。
  2. 失うもの（その日にらく助で調整した訪問・名寄せできない行）と、戻せるか（打刻のある日がある週は「画面からも元に戻せません」）を説明。
  3. 選択肢:「画面で取り込む（管理者が連携ページで操作）／らく助を正にしてカイポケへ送り直す（§1〜§5）／今は何もしない」。
- PO が**「取り込む」と名前を挙げて**頼んだときだけ、操作 `kaipoke-import`（部品 `agent/rk/ops/kaipoke_import.py`）で行う。勝手に進めない:
  1. プレビュー（ロボット・1〜2 分・了承の後・日中）: `PYTHONPATH=. python -m rk.ops.kaipoke_import preview --week-start <月曜> --approved "<誰が・いつ>" --op-out ../docs/reports/agent/import-op.json`。
     `summary` の数（打刻のある日＝差分の日／置き換える日・消える件数 `replace_wiped`・入る件数 `replace_inserted`・対象外）と、
     **らく助で調整した訪問のうち置き換わるもの**（`adjusted_replaced`：「カイポケの内容で作り直されます」／「カイポケに無いため消えます」）を、案の `issues[]` に 1 件ずつ出す。
  2. 書き出した op を案（plan.json）の `ops` に入れる（`preview_reviewed_at` は了承の時刻に合わせる・3 時間を過ぎたらプレビューを取り直す）。置き換える日があると、取り込みもロボットを使う → **09:00〜17:00 だけ**（`rk plan check` が止める）。
  3. 了承（①この案で反映する ②ここを直してほしい ③やめる）→ `rk backup` → `rk apply` → `rk verify`。反映の直前にもプレビューがまだ有効か・その後に別の取り込みが無いかを読み直す。
  4. 戻し方: 打刻のある日が無い週だけ `rk undo`（取り込みの直前の盤面へ戻す `kaipoke-import-undo`）。打刻のある日がある週は、案の時点で「**この週には打刻のある日があるため、取り込んだ後は画面からも元に戻せません**」と伝える。取り込んだ後に打刻が付いた週も戻せない。

## 7. 答え方
```
週43 のカイポケとのずれ: 12 件（追加 5・削除 2・変更 5）。
・送れるのは明日以降の 9 件。担当なし 0 件。
・削除 2 件と変更 2 件は、お客様がカイポケで手を入れた可能性があります（表の ★）。
根拠: ●未送信（rk.ops.kaipoke unsent）。カイポケの写しは 10/18 01:00（日本時間）時点。
```
