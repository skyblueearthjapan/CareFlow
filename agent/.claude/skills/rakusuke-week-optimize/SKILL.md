# rakusuke-week-optimize — 今週の最適解（ならし）

書き込むスキル。AGENTS.md §4-1 の順（案 → 見せる → 選択肢で了承 → `rk backup` → `rk apply` → `rk verify`）を必ず通す。
本番を読むのは自由。案を作るまで（`rk level`）は本番に書かない。

## 0. 先に知っておくこと

- 道具は `rk level`（中身は `docs/tools/week-leveling/` の計算。OR-Tools で 1 日ずつ「出勤している職員＝車・訪問＝立ち寄り先」を解く）。
  1 日 30 秒ほど × 日数かかる。**1 本ずつ**（並べて回すと CPU を取り合って結果が揺れる・PC のメモリも少ない）。長いときはバックグラウンドで。
- 職員の役割（正規・マネージャー・どの拠点を回るか）と 1 人の上限は `docs/tools/week-leveling/config.local.json`（職員コードで書く・git 管理外）。無ければ止まって PO に聞く。
- **新人（同行だけの職員）は自動で外して計算する**（`--include-trainee` を付けない限り）。新人を担当にした案はアプリが断る。
- 道具は**週の予定（visits）を読む**。固定訪問の枠（毎週の型）は直接読まない → マスターを変えた直後は、先に `rakusuke-week-check` で「型と今週の違い」を見る。赤ピン（locked）も見ないので、希望の時間帯があれば時刻を動かすことがある。
- **すでにならして反映した週をもう一度ならすと、担当が大きく入れ替わる**（道具は「今の担当のまま」を重んじない。週43 の試しでは 149 件中 80 件の担当が変わった）。反映済みの週で一部の日だけ変えたいときは `--day <その日>` に絞る。
- 出力: 案 = `agent/runs/plans/<日時>-week<NN>-leveling*.json`、Excel/A4 = `docs/reports/agent/<日付>/<時刻>-week<NN>-leveling*/`（利用者名入り・git 管理外・公開しない）。

## 1. 流れ（毎週の回し方）

### 1-1. 状況を読む（書かない）
```
rk whoami
rk sql visit_counts_by_day -p date_from=2026-10-19 -p date_to=2026-10-25     # 週ができているか（0 件＝まだ週を作っていない）
rk sql day_load_vs_staff  -p date_from=2026-10-19 -p date_to=2026-10-25     # 日ごとの件数と出勤人数
rk sql staff_week_overrides -p monday=2026-10-19                            # 休み・半休・時間変更
rk sql staff_week_events    -p monday=2026-10-19                            # 会議・研修・朝会
rk sql pool_week            -p monday=2026-10-19                            # 特別訪問週間の○・回数の足りない方
rk sql master_vs_week_diff  -p monday=2026-10-19                            # 型と今週の違い
rk sql pending_leave_requests -p request_type=                              # 承認前の休み申請（案に入らない）
```
- 承認前の休み申請があれば「先に承認しますか」を聞く（承認前は休みとして数えない）。
- 細かい点検は `rakusuke-week-check`。

### 1-2. 週を作る（まだ無いとき）
画面の「週を作る」→「前の週をコピー」と同じ API を、操作 `copy-week` で代わりに押す（書き込み。§4-1 の順で）。
1. 確認（読むだけ）: `echo '{"source_week_start":"2026-10-12","target_week_start":"2026-10-19","fill_from_fixed":false}' | rk post-read /schedule/v2/copy-week/preview --json -`
   → 写る件数（`copy_count`）・写さない内訳（`skipped`）・担当を手で付ける訪問（`needs_manual_staff`）・**写す先に今ある訪問（`existing.total`）**を読む。
   - `existing.total` が 0 でなければ止まる（もう週がある＝コピーは使わない。上書きは PO が名前を挙げて頼んだときだけ）。
   - 写す元は写す先の 1〜8 週前。祝日（`source_holidays`/`target_holidays`）があれば伝える。
2. 案（例 `agent/runs/plans/<日時>-copy-week<NN>.json`）:
   ```json
   {"kind": "copy-week", "title": "週43（10/19〜10/25）を週42 から作る",
    "target": {"iso_year": 2026, "iso_week": 43, "week_start": "2026-10-19"},
    "summary": ["週42 の 118 件を写す（取消・予定外・特別訪問の○は写さない）"],
    "ops": [{"op": "copy-week", "label": "週43 を週42 から作る",
             "source_iso_year": 2026, "source_iso_week": 42, "target_iso_year": 2026, "target_iso_week": 43,
             "fill_from_fixed": false, "assign_staff": false}],
    "checks": ["写す先の週は空"], "warnings": ["週を消すにはバックアップから（API では戻せない）"]}
   ```
   - **自動スタッフ割当はしない**（`assign_staff: false`。true は `rk plan check` が断る）。担当は 1-4 のならし案で付ける。
   - 「固定訪問から補う」（`fill_from_fixed`）は既定 false（画面と同じ）。補うかは選択肢で聞く。
3. `rk plan check` → 要点を見せ選択肢で了承（「この内容で週を作る／写す元を変える／やめる」）。**元に戻すにはバックアップから**と伝える。
4. `rk backup --label before-copy-w<NN>` → `rk apply <案> --approved "..."`（押す直前に確認画面と同じ内容を読み直し、写す先に訪問があれば止まる）→ `rk verify <案>`（写す先の件数が 0 でない・写す元とおおよそ同じ）。
5. 作った後は 1-1 をもう一度読む（同じ方が同じ日に 2 件ないか。2 名体制・1 日 2 回は正常）。`needs_manual_staff` の訪問はならし案で担当が付く。

### 1-3. 条件を聞く（1 問ずつ・選択肢で）
1. 範囲: 「週全部／特定の日（〇日）」
2. 休む人・抜く人: 「いない／〇〇さんを〇日（または週全部）」→ `--off <職員コード>[@日付]`
3. 入りきらないときの受け方: 「マネージャーが受ける（既定）／正規が 1 名まで少しオーバー（`--allow-over 1`）／マネージャーより先に少しオーバー（`--allow-over 1 --over-before-manager`）」
4. 特別訪問週間の○: 「入れる（`--add-special`）／入れない」（`pool_week` に kind=special があるときだけ聞く）
5. 今週だけ取消にする予定の訪問: あれば `--drop <訪問 ID の先頭>`（取消そのものは `rakusuke-visit-change`）
6. 件数をならすか: 「ならす（`--balance`）／移動の短さを優先（既定）」

### 1-4. ならし案を作る（本番は読むだけ）
```
rk level week --week 2026-10-19 [--day 2026-10-22] [--off S004@2026-10-22] [--allow-over 1] \
              [--over-before-manager] [--balance] [--add-special] [--drop 3f2a9c1e] [--seconds 60]
rk level day  --date 2026-10-22 --off S004        # 急な休みの 1 日（rakusuke-absence から使う）
```
- 出力の JSON: `plan`（案のパス）・`reports`（Excel/A4 のフォルダ）・`ready`・`blockers`・`summary`・`checks`。
- **合格の条件**（自分で確かめてから見せる）:
  1. `ready` が true（`blockers` が空。決まりの検査の問題 0・新人が担当でない・コースが決まる）
  2. 入らない訪問が 0、または全部を管理者と決めて `rk plan resolve` で書き込んである（下の「入らない訪問を決める」）
  3. `reports` の `summary.json` の `app_check.yardstick_match` が true（アプリの診断と同じ物差し）、`one_more_move_missed` が 0（0 でなければ `--seconds 90` で作り直す）
  4. 案の重なり 0（`summary` の「案の重なり」）
  5. `warnings` に「1 件に決まらない」が無い（あれば反映の途中で止まる → 作り直すか PO に相談）
- 同じデータで条件だけ変えるときは `--from-dir <前回の reports のフォルダ>`（本番に繋がない・早い）。

### 1-4b. 入らない訪問を決める（`rk plan resolve`）
入らない訪問がある案は `ready:false`（`blockers` に「入らない訪問が N 件…」）。案の `unplaced` に 1 件ずつ・理由（`reason`）・相談先（`hint`）がある。`rk plan check <案>` は「まだ決めていない入らない訪問」を並べる。
1. 管理者に、入らない訪問を**平易な日本語で理由とともに**見せる（例「10/22（木）〇〇様 10:00 は、その時刻に空いている人がいません」）。
2. **選択肢で**聞く（1 件ずつ。同じでよければ「全部まとめて」も選べる）:
   - 保留プールへ戻す（今週は行かない・API では戻せない → バックアップから）
   - 上限を少し超えて〇〇さんに付ける（承知の上で超過・職員は管理者に選んでもらう）
   - 時刻をずらす（何時にするか・誰が行くか。ご本人への連絡が要る）
   - いまの担当のまま残す（休みの職員に訪問が残る・当日までに担当を決める）
   応援を頼むなら、応援の方の職員コードで「上限を超えて付ける」か「時刻をずらす」を選ぶ。
3. 決めたら書き込む（決めた人を必ず `--approved` に）:
   ```
   rk plan resolve <案> --visit <訪問 ID の頭か名前の一部> --choice pool --approved "<誰が・いつ>"
   rk plan resolve <案> --visit <…> --choice allow-over --staff <職員コード> --approved "<…>"
   rk plan resolve <案> --visit <…> --choice shift --start 13:30 [--staff <職員コード>] --approved "<…>"
   rk plan resolve <案> --visit <…> --choice keep --approved "<…>"
   rk plan resolve <案> --all pool --approved "<…>"        # まだ決めていない全部を同じに（shift は 1 件ずつ）
   ```
   全部決まり、ほかの `blockers` が無ければ `ready:true` になる。決め直しは同じ訪問へもう一度。
4. その後はいつもどおり: `rk plan check` → `rk plan report`（A4 に「入らなかった訪問と決めたこと」が載る）→ 了承 → `rk backup` → `rk apply` → `rk verify`。

### 1-5. 見せる（A4/A3）
```
rk plan check  <案>
rk plan report <案>          # A4 縦: 要点・操作の一覧・決まり・気を付けること
rk plan report <案> --a3     # A3 横: 日ごとに 1 枚の時間割（桃色＝変わる。1 日の案はその日だけ）
```
- 加えて `reports` の `leveling-a4.pdf`（日ごとの全員の時間割・アプリの物差しの比較）と `leveling.xlsx`（変更一覧）。
- 要点は 3〜5 行で（下の §4 の言い方）。**元に戻せるか**も言う: 移動・担当は API で戻せる見込み／プールへ戻した訪問・○の配置はバックアップから。

### 1-6. 了承（選択肢で）
「この案で反映する／条件を変えて作り直す（何を変えるか）／やめる」。了承の言葉と時刻を `--approved` に書く。

### 1-7. 反映
1. 案を作ってから時間が経った（目安 1 時間）・その間に誰かが画面で触った → 作り直す。`rk apply` は反映の前に週を読み直して `source.basis_hash` と比べ、違えば「案を作った後に予定が変わりました。案を作り直してください」で止まる（`ready: false` の案も止まる）。
2. `rk backup --label w<NN>-leveling`（時刻は UTC）
3. `rk apply <案> --approved "PO 今泉さん 10/12 15:10 了承"` — 流す順は 手の上書きを外す → 入らない訪問をプールへ → ○を置く・今週だけ移動 → コースに担当。
4. 途中で止まったら、勝手にやり直さない。止まった 1 件と理由を伝え、`rk verify` で入った所までを確かめてから PO に聞く。

### 1-8. 確かめる
```
rk verify <案>
rk sql unassigned_visits -p date_from=… -p date_to=…     # 担当なし 0
rk sql staff_overlaps    -p date_from=… -p date_to=…     # 重なり 0
rk get /schedule/v2/feasibility-report -q iso_year=2026 -q iso_week=43 -q include_html=false   # 実現性チェック
```
結果を 3〜5 行で報告（成功件数・照合・バックアップ名・元に戻すコマンド）。

### 1-9. 新人の同行
- `rk sql accompaniments_week -p monday=…` で今の同行を読む → 新人の出勤日ごとに先輩のコースを提案（偏らないように。夕方が混む人に付けると学びと負担軽減の両立）→ 選択肢で了承 → `accompaniment-set` の案で反映（`rakusuke-absence` の同行の項と同じ）。
- 新人を担当（コース）にはしない。

### 1-10. カイポケへ
- 送るのはこのスキルではしない → `rakusuke-kaipoke`（差分を見て、お客様がカイポケで直した所を分けて見せ、送る範囲の了承を取り、日中に送る）。
- 「カイポケへ送る分がおよそ何件あるか」だけ `rk post-read /integrations/unsent-summary` で予告してよい。

### 1-11. お客様向けの提出物
- 反映後の週の A4（`rk level week --week … --no-app-check` で今の盤面を読み直すか、`rk plan report`）を `docs/reports/agent/` に。公開しない。

## 2. 決まり（ならしで守るもの）
| 項目 | 決まり |
|---|---|
| 上限 | 正規は 1 人 1 日 6 名（config の cap_regular）。少しオーバーは了承があるときだけ |
| 曜日 | 動かさない |
| 時刻 | 固定の時刻が第 1。だめなら希望の時間帯の中。固定と希望が 30 分超離れていれば固定のまま |
| 時間の種類 | 固定＝ちょうど／時間帯＝希望の範囲で開始／午前＝12:00 前に開始／午後＝13:00 以降／終日＝どこでも（下限は勤務開始） |
| 勤務時刻 | 守る。マネージャーはあふれの受け皿で、必要なら超えてよい（理由を添える） |
| 予定 | 会議・朝会など（取消以外）は前後 15 分込みで塞ぐ。予定の時間は昼休みに数えない |
| 昼休み | 11:30〜13:30 の中で 45 分をなるべく。入らない日だけ 30 分（30 分は必ず） |
| NG・女性限定 | 絶対に破らない |
| 同じ建物 | 約 100m 以内の 2 名は 1 人で 90 分の枠・移動 0 |
| 移動 | 直線 ÷ 20km/h（最低 1 分）＋別の住所へ 8 分。1 件目への移動は数えない |
| 拠点 | 正規は自分の拠点のコース（拠点が休みの曜日は別）。またぎは重い |
| ローテーション | 前回と同じ職員 200・2 回前 100・3 回前 50（移動 1 分＝1） |
| 新人 | 担当にしない（同行だけ） |
| コース | 1 人 1 日 1 コース。使うのは A〜E と M（M2・臨時へは移さない） |

## 3. 「もしも」の試算
| 言われたこと | やり方 |
|---|---|
| 〇〇さんを抜いたら | `--off <コード>`（日付なし＝週全部、`@日付`＝その日） |
| 1 名までオーバーしてよい | `--allow-over 1`（マネージャーより先なら `--over-before-manager` も） |
| 件数を平らに | `--balance` |
| マネージャーを延ばしたら・勤務時刻を変えたら | 前回の `reports` のフォルダを `docs/reports/agent/<日付>/whatif-…/` に写し、`week.json` の `shifts`（またはその週の `weekly_overrides` に `custom_time`）を書き換えて `--from-dir` で回す。**本番は変えない** |
| この訪問を外したら | `--drop <訪問 ID の先頭>` |
| ○を入れたら | `--add-special` |
- 比べるときは同じ `--seconds` で、1 本ずつ。結果は「入らない件数・移動の分・マネージャーの超え・前回と同じ」の 4 つを並べて見せる。

## 4. 管理者への説明のしかた（平易に）
- 結論から: 「来週（10/19〜24）の案ができました。149 件すべて入ります。移動は合計 1,315 分 → 1,289 分です。」
- 変わるところ: 「担当が変わるのは 〇件、時刻が変わるのは 〇件（いちばん大きいのは 〇〇様の 〇分）です。A3 の桃色の所です。」
- 気を付ける点は言い換える: 「マネージャーの川名さんが 2 日、勤務時刻を 5〜20 分超えます（受け皿のため）」「昼休みが 40 分の日が 1 日あります」。
- 入らない訪問は理由と相談先を 1 行で: 「〇〇様（火 13:00）は、その時刻に空いている人がいません。ご本人に時刻を動かせるか伺うか、マネージャーの延長でもう一度試せます。」
- 言わない: ソルバー・OR-Tools・JSON・UUID・op 名。言うときは「計算の道具」「案のファイル」「画面のボタンと同じ仕組み」。
- 言葉は「合わせる・調整」。アプリ名は「らく助」。

## 5. してはいけないこと
- 「週を生成」（固定訪問から作り直す）「今週全件解除」「自動スタッフ割当」「全面最適化」「範囲最適化の適用」「sync-fixed-to-week」「一斉スタッフ未割当」をエージェントが押す・呼ぶ（AGENTS.md §4-2）。
- 了承の前の反映。`ready: false` の案の反映。並べての試算。
- 「今週だけ取消」で入らない訪問を消す（プールに出ない）→ 案のとおり「プールへ戻す」。
- 新人を担当にする。NG・女性限定を了承で通す。
- 利用者名入りの出力を `docs/reports/agent/` 以外に置く・公開する。
