# rakusuke-course-plan — 型の作業場（コースの型を仮の 1 週間で試す）

型の作業場は、**日付の無い仮の 1 週間**です。今の固定訪問の枠（マスター）を下書きに写し、そこでコースと時刻を組み直したり、
「もしも」を試したりします。**本物の週の予定にもマスターにも触りません**。良い型ができたら、マスターと見比べてから
「固定訪問に登録」の案（`pfv-update`）を作り、了承 → 反映の手順に進みます。
設計: `../docs/plans/agent-skills/template-workspace-design-2026-10-12.md`（決まりの正典は `course-plan-design-2026-10-12.md`）。

## 0. 先に知っておくこと

- **二段の考え方**: 型（この作業場）＝全員が休みなく稼働する前提の最適な型。今週の話（急な休み・キャンセル・特別訪問週間）は `rakusuke-week-optimize`（`rk level`）。今週だけの話なら、このスキルではありません。**本物の週（visits）は絶対に触りません**。
- コース＝その曜日に出勤の型がある職員 1 人に 1 本（新人を除く・マネージャーを含む）。直近の週にその人が多く持ったコースを仮に当て、勤務時刻・NG・女性限定・固定イベントはその人で見ます。
- 時刻は**希望の時間帯の中だけ**で動かします（固定・希望の無い方は今の時刻のまま）。**曜日は動かしません**。
- 🔴 赤ピンの枠は**曜日と時刻を動かしません**（コースは替えてよい）。赤の付け外しはこの作業場ではしません（患者マスタで人がする・PO の判断）。
- **まだ枠の無い方**（固定訪問の枠が 1 つも無く、希望がある方。新しい方など）は、希望の曜日・時間帯の中に新しい枠を置きます。希望の回数が曜日の数より少なければ、混み具合の軽い曜日から選びます。2 名体制・NG・女性限定も守ります。回数も曜日も無い方は置けないので、曜日を聞いて `--add-patient` で足します。
- 登録の案は、**赤ピンの整理（本番で赤を一度ゼロに戻す K-4）が終わるまで** `ready:false` です。済んだと PO が言うまで `--red-cleanup-done` を付けません。
- 下書きは `agent/runs/template-drafts/<名前>.json`、帳票は `docs/reports/agent/<日付>/template-*.html`（利用者名入り・公開しない）。
- 計算は 1 曜日 20 秒ほど × 最大 2 回（昼休み 45 分で入らなければ 30 分）。週まるごとで数分。**1 本ずつ**流します。

## 1. 流れ

### 1-1. 相談を受ける（選択肢で 1 問ずつ）
- どの拠点か（例「稲毛」）。曜日は既定で週まるごと（月〜土の営業日）。
- 何を試したいか: ①今の型をならす ②新しい方の枠を作る ③もしも（職員が減ったら・この人がいなかったら・この方の希望が変わったら）。
- 変える枠をどれくらいに抑えたいか（`--max-changes N`・1 曜日あたり）。

### 1-2. 下書きを作って解く（本番は読むだけ）
```
rk whoami
rk template new ina-v1 --office 稲          # 今のマスターを写す（読むだけ）。「まだ枠の無い方」も一覧に出る
rk template solve ina-v1                     # 週まるごと（--weekday mon,tue で一部だけ）
rk template compare ina-v1                   # マスターと比べる（曜日ごとの数・違う枠）
rk template report ina-v1                    # A3 横の時間割（行 = コース・列 = 月〜土）＋ A4 の要点
```

### 1-3. もしも・手での調整（元の下書きは残して写しで試す）
```
rk template whatif ina-v1 --as ina-4ppl --staff-count mon=4,tue=4   # 月火が 4 人なら
rk template whatif ina-v1 --as ina-noS004 --drop-staff S004          # この人がいなかったら
rk template whatif ina-v1 --as ina-new --add-patient P130:tue,fri@09:00-12:00   # 枠の無い方を曜日・時間帯つきで足す
rk template whatif ina-v1 --as ina-pref --pref P035:mon=13:00-15:00  # この方の希望の時間帯が変わったら（試算だけ）
rk template solve ina-4ppl
rk template compare ina-4ppl ina-v1                                  # 下書きどうしも比べられる
rk template move ina-v1 --slot mon03 --course B --start 10:30        # 1 枠を手で動かす（決まりを確かめる・解き直しても動かさない）
```
- `move` は NG・女性限定・赤ピンの時刻・希望の範囲を確かめて、外れていれば断ります。間に合わないなどは「増えた気をつけること」に出します。
- 職員の数のもしもで仮の職員を足した下書き、希望のもしもで作った下書きは**登録できません**（試算だけ）。

### 1-4. 見せる（必ずマスターと比べてから）
数の言い方（平易に・何を数えたかを添える）:
- 「間に合わない組」= 同じコースで前の訪問から次の訪問へ移動が間に合わない組の数
- 「上限超え」= 正規のコースで 1 日 7 名以上になる所
- 「コースの空いた枠」= コースが決まっていない固定訪問の枠（週を作るとコース A に寄ってしまう元）
- 「人のいないコース」= その曜日に担当できる人がいないコースに入っている枠
- 「件数の差」= 正規のコースの 1 日の件数の多い・少ないの差、「マネージャーの件数」= あふれの受け皿に入った件数
- 「移動」= 直線の距離から見積もった移動の合計（分）。マスターの移動は「間に合わない組」や「コースの空いた枠」を含んだ数なので、同じ土俵ではないことを言い添えます
- 「変える枠」= マスターとコースか時刻が違う枠。そのうち「赤ピンの枠のコース替え」（曜日と時刻は同じ）と「コースの空いた枠を埋めるだけ」を分けて言います

答えの型（例）:
```
稲毛の型を仮の 1 週間に写して、週まるごと組み直してみました（10/12 17 時に読んだマスター・本物の予定は変えていません）。
・間に合わない組 21→4、上限超え 1→0、コースの空いた枠 23→0 になります。件数の差は月曜 4→0・木曜 5→0。
・まだ枠の無い方 6 名分の新しい枠を、希望の曜日・時間帯の中に置けました（3 名は希望の回数・曜日が無いので、曜日を教えていただければ置けます）。
・変える枠は 63（ほとんどが赤ピンの枠のコース替えで、曜日と時刻はそのままです）。
A3 の時間割を案のペインに出しました。お手すきのときにご覧ください。
```

### 1-5. 固定訪問に登録（今は案を作るところまで）
```
rk template commit ina-v1                    # マスターが写した後に変わっていないかを読み直して確かめ、pfv-update の案を作る
rk plan report <plan.json>                   # A4（結論・気になる点・変わる枠と理由）
```
- 写した後にマスターが変わった方がいると、案は止まります → `rk template new <名前> --force` で写し直して解き直す。
- 赤ピンの整理が済み PO が了承したら: `rk template commit ina-v1 --red-cleanup-done` → 了承（3 択）→ `rk backup` → `rk apply` → `rk verify`。
- 型だけ変わります（`pattern_only`）。予定は次に「週を作る」ときから。今の週へ映すことはしません。
- 赤ピンが要る枠は、登録の後に患者マスタで（人が・PO の判断で）付けます。

## 2. 気をつけること
- **本物の週・マスターには、登録の手順（了承 → バックアップ → 反映）以外で触りません**。下書きは何度作り直してもかまいません。
- 登録の操作は**患者の枠の全件の置き換え**です。計算しなかった曜日の枠も items に入っています（消えないように）。
- NG・女性限定は、コースに当てたその人で絶対に守ります。担当は週ごとに替わるので、週のならしでも改めて守られます。
- 拠点をまたぐ枠（都賀の方が稲毛のコースにいる等）は、コースの拠点の側で数えます。
- 利用者名の入った出力は `docs/reports/agent/` の下だけ。チャットには要点だけ。
- 1 曜日だけの古い試作 `rk courseplan` も残っていますが、型の相談はこの作業場（`rk template`）を使います。

## 案の出し方（必須・AGENTS.md §5-2）

案を作るときは `headline`（結論 3 行まで）・`ops[i].reason`（1 件ごとの理由）・`issues[]`（気になる点・足りない所と選択肢）・`conditions[]`（今回だけの条件）を必ず埋める（`rk template commit` が書く。`rk plan check` が足りないと注意する）。
`rk plan report` で出した帳票（案のペイン）を指し、チャットでは **結論・気になる点・確かめの問い（①この案で反映する ②ここを直してほしい ③やめる）** だけを話す。

> **最後に必ず**（案を出したら、この順で。長くしない）
> ① 結論と気になる点を短く　② 「案は画面の右の欄（シート）にあります。見てください」と一言
> ③ 「どれにしますか？」と聞き、次の 3 つを**この番号のまま、1 行ずつ分けて**示す（聞かずに終わらない・1 行に並べない）:
> 　①この案で反映する
> 　②ここを直してほしい
> 　③やめる
> 進み具合の一言も**日本語で**（英語を書かない）
> ④ 相談の終わり・直されたとき・試行錯誤のあとは、引き継ぎ帳に 1 件書く（AGENTS.md §2-5・固定の 5 行・お客様には言わない）
「ここを直して」が出たら下書きを写して（`whatif --as`・`move`）作り直し、`rk template compare <新> <前>` で「前の案との違い」を示し、了承が出るまで繰り返す。了承 → `rk backup` → `rk apply` → `rk verify` → 短い「反映しました」の報告。

## 作業場モード（アプリの型の作業場で、人と同じ下書きを一緒に触る）

画面の文脈が `template_ws` のとき（AGENTS.md §11）。この節が上の「ローカルの下書き（JSON）」の手順より優先。

```
rk template draft-list                                   # 画面の下書き（バックエンド・拠点／全拠点つき）
rk template draft-new <名前> --office <略称|all>         # 下書きを作る（all = 全拠点。稲毛と都賀を一緒に）
rk template explain <名前> [--seq N]                     # 最適化で何をどう変えたか（画面の［くわしく］と同じ中身）
rk template draft-show <名前> [--slots]                  # 数の物差し・最新の編集（誰が・理由）・枠
rk template draft-move <名前> --slot <key> --course <id> --start HH:MM --reason "…"
rk template draft-optimise <名前> [--weekday tue] --reason "火曜を軽くします"
rk template draft-whatif <名前> --staff-count sat=3 --reason "土曜を 1 人減らしたら"
rk template draft-undo <名前> / draft-redo <名前>
```
- 相手は下書き。**承認番号は要らない**（1 手ごとに理由つきで履歴に残り、人が画面の ↶ で戻せる）。actor は自動で「らく助エージェント」。
- 「火曜の A コースを軽くして」= `draft-show --slots` で火曜の A の枠を見て、移動の近い他コースへ `draft-move`（希望の範囲の中・赤ピンの時刻は動かせない）か、`draft-optimise --weekday tue`。理由は平易に。
- 「青木様をなるべく今のコースを崩さず入れて」= 枠の無い方は `draft-whatif` で足してから、`draft-optimise`（変える枠を少なくしたいと添える）。置けなければ理由をそのまま伝える。
- 「土曜を 1 人減らしたら？」= `draft-whatif --staff-count sat=<今-1>` → `draft-optimise --weekday sat` → 数の物差しの前後を 2〜3 行で。
- 出口（①型に登録 ②この週のコースに入れる）だけが承認番号＋`rk plan check`。基本は人が画面の［型に登録］［この週のコースに入れる］を押す。エージェントが案を出すときは 3 択（この案で反映する／ここを直してほしい／やめる）で念押し。
- A4 の案の欄は使わず、盤面に直接出す。人が動かした枠は、影響をひと言伝えて提案する。
- **全拠点の下書き**（画面の拠点で「全拠点」・`draft-new --office all`）: 拠点ごとのコースが同じ盤面に並ぶ。最適化は拠点ごとに解く（別の拠点のコースへは動かせない）。曜日ごとの職員の数のもしも（`--staff-count`）は拠点ごとの下書きで試す。①②の出口は全拠点を 1 回でまとめて入れる。
- **最適化の後は、何をどう変えたかを必ず報告する**（`draft-optimise` の結果の「何をどう変えたか」か `rk template explain`）。チャットは 3〜5 行:
  1. 変わった枠を種類ごとに（コースが無かった枠にコースを付けた・コースだけ変えた・コースと時刻を変えた・時刻だけ変えた・新しく置いた・外した）。
  2. 守る決まりの数の前後（間に合わない組・上限超え・コースの無い枠）と、一般職員の件数のならび（例 5・7・3 → 6・6・6）。
  3. **移動の合計が増えたら、その理由を必ず言う**: コースの無い枠・人のいないコースの枠・新しく置いた方は、いまの型では道順に入っておらず移動に数えられていなかったので、道順に入れた分だけ増える。「道順に新しく入った訪問による分 ＋◯分・並べ替えによる分 ◯分」と分けて言う。多く増えた曜日はその理由も（例「火曜はコースの無い枠が 5 件あった」）。
  4. 気になる点（管理者の訪問が増えた・まだ残る間に合わない組 など）。
  くわしい一覧は画面の［くわしく］にあると添える。言葉は「合わせる・調整」（「直す・修正」は使わない）。
