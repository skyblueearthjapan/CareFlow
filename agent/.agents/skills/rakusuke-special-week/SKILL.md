# rakusuke-special-week — 特別訪問週間

書き込むスキル。AGENTS.md §4-1 の手順（案 → 見せる → 了承 → `rk backup` → `rk apply` → `rk verify`）を必ず通す。

## 0. 仕組み（利用者・管理者への説明にも使う）

- 特別訪問週間 = **期間中だけ回数を上乗せ**する。毎週の型（固定訪問の枠）は変えない。
- ○（追加枠）は「この日に 1 回足す」という日ごとのチケット。保留プールの⭐になる。**○を立てただけでは予定は増えない** → コースへ置いて初めて予定になる。
- 有効な期間はおひとり 1 本だけ。非稼働（入院・休止など）の方には登録できない。日曜には○を立てない。
- 2 名体制の方は同じ日に 2 回分の配置が要る。
- 利用者の拠点と置くコースの拠点が同じであること（違えば同じ拠点の M に置いてから移す）。
- 手で置いた訪問と○は自動では結び付かない → ○は必ずこのスキルの「置く」操作で置く。

## 1. 聞くこと（1 問ずつ）

1. 利用者（`rk sql patient_lookup -p name=…`。複数なら選択肢）。
2. 期間（開始日〜終了日。曜日つきで復唱）と **週の目標回数**（「週 5 回以上」など。1〜7）。
3. ○を立てる日:「毎日（月〜土）／指定の曜日／日付を指定」。今ある固定の訪問の日に重ねるかどうかも確かめる（重ねると同じ日に 2 回）。
4. 配置:「時刻と担当まで案を作る（おすすめ）／○だけ立てて、配置は画面でする」。
5. 案を見せた後:「この案で反映する／条件を変える／やめる」。

## 2. 読むもの

```
rk get /special-visit-periods -q patient_id=<UUID>                      # 既に有効な期間があるか
rk get /special-visit-periods/<期間ID>/calendar                         # 週ごとの合計と目標・○・固定の訪問
rk get /special-visit-marks/pool -q iso_year=2026 -q iso_week=43        # まだ置いていない⭐
rk get /patients/<UUID>                                                 # 拠点・2 名体制・女性限定・希望の時間帯
```

## 3. 手順

### 3-1. 期間の登録と○（1 つ目の案）
```json
{ "kind": "special-week", "title": "伊東様 特別訪問週間 10/19〜11/1（週 5 回）", "target": {"iso_year": 2026, "iso_week": 43},
  "summary": ["期間 10/19（月）〜11/1（日）・週 5 回以上", "○ 6 日分（10/20・21・22・27・28・29）"],
  "ops": [ { "op": "special-period-create", "patient_id": "<UUID>", "start_date": "2026-10-19", "end_date": "2026-11-01",
             "weekly_target": 5, "marks": ["2026-10-20", "2026-10-21", "2026-10-22", "2026-10-27", "2026-10-28", "2026-10-29"],
             "label": "伊東様 特別訪問週間の登録と○ 6 日" } ],
  "checks": ["有効な期間は 1 本", "日曜なし"], "warnings": [] }
```
- 既にある期間に○を足すだけなら `"action": "add-marks"`（`period_id` か `patient_id`）。

### 3-2. ○の配置案（2 つ目の案）
1. 週のならしに⭐を入れて、時刻と担当まで決めた案を作る（本番は読むだけ）:
   ```
   rk level week --week 2026-10-19 --add-special          # 1 日だけなら --day 2026-10-20
   ```
   道具は「その日に訪問が無い日」にだけ足す。入らない⭐はその理由が出る。
2. `rk plan check` → `rk plan report <案> --a3`。要点: どの日・何時・誰が・コースの移動・入らない⭐とその理由。
3. 了承 → `rk backup --label special-<日付>` → `rk apply` → `rk verify`。
4. 置いた後に週の合計が目標に届いたかを `…/calendar` の `target_met` で確かめて報告。

1 件だけ手で決めて置く場合の op:
```json
{ "op": "special-visit-place", "mark_id": "<○のID>", "date": "2026-10-20", "course_template_id": "<コース>",
  "start_time": "14:00", "label": "10/20（火）伊東様 14:00 稲毛 A（特別訪問週間）" }
```

## 4. plan.json の op と受け取る値

| op | 何をする | 主な値 | 元に戻せるか |
|---|---|---|---|
| `special-period-create` | 期間の登録＋○ | `patient_id`・`start_date`・`end_date`・`weekly_target`・`note`・`marks`（日付）・`action`（create/add-marks/cancel/remove-marks）・`period_id` | 登録 → 期間の取消で戻せる／○の追加 → 置く前なら取り下げで戻せる |
| `special-visit-place` | ⭐をコースへ置く | `mark_id`（または `patient_id`＋`date`）・`date`（または `iso_year`・`iso_week`）・`course_template_id`（または `course_id`）・`start_time`・`move_to_weekday` | 戻せる（置いた訪問を消すと⭐に戻る）。○の曜日を動かした配置は不可 |
| `move-visit-week` | 置いた後に同じ拠点の別コースへ移す | rakusuke-visit-change を参照 | 戻せる |
| `patch-course-staff` | その日のコースの担当 | rakusuke-visit-change を参照 | 戻せる |

## 5. 終わらせる・取り消す

- 期間を早めに終える・延ばす・目標を変える: 期間の変更は今の op に無い → 画面の「特別訪問週間」で行うか、PO に相談（勝手に別の経路を使わない）。
- 登録した期間をなかったことにする: `{"op":"special-period-create","action":"cancel","patient_id":…,"start_date":…}`（○はプールから消える。置いた訪問は残るので、先にそれを戻す）。
- 置いた○を戻す: `rk undo <run-id>`、または `return-to-pool`（その日・その時刻の訪問を消すと⭐に戻る）。

## 6. 報告の型

```
伊東様の特別訪問週間（10/19〜11/1・週 5 回以上）を登録し、○ 6 日分を置きました（照合も一致）。
・週 43: 5 回（目標達成）／週 44: 5 回（目標達成）
・時刻: 10/20（火）14:00 鈴木さん ほか（A3 の時間割: docs/reports/agent/…）
・元に戻す: ご希望があれば確かめてから戻します・カイポケへ送る分 6 件（差分を見てから日中に）
```

## 案の出し方（必須・AGENTS.md §5-2）

案を作るときは `headline`（結論 3 行まで）・`ops[i].reason`（1 件ごとの理由）・`issues[]`（気になる点・足りない所と選択肢）・`conditions[]`（今回だけの条件）を必ず埋める（`rk plan check` が足りないと注意する）。
`rk plan report` で出した帳票（案のペイン）を指し、チャットでは **結論・気になる点・確かめの問い（①この案で反映する ②ここを直してほしい ③やめる）** だけを話す。

> **最後に必ず**（案を出したら、この順で。長くしない）
> ① 結論と気になる点を短く　② 「案は画面の右の欄（シート）にあります。見てください」と一言
> ③ 「どれにしますか？」と聞き、次の 3 つを**この番号のまま、1 行ずつ分けて**示す（聞かずに終わらない・1 行に並べない）:
> 　①この案で反映する
> 　②ここを直してほしい
> 　③やめる
> 進み具合の一言も**日本語で**（英語を書かない）
「ここを直して」が出たら案を作り直し（`compare_to`・`diff` に「案 1 との違い」）、了承が出るまで繰り返す。了承 → `rk backup` → `rk apply` → `rk verify` → 短い「反映しました」の報告。
