# rakusuke-absence — 急な休み・欠員

書き込むスキル。AGENTS.md §4-1 の手順（案 → 見せる → 了承 → `rk backup` → `rk apply` → `rk verify`）を必ず通す。

## 0. 最初に知っておくこと（落とし穴）

- **休みを登録しても訪問は動かない**。登録だけだと、その方の訪問は元の担当のまま残る（プールにも行かない）。振り分けは別の操作。
- **新人**（同行だけの職員）は担当にできない（らく助が断る）。新人が休むなら、その日の**同行を外す**だけでよい（`accompaniment-set`）。先輩が休むと、付いていた新人の同行先も無くなる → 同行の付け替えも案に入れる。
- **打刻済み・完了の訪問**は動かさない（据え置き）。当日の午後に休む場合は、残りの訪問だけが対象。
- **過去の日**は休みにできない（当日は可）。
- **カイポケへの送信は別**（`rakusuke-kaipoke`）。当日の変更は送れない（明日以降だけ）。当日分はお客様がカイポケで直接直していることが多い → 送る前に必ず差分を見る。

## 1. 聞くこと（1 問ずつ・選択肢で）

1. **誰が・いつ**:「どなたが、何日（曜日）にお休みですか」— 名前は `rk sql staff_lookup -p name=…` で確かめる（複数なら選択肢）。
2. **休みの種類**: 「終日休み／午前休／午後休／時間の変更（何時〜何時）」。
3. **振り分け方**（下の §2 の判断材料を添えて）:
   - 「何人かに分けて振り分ける（時刻の調整も含めて組み直す）」← おすすめ（件数が多い・移動が長い日）
   - 「1 人に全部任せる（時刻はそのまま）」← 代わりの方が 1 人で全部入れるとき
   - 「休みの登録だけ（振り分けは自分で画面でする）」
4. 案を見せた後:「この案で反映する／条件を変えて作り直す／やめる」。

## 2. どちらにするかの決め方

まず読む（書かない）:
```
rk get /staff/overrides-week -q iso_year=2026 -q iso_week=43          # その週の休み
rk get /visits -q staff_id=<休む方の UUID> -q week_start=2026-10-22 -q week_end=2026-10-22   # その日の訪問
echo '{"staff_id":"<UUID>","date":"2026-10-22"}' | rk post-read /schedule/v2/substitute-candidates --json -   # 代わりの候補（◎△×）
```
- 代わりの候補の応答の `whole_ok_staff_ids`（1 人で全部引き受けられる人）がいて、時刻を動かさずに済む → **1 人に任せる**も選べる。
- 件数が多い・1 人では入りきらない・移動が長くなる → **何人かに分けて組み直す**（ならし）。
- どちらでも入らない訪問が出たら、勝手に取り消さない。理由を見せて、どうするかを管理者に選んでもらう（下の 3-A の 2）。

## 3-A. 何人かに分けて組み直す（ならし）

1. その日を組み直す案を作る（本番は読むだけ・1 本ずつ）:
   ```
   rk level day --date 2026-10-22 --off S004            # 休む方の職員コード。半休や新人は --off を足す
   ```
   出力の案（`agent/runs/plans/…leveling….json`）の ops に**休みの登録が無い**ので、先頭に足す（§4 の `staff-day-off`）。
2. 入らない訪問を決める（`rk plan resolve`）:
   入らない訪問がある案は `ready:false`（`blockers` に「入らない訪問が N 件…」）。案の `unplaced` に 1 件ずつ・理由（`reason`）・相談先（`hint`）がある。`rk plan check <案>` は「まだ決めていない入らない訪問」を並べる。
   1. 管理者に、入らない訪問を**平易な日本語で理由とともに**見せる（例「10/22（木）〇〇様 10:00 は、その時刻に空いている人がいません」）。
   2. **選択肢で**聞く（1 件ずつ。同じでよければ「全部まとめて」も選べる）:
      - 保留プールへ戻す（今週は行かない・API では戻せない → 画面からは元に戻せません）
      - 上限を少し超えて〇〇さんに付ける（承知の上で超過・職員は管理者に選んでもらう）
      - 時刻をずらす（何時にするか・誰が行くか。ご本人への連絡が要る）
      - いまの担当のまま残す（休みの職員に訪問が残る・当日までに担当を決める）
      応援を頼むなら、応援の方の職員コードで「上限を超えて付ける」か「時刻をずらす」を選ぶ。
   3. 決めたら書き込む（決めた人を必ず `--approved` に）:
      ```
      rk plan resolve <案> --visit <訪問 ID の頭か名前の一部> --choice pool --approved "<誰が・いつ>"
      rk plan resolve <案> --visit <…> --choice allow-over --staff <職員コード> --approved "<…>"
      rk plan resolve <案> --visit <…> --choice shift --start 13:30 [--staff <職員コード>] --approved "<…>"
      rk plan resolve <案> --visit <…> --choice keep --approved "<…>"
      rk plan resolve <案> --all pool --approved "<…>"        # まだ決めていない全部を同じに（shift は 1 件ずつ）
      ```
      全部決まり、ほかの `blockers` が無ければ `ready:true` になる。決め直しは同じ訪問へもう一度。
   4. その後はいつもどおり: `rk plan check` → `rk plan report`（A4 に「入らなかった訪問と決めたこと」が載る）→ 了承 → `rk backup` → `rk apply` → `rk verify`。
3. `rk plan check <案>` → `rk plan report <案> --a3`（A3 横の時間割）と A4 一覧を見せる。要点: 何件を誰へ・時刻が変わる方・入らない訪問とその理由・移動の増減・カイポケへ送る件数・**元に戻せるか**（プールへ戻した訪問は API では戻せない → 画面からは元に戻せません）。
4. 了承 → `rk backup --label absence-<日付>` → `rk apply <案> --approved "<誰が・いつ了承>"` → `rk verify <案>`。
5. 同行（新人）が付いていたら、付け替え先を選択肢で聞いて `accompaniment-set` の案で反映。

### 変わった注文（`rk level` の指定 → 自作）
`rk level day|week` には `--days thu,fri`・`--prefer-staff`・`--avoid-staff`・`--keep-current`・`--cancel`・`--fast`・`--only-staff … --window …`・`--not-same-day`・`--pair-staff`・`--forbid-pair` が足せる。表と約束（まず指定で・言えなければ scratch の小さなスクリプトで `tools.leveling.api`・共有の道具は書き換えない）は `rakusuke-week-optimize` の §1-4a と `agent/tools/leveling/CUSTOM.md`。急な休みで「A さんに多めに・B さんは最後の手段」のように言われたら `--prefer-staff` / `--avoid-staff` を足して作り直す。

## 3-B. 1 人に全部任せる（急休代替）

案（plan.json）の ops は 1 件:
```json
{ "op": "staff-off-week", "staff_id": "<休む方>", "date": "2026-10-22", "to_staff_id": "<引き受ける方>",
  "label": "10/22（木）田中さん休み → 鈴木さんへ" }
```
- これ 1 回で: 休みの登録・その日の訪問（本人の枠だけ。2 名体制の相方は残る）とコースの担当を引き受け先へ・その日の固定イベント（朝会など）に不参加の印。
- `to_staff_id: null` にすると全部「担当なし」になる（後で人が画面で付ける）。
- NG 職員・女性限定に触れると断られる。**了承して通す（acknowledge）は使わない**。候補から外して選び直す。
- **元に戻せない（rk undo 不可）** → 了承のときに「この操作は、画面からは元に戻せません」と必ず伝える。直後なら、エージェントのアカウントで画面を開いて「戻る」1 回で全部戻るが、その週で他の操作をした後は使えない。

## 4. 使う操作（plan.json の op と受け取る値）

| op | 何をする | 主な値 | 元に戻せるか |
|---|---|---|---|
| `staff-day-off` | 休み・半休・時間変更を登録（訪問は動かさない） | `staff_id`・`date`・`type`（休み/午前休/午後休/時間変更）・`start_time`/`end_time`・`note`・`action`（set/remove） | 戻せる（取り消すと本人にお知らせが届く） |
| `staff-off-week` | 休み＋その日の担当を 1 人へ | `staff_id`・`date`・`to_staff_id`（null=担当なし） | **戻せない**（画面からは元に戻せません） |
| `assign-staff-week` | 1 件だけ担当を替える | `visit_id`・`staff_id`（null=担当なし） | 戻せる |
| `patch-course-staff` | その日のコースの担当を替える | `course_id`（または `iso_year`・`iso_week`・`weekday`・`course`=「稲A」など）・`staff_id` | 戻せる |
| `move-visit-week` | 今週だけ時刻・日・コースを動かす | `iso_year`・`iso_week`・`patient_id`・`old_weekday`・`old_start_time`・`new_weekday`・`new_start_time`・`new_course_template_id` | 戻せる |
| `return-to-pool` | 入らない訪問をプールへ | `visit_id` | **戻せない**（画面からは元に戻せません） |
| `accompaniment-set` | 同行の付け替え（その週・全置換） | `staff_id`（同行する人）・`iso_year`・`iso_week`・`course_ids`・`visit_ids` | 戻せる |

休みの登録の例:
```json
{ "op": "staff-day-off", "staff_id": "S004", "date": "2026-10-22", "type": "休み", "note": "体調不良",
  "label": "10/22（木）田中さん 休み" }
```

## 5. 元に戻す・休みの取消

- 反映した案を戻す: `rk undo <run-id>`（了承が要る）。戻せない操作が入っていた場合は「この操作は、画面からは元に戻せません」とだけ伝え、戻しの手立ては PO に相談する（管理者には内側の話をしない）。
- 休みそのものの取消だけ:`{"op":"staff-day-off","staff_id":…,"date":…,"action":"remove"}`（本人に取消のお知らせが届くことを先に伝える）。訪問は自動では戻らない。

## 6. 報告の型

```
10/22（木）田中さんのお休みを登録し、訪問 6 件を 鈴木さん 3 件・高橋さん 3 件へ振り分けました（照合も一致）。
・時刻が変わる方: 伊東様 9:30→10:00（ご連絡をお願いします）
・入らない訪問: なし
・元に戻す: この操作は画面からは元に戻せません
・カイポケ: 明日以降の 6 件が未送信です（送るときは差分を見てから日中に）
```

## 案の出し方（必須・AGENTS.md §5-2）

案を作るときは `headline`（結論 3 行まで）・`ops[i].reason`（1 件ごとの理由）・`issues[]`（気になる点・足りない所と選択肢）・`conditions[]`（今回だけの条件）を必ず埋める（`rk plan check` が足りないと注意する）。
`rk plan report` で出した帳票（案のペイン）を指し、チャットでは **結論・気になる点・確かめの問い（①この案で反映する ②ここを直してほしい ③やめる）** だけを話す。

> **最後に必ず**（案を出したら、この順で。長くしない）
> ① 結論と気になる点を短く　② 「案は画面の右の欄（シート）にあります。見てください」と一言
> ③ 「どれにしますか？」と聞き、次の 3 つを**この番号のまま、1 行ずつ分けて**示す（聞かずに終わらない・1 行に並べない）:
> 　①この案で反映する
> 　②ここを直してほしい
> 　③やめる
> 進み具合の一言も**日本語で**（英語を書かない）
「ここを直して」が出たら案を作り直し（`compare_to`・`diff` に「案 1 との違い」）、了承が出るまで繰り返す。了承 → `rk backup` → `rk apply` → `rk verify` → 短い「反映しました」の報告。
